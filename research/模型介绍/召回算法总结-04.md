# KGAT、KGCN、TransE + GNN：知识图谱推荐三种子路线

这三个模型都想解决同一个问题：**用户交互太稀疏时，如何利用演员、导演、类型、IP、世界观、剧情元素等知识图谱关系来提升推荐**。但它们的建模方式不同。

---

## 1. KGAT：Knowledge Graph Attention Network for Recommendation

### 1.1 核心思想

KGAT 的关键词是 **attention**。

它把两类数据放进同一张图里：

- **用户-物品交互图**：User A 看过 Movie X；
- **知识图谱**：Movie X → 演员 → Actor Y；Movie X → 类型 → Genre Z；Movie X → 属于 IP → Franchise W。

KGAT 会在图上传播信息，让用户表示不仅来自他看过的电影，还来自电影连接的演员、导演、类型、IP 等实体。

### 1.2 大致结构

可以理解为：

```text
用户历史电影
    ↓
连接到知识图谱实体
    ↓
多跳传播
    ↓
注意力加权
    ↓
更新用户 / 电影表示
    ↓
预测用户对电影的偏好
```

例如：

```text
用户看过《盗梦空间》
        ↓
《盗梦空间》—导演→ 诺兰
《盗梦空间》—类型→ 科幻
《盗梦空间》—演员→ 莱昂纳多
        ↓
诺兰 →《奥本海默》
诺兰 →《信条》
科幻 →《星际穿越》
```

KGAT 会判断这些关系对当前用户的重要性，再决定推荐结果更偏向“诺兰导演”还是“科幻题材”。

### 1.3 优点

- **能建模高阶关系**：不只看用户看过什么，还能通过多跳关系发现潜在偏好；
- **注意力机制可解释性较好**：可以知道推荐结果更依赖演员、导演还是题材；
- **适合长视频**：影视内容天然有丰富的元数据和关系图。

### 1.4 局限

- 图规模大时训练和推理成本高；
- 知识图谱质量很关键，如果元数据错误或缺失，会带来噪声；
- 多跳传播可能引入不相关关系，例如两个电影共享一个次要配角，但不代表风格相似。

## 2. KGCN：Knowledge Graph Convolutional Networks for Recommendation

### 2.1 核心思想

KGCN 的关键词是 **convolutional**，即用图卷积在知识图谱邻居上聚合信息。

它的做法可以简单理解为：

> 对每个电影，先看它连接了哪些实体，再把这些邻居实体的表示聚合起来，形成这个电影的丰富表示。

例如电影《沙丘》连接：

```text
《沙丘》
 ├── 类型：科幻
 ├── 导演：丹尼斯·维伦纽瓦
 ├── 原著：弗兰克·赫伯特
 ├── 演员：蒂莫西·查拉梅
 └── IP：Dune
```

KGCN 会把这些邻居信息聚合到电影 embedding 中，让模型知道它不仅是“一个 ID”，而是一个具有语义和关系结构的影视内容。

### 2.3 大致结构

```text
电影节点
   ↓
找知识图谱邻居
   ↓
根据关系类型和用户偏好加权
   ↓
图卷积聚合邻居表示
   ↓
得到增强后的电影 embedding
   ↓
与用户 embedding 计算匹配分数
```

### 2.4 与 KGAT 的区别

| 维度 | KGAT | KGCN |
|---|---|---|
| 核心机制 | 图注意力传播 | 图卷积聚合 |
| 关注点 | 哪些关系对用户更重要 | 如何从邻居实体中提取物品表示 |
| 图结构 | 用户-物品图 + 知识图谱 | 主要围绕物品在知识图谱中的邻域 |
| 直觉 | “这个用户为什么会对这条关系敏感？” | “这个电影由哪些知识结构定义？” |
| 适用场景 | 偏好路径推理、可解释推荐 | 内容表示增强、元数据丰富的推荐 |

简化地说：

> **KGCN 更像是在“增强电影表示”，KGAT 更像是在“推理用户偏好路径”。**

### 2.5 优点

- 能显著增强冷启动物品表示；
- 对元数据丰富的电影、剧集、纪录片很适用；
- 图卷积结构直观，容易和深度推荐模型结合。

### 2.6 局限

- 邻居聚合可能过度平滑，多个电影最终表示变得相似；
- 不同关系的重要性需要额外建模；
- 对超大知识图谱的在线服务成本较高。

## 3. TransE + GNN：知识图谱嵌入 + 图神经网络组合

### 3.1 TransE 是什么？

TransE 是一种经典的知识图谱 embedding 方法。

它把知识图谱三元组表示为：

```text
头实体 + 关系 ≈ 尾实体
```

例如：

```text
《盗梦空间》 + 导演 → 诺兰
```

在向量空间中希望满足：

```text
embedding(盗梦空间) + embedding(导演)
≈ embedding(诺兰)
```

再比如：

```text
《沙丘》 + 类型 → 科幻
```

则希望：

```text
embedding(沙丘) + embedding(类型)
≈ embedding(科幻)
```

### 3.2 核心思想

TransE + GNN 是一种组合思路：

1. **TransE 先学习实体和关系的 embedding**；
2. **GNN 再在图结构上传播和聚合这些 embedding**；
3. 最后将增强后的电影表示用于推荐。

可以理解为：

```text
演员、导演、类型、IP、世界观
        ↓
TransE 学出实体/关系向量
        ↓
GNN 在图上传播信息
        ↓
得到更丰富的电影表示
        ↓
与用户偏好匹配
```

### 3.3 为什么需要 GNN？

TransE 能把实体映射到连续向量空间，但它本身对复杂图结构的表达能力有限。GNN 可以补充这一点：

- TransE 负责：把实体和关系变成可计算的向量；
- GNN 负责：利用图上的邻居关系传播信息。

例如：

```text
用户看过《蝙蝠侠：黑暗骑士》
        ↓
《黑暗骑士》—导演→ 诺兰
诺兰 ←导演— 《奥本海默》
        ↓
推荐《奥本海默》
```

TransE 可以表达“导演”这个关系的方向和语义；GNN 可以在多部电影、多个人物、多个 IP 之间传播这种关系。

### 3.4 优点

- 适合构建通用影视知识图谱；
- 能把电影、演员、导演、类型、IP 放在同一个向量空间；
- 对冷启动和跨内容泛化有帮助；
- 可以作为下游推荐模型的特征增强模块。

### 3.5 局限

- TransE 对复杂关系建模能力有限，例如一对多、多对多关系；
- 单独使用 TransE 通常不足以做高质量推荐；
- 需要与 GNN 或其他深度模型结合；
- 图谱构建和实体对齐成本高。

## 4. 三个模型的直观对比

| 模型 | 核心机制 | 更关注什么 | 推荐直觉 | 长视频适用性 |
|---|---|---|---|---|
| **KGAT** | 图注意力传播 | 用户在知识图谱中的偏好路径 | “这个用户偏好某导演/题材/IP” | 很适合解释推荐理由 |
| **KGCN** | 图卷积邻居聚合 | 物品本身的知识结构 | “这部电影由哪些元数据定义” | 很适合新片冷启动 |
| **TransE + GNN** | 知识图谱 embedding + 图传播 | 实体和关系的语义表示 | “这些电影在语义空间中相关” | 适合构建通用影视知识底座 |

## 5. 在长视频推荐中的实际用法

### 场景一：新片冷启动

一部新电影刚上线，没有用户交互，但已经有：

- 演员；
- 导演；
- 类型；
- IP；
- 剧情关键词；
- 视觉风格；
- 原著信息。

这时可以用：

```text
KGCN / TransE + GNN
```

它们能在没有行为数据时增强新片表示。

### 场景二：解释推荐

用户问：“为什么给我推荐《奥本海默》？”

系统可以利用 KGAT 的注意力路径：

```text
因为你看过《盗梦空间》
        ↓
共同导演：克里斯托弗·诺兰
        ↓
推荐《奥本海默》
```

这种推荐解释比“模型预测分数高”更友好。

### 场景三：IP 或世界观推荐

用户喜欢：

- Dune；
- 星球大战；
- 漫威；
- 指环王；
- 哥斯拉。

知识图谱可以把这些内容连接为：

```text
电影 —属于→ IP
电影 —衍生自→ 原著
电影 —世界观属于→ Shared Universe
电影 —角色关联→ 角色
```

这时 KGAT 和 TransE + GNN 都能帮助系统理解“同一宇宙”“同一作者”“同一风格流派”。

### 场景四：长尾影片召回

一些小众电影交互很少，但元数据丰富：

- 独立导演；
- 电影节获奖；
- 相似题材；
- 相似摄影风格；
- 相同编剧。

知识图谱召可以帮助这些影片获得额外曝光机会。

---

## 6. 一句话总结

> **KGCN 用图卷积增强电影表示，KGAT 用注意力建模用户偏好路径，TransE + GNN 先学习知识图谱语义，再用图神经网络传播关系信息。三者共同解决的问题，是让推荐系统不仅知道“谁看过什么”，还知道“这个内容是什么、为什么相似、用户偏好从何而来”。**
