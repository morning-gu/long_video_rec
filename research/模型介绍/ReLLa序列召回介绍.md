存在。**ReLLa** 是一个把 **检索增强** 和 **LLM 序列推荐** 结合起来的算法/框架，全称是：

> **ReLLa: Retrieval-enhanced Large Language Models for Lifelong Sequential Behavior Comprehension in Recommendation**

它由 Jianghao Lin 等人在 WWW 2024 提出，是面向 **零样本 / 少样本序列推荐任务** 的 LLM 推荐框架。

论文信息：

> Jianghao Lin, Rong Shan, Chenxu Zhu, Kounianhua Du, Bo Chen, Shigang Quan, Ruiming Tang, Yong Yu, Weinan Zhang, “ReLLa: Retrieval-enhanced Large Language Models for Lifelong Sequential Behavior Comprehension in Recommendation,” WWW, 2024.

---

## 1. ReLLa 解决什么问题？

ReLLa 针对的是一个关键问题：

> **LLM 对长用户行为序列的理解能力不足。**

论文中把它称为：

> **lifelong sequential behavior incomprehension problem**

意思是：即使把用户历史行为写成文本，并且长度远没有达到 LLM 的上下文窗口限制，LLM 也未必能有效利用这些历史行为来推断用户对候选内容的偏好。

在传统序列推荐模型如 SIM 中，随着用户行为序列变长，模型效果通常会提升；但论文发现，Vicuna-13B 这类 LLM 在行为序列变长后，效果可能先升后降。

这说明：

```text
更多历史 ≠ LLM 更理解用户
```

原因是推荐任务中的历史序列和自然语言文本不同：

- 用户行为之间有复杂依赖；
- 不是所有历史行为都与当前候选相关；
- 行为序列中存在大量噪声；
- LLM 需要判断“哪些历史行为对预测当前 item 有用”，而不是简单阅读全文。

---

## 2. ReLLa 的核心思想

ReLLa 的核心思想是：

> **在把用户历史交给 LLM 之前，先用语义检索挑选与目标 item 最相关的历史行为，而不是简单取最近 K 个行为。**

也就是说，传统方法通常是：

```text
用户历史：
行为1, 行为2, ..., 行为100

↓

取最近 20 个行为

↓
输入 LLM

↓
预测候选 item
```

ReLLa 改为：

```text
用户历史：
行为1, 行为2, ..., 行为100

↓

根据候选 item 的语义
检索最相关的 20 个历史行为

↓
输入 LLM

↓
预测候选 item
```

它把“最近行为截断”变成了“语义相关行为检索”。

---

## 3. 两个关键模块

### 3.1 SUBR：Semantic User Behavior Retrieval

SUBR 是 ReLLa 的核心。

它根据目标 item，从用户长期行为序列中检索语义上最相关的历史行为。

例如，目标候选电影是：

```text
科幻电影 D
```

用户历史中有：

```text
1. 科幻电影 A
2. 爱情电影 B
3. 科幻剧 C
4. 综艺 D
5. 纪录片 E
6. 科幻纪录片 F
```

传统截断可能只取最近几个：

```text
科幻剧 C, 综艺 D, 纪录片 E, 科幻纪录片 F
```

而 SUBR 会优先取出：

```text
科幻电影 A
科幻剧 C
科幻纪录片 F
```

因为它们与目标 item 语义更相关。

这解决了两个问题：

1. **历史行为太长，LLM 难以处理**；
2. **不相关历史行为会稀释关键偏好信号**。

---

### 3.2 ReiT：Retrieval-enhanced Instruction Tuning

ReLLa 不只在推理阶段使用检索，还把检索增强用于少样本微调。

做法是：

```text
原始训练样本
+ SUBR 增强后的训练样本
+ 指令格式
↓
微调 LLM
```

也就是构造混合训练集：

```text
原始样本：直接使用用户最近历史
增强样本：使用语义检索后的历史
```

这样 LLM 可以同时学习：

- 正常截断历史下的推荐能力；
- 检索增强历史下的推荐能力；
- 如何从语义相关行为中推断偏好。

---

## 4. ReLLa 的工作流程

以一个电影推荐任务为例。

假设输入是：

```text
用户历史：
电影A：科幻、太空
电影B：爱情
电影C：悬疑
电影D：科幻、人工智能
电影E：纪录片

候选电影：
电影F：科幻、太空、人工智能
```

### 第一步：构造候选 item 语义表示

把候选电影转为文本描述：

```text
电影F：一部关于人工智能和太空探索的科幻电影
```

### 第二步：对历史行为做语义检索

用 embedding 或语义相似度计算候选电影与历史电影的相似度：

```text
电影A：科幻、太空        相关性 0.91
电影D：科幻、人工智能    相关性 0.93
电影C：悬疑              相关性 0.42
电影B：爱情              相关性 0.18
电影E：纪录片            相关性 0.37
```

选择 Top-K 相关历史：

```text
电影D、电影A
```

### 第三步：构造 prompt

将用户画像、检索后的历史行为、候选电影放入 LLM prompt：

```text
用户历史行为：
1. 看过电影D：科幻、人工智能
2. 看过电影A：科幻、太空

候选电影：
电影F：一部关于人工智能和太空探索的科幻电影

问题：
用户点击/观看电影F 的概率是多少？
```

### 第四步：LLM 打分

ReLLa 使用 LLM 对候选 item 做 pointwise scoring，也就是：

```text
给定用户历史和候选 item
LLM 输出一个偏好分数
```

输出可能是：

```text
0.86
```

对多个候选 item 重复这个过程，即可得到推荐排序。

## 5. ReLLa 与 GRU4Rec / SASRec / BERT4Rec 的区别

| 维度 | GRU4Rec | SASRec | BERT4Rec | ReLLa |
|---|---|---|---|---|
| 模型基础 | GRU / RNN | Self-attention | 双向 Transformer | LLM |
| 输入 | item ID 序列 | item ID 序列 | item ID 序列 | 文本化历史行为 |
| 主要目标 | next-item prediction | next-item prediction | masked item prediction | 零样本 / 少样本 CTR 或推荐打分 |
| 历史选择 | 全部或截断序列 | 全部或截断序列 | 全部或截断序列 | 语义检索相关历史 |
| 语义理解 | 弱 | 弱 | 弱 | 强 |
| 冷启动能力 | 较弱 | 较弱 | 较弱 | 较强 |
| 可解释性 | 一般 | 一般 | 一般 | 较强 |
| 成本 | 低到中 | 中 | 中 | 高 |
| 适合部署阶段 | 召回 / 精排兴趣特征 | 召回 / 精排兴趣特征 | 召回 / 精排兴趣特征 | 少量候选重排或打分 |

核心区别是：

```text
GRU4Rec / SASRec / BERT4Rec：主要学习 item ID 序列中的行为规律。
ReLLa：把长期行为转成语义文本，并用 LLM 理解与目标 item 相关的历史。
```

## 6. ReLLa 的优势

### 6.1 缓解长序列理解问题

ReLLa 不是把长历史硬塞给 LLM，而是先找出与候选 item 语义相关的历史行为，降低 LLM 的理解难度。

### 6.2 提高少样本能力

论文报告，在少样本设置下，ReLLa 使用不到 10% 的训练样本，在部分数据集上超过了使用全量训练数据的传统 CTR 模型，如 DCNv2、DIN、SIM。

这说明 LLM 的先验知识和语义理解能力在推荐任务中确实有价值。

### 6.3 对长视频推荐很有吸引力

电影和剧集有丰富语义：

- 题材；
- 演员；
- 导演；
- 世界观；
- 剧情元素；
- 风格；
- 情绪；
- IP 关联。

ReLLa 可以利用这些语义信息做历史行为检索。

例如用户看过：

```text
《银翼杀手2049》
《沙丘》
《西部世界》
```

候选是：

```text
一部新的赛博朋克科幻剧
```

ReLLa 可以根据语义相关性把这三部历史作品检索出来，并让 LLM 推断用户可能喜欢候选剧集。

这比只靠 item ID embedding 更容易解释。

### 6.4 对冷启动有帮助

传统 ID-based 序列模型对新片不友好，因为新片没有足够交互数据。

ReLLa 可以利用候选电影的文本描述、类型、演员、剧情简介和 LLM 世界知识，即使新片没有交互历史，也能形成一定偏好判断。

---

## 7. ReLLa 的局限

### 7.1 计算成本高

对每个候选 item 都要做：

1. 语义检索；
2. prompt 构造；
3. LLM 打分。

如果候选集很大，成本非常高。

因此 ReLLa 不适合直接做大规模召回，更适合：

```text
小候选集精排 / 重排
```

或离线场景。

---

### 7.2 严格来说不是传统意义的“召回算法”

ReLLa 更准确地说是：

> **LLM-based sequential recommendation / LLM-based ranking framework**

它不是像双塔模型或 ANN 检索那样直接从百万级片库中召回候选。

如果你的系统阶段是：

```text
召回 → 粗排 → 精排 → 重排
```

ReLLa 更适合放在：

```text
精排或重排
```

而不是第一阶段大规模召回。

---

### 7.3 依赖 item 文本质量

ReLLa 的效果依赖 item 语义描述质量。

如果电影元数据不完整、剧情简介噪声大、标签错误，SUBR 和 LLM 推理都会受影响。

---

### 7.4 训练目标与线上业务目标可能不完全一致

论文主要验证的是推荐相关性或 CTR 类任务。

但长视频平台还关心：

- 完播率；
- 观看时长；
- 续看率；
- 弃剧率；
- 用户满意度；
- 长期留存。

这些目标需要额外建模。

---

## 8. 在长视频推荐系统中如何使用 ReLLa

一个实际系统可以这样融合 ReLLa：

```text
第一阶段：多路召回
- 协同过滤
- 双塔模型
- SASRec / BERT4Rec
- 多模态召回
- 知识图谱召回

第二阶段：粗排
- 轻量模型过滤

第三阶段：精排
- MMoE / PLE 多目标模型

第四阶段：重排
- ReLLa 对 Top 50 或 Top 100 候选做语义打分
- 结合完播率、观看时长、多样性、疲劳度
```

也就是说，ReLLa 可以作为一个高级重排模块：

```text
传统模型先筛出候选
ReLLa 再利用 LLM 语义理解能力做精细化判断
```

---

## 9. 一句话总结

> **ReLLa 存在，它是一个把“语义检索用户历史行为”和“LLM 推荐打分”结合起来的序列推荐框架，适合处理长历史、少样本、语义丰富的推荐任务；但由于推理成本高，它更适合精排或重排，而不是大规模召回。**

# ReLLa 的训练与推理输入输出

ReLLa 把推荐问题转化为 **LLM 的 Yes / No 二分类任务**：给定用户历史行为序列和一个候选物品，让 LLM 预测用户是否会与该物品交互。下面分别拆解训练和推理两个阶段。

---

## 1. 任务的基本形式

对每个样本：

```
输入 = (用户行为序列 H = [item₁, item₂, ..., itemₜ], 目标物品 v)
输出 = Yes / No（用户是否会点击/交互 v）
```

关键点：**ReLLa 一次只判断一个候选物品**，不像双塔模型那样一次从百万库中检索 Top-N。这决定了它更接近精排/重排，而非大规模召回。

---

## 2. 训练阶段的输入输出

训练分三步：语义检索 → 指令构造 → 指令微调。

### Step 1：SUBR 语义行为检索

先不直接取“最近 K 个行为”，而是用文本 embedding 模型（论文中用了 OpenAI 的 text-embedding-ada-002）做检索：

- **输入**：
  - 目标物品 v 的文本描述（如标题、类目、品牌、价格）
  - 用户完整终身行为历史中每个物品的文本描述
- **计算**：
  - 对 v 和每个历史物品分别编码
  - 按余弦相似度排序，取最相关的 K 个历史行为
- **输出**：与目标物品语义最相关的 K 条历史行为（替代最近 K 条）

### Step 2：构造指令微调样本

将 (检索到的历史行为, 目标物品) 填入指令模板。以长视频场景为例：

```text
You are a recommendation expert. Based on the user's viewing
history, predict whether the user will watch the target show.

User's viewing history:
1. 《权力的游戏》 — 奇幻/剧情/战争，HBO 剧集，完播
2. 《西部世界》 — 科幻/悬疑，HBO 剧集，看至 S1E5
3. 《王冠》 — 历史/传记，Netflix 剧集，收藏
...（K 条 SUBR 检索出的相关历史）

Target show:
《沙丘：预言》 — 科幻/剧情，HBO 剧集，衍生前传

Answer (Yes or No):
```

- **输入**：指令模板 + K 条历史行为（带文本元数据）+ 目标物品描述
- **标签输出**：`Yes`（训练集中该样本是真实正样本）或 `No`（负采样得到的负样本）

训练数据是**混合构造**的：
- 一部分样本用“最近 K 条行为”（原始样本）
- 一部分样本用“SUBR 检索的 K 条相关行为”（增强样本）

### Step 3：LoRA 指令微调（ReiT）

- **输入**：上述 (prompt, Yes/No) 对，批量喂给 LLM（论文骨干为 LLaMA-7B / Vicuna-7B 等）
- **训练方式**：LoRA 参数高效微调，冻结主干大部分参数
- **损失函数**：对输出 token（Yes 或 No）的交叉熵
- **输出**：微调后的 LoRA 权重

---

## 3. 推理阶段的输入输出

推理时流程与训练一致，但去掉标签：

```
输入:
  1. 用户历史行为库（终身长度）
  2. 一个候选物品 v

过程:
  a) SUBR: 用 v 的 embedding 检索最相关的 K 条历史
  b) 将 (K 条历史, v) 填入指令模板
  c) LLM 前向生成

输出:
  - Yes / No
  - 更常用的是取出 Yes token 的生成概率，作为连续打分 S(v)
```

对候选集合排序时，需要对每个候选重复上述过程：

```text
候选集合 C = {v₁, v₂, ..., vₘ}
for each vᵢ:
    promptᵢ = SUBR(user_history, vᵢ) + 模板(vᵢ)
    sᵢ = P("Yes" | promptᵢ)
输出: 按 sᵢ 降序排列的候选列表
```

---

## 4. 训练 vs 推理输入输出对照表

| 维度 | 训练阶段 | 推理阶段 |
|---|---|---|
| 核心输入 | (用户历史, 候选物品, 真实标签) 三元组 | (用户历史, 候选物品) 二元组 |
| 历史行为来源 | 最近 K 条 + SUBR 检索 K 条（混合） | SUBR 检索 K 条（面向当前候选） |
| 历史表示 | 物品文本元数据（标题/类目/品牌等） | 同左，长视频可换成标题/类型/主演/观看状态 |
| 标签/输出 | `Yes` 或 `No`，用于交叉熵监督 | `Yes` 概率作为分数，或二值判断 |
| 额外输出 | LoRA 微调权重 | 排序后的候选列表（逐个打分） |

---

## 5. 需要注意的两个工程含义

**① 不是真正意义上的召回模型。**
传统召回（双塔、SASRec）是“一个用户向量 → ANN 检索 Top-N”，一次服务整个候选库；ReLLa 是“一个用户 + 一个候选 → 一次前向 → 一个分数”，候选越多推理成本线性增长。所以它更适合：

- 精排/重排阶段处理几十到几百个候选
- 或离线对高价值流量做深度打分

**② 历史检索是“目标感知”的。**
SUBR 会为每个候选物品动态检索不同的历史子集——判断科幻剧时召回你看过的高分科幻历史，判断甜宠剧时召回言情历史。这是它与 SASRec/BERT4Rec（用固定用户表示对所有候选打分）的本质区别，也是它处理终身长序列的关键设计。

一句话总结：**ReLLa 的输入是“为候选物品动态检索出的语义相关历史 + 该候选的文本描述”，输出是对该候选的 Yes/No 判断（训练时带标签做 LoRA 微调，推理时用 Yes 概率作排序分数）。**
