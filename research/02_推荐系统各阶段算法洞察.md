# 长视频推荐各阶段常用算法总结

## 1. 召回阶段：从海量片库中快速筛出候选

目标：**快、覆盖广、多样性高**，通常从百万级内容库筛出几百到几万候选。

| 算法类型 | 代表算法/方法 | 适合解决的问题 | 长视频场景特点 |
|---|---|---|---|
| 协同过滤 | ItemCF、UserCF、矩阵分解、ALS | 根据用户-物品共现关系找相似内容 | 适合经典电影偏好，如“看过 A 的用户也看 B” |
| 隐向量召回 | MF、BPR、FM、Neural CF | 学习用户和影片的低维表示 | 适合评分或隐式观看数据 |
| 双塔召回 | User Tower + Item Tower + ANN | 大规模实时召回 | 工业主流，可离线预计算 item embedding，线上实时计算 user embedding |
| 序列召回 | GRU4Rec、SASRec、BERT4Rec | 捕捉用户兴趣演化 | 适合追剧、连续观看、偏好漂移 |
| 图召回 | NGCF、LightGCN、PinSage 类 GNN | 利用用户-影片交互图的高阶关系 | 适合稀疏数据和长尾内容 |
| 知识图谱召回 | KGAT、KGCN、TransE + GNN | 引入演员、导演、类型、IP、世界观 | 长视频特别适用，因为影视元数据丰富 |
| 多模态召回 | 图像/文本/音频 embedding + ANN | 根据海报、预告片、剧情简介、风格找相似片 | 适合“氛围相似”“风格相似”的推荐 |
| 语义/LLM 召回 | Semantic ID、生成式检索、TIGER、GPTRec | 用语义空间替代纯 ID embedding | 有助于新片冷启动和跨语言推荐 |
| 热门/运营召回 | 热门榜、新片榜、编辑精选、地区榜 | 保证基础覆盖和运营目标 | 用于保证商业内容、新片、本地化内容曝光 |
| 多路召回融合 | 多通道候选去重、加权、截断 | 避免单一召回偏置 | 工业系统通常同时保留几十路召回 |

### 典型召回通道组合

一个流媒体系统通常同时使用：

- 协同过滤召回；
- 双塔向量召回；
- 序列推荐召回；
- 图召回；
- 知识图谱召回；
- 多模态相似召回；
- 热门与新片召回；
- 个性化榜单召回；
- 续看/追剧召回；
- 搜索历史召回；
- 运营规则召回。

## 2. 粗排阶段：轻量模型过滤候选

目标：**在效果和速度之间折中**，把召回出的几千或几万候选压缩到几百或几千，交给精排模型。

| 算法类型 | 代表算法/方法 | 适合解决的问题 | 特点 |
|---|---|---|---|
| 轻量线性模型 | LR、FM、FFM | 快速预估相关性 | 可解释性强、部署成本低 |
| 因子分解机 | FM、Field-aware FM | 自动学习特征交叉 | 适合稀疏特征 |
| 轻量深度模型 | 小型 DNN、简化 Wide & Deep | 学习非线性关系 | 比 LR 表达能力强 |
| 双塔粗排 | 简化 user tower + item tower | 快速批量打分 | 适合大规模候选打分 |
| 知识蒸馏 | 精排模型蒸馏到粗排模型 | 让粗排更接近精排目标 | 工业常用 |
| 多目标粗排 | 轻量 MMoE / PLE / Shared-Bottom | 同时预测点击、播放、完播 | 适合视频平台 |
| 级联模型 | 简单规则 + 轻模型 + 中复杂模型 | 降低计算成本 | 适合超大规模系统 |

### 粗排常用目标

- 点击概率；
- 播放概率；
- 预计观看时长；
- 完播概率；
- 续看概率；
- 负反馈概率。

### 粗排关键约束

- 模型不能太重；
- 延迟必须低；
- 目标应与精排一致；
- 不能过早过滤掉多样性或冷启动内容。

## 3. 精排阶段：核心效果模型

目标：**更准确地预测用户对候选影片的多种行为**，是推荐系统效果优化的核心。

| 算法类型 | 代表算法/方法 | 适合解决的问题 | 长视频应用 |
|---|---|---|---|
| 传统排序模型 | LR、FM、GBDT+LR | 特征记忆和基础排序 | 早期工业系统常用 |
| Wide & Deep | Wide & Deep Learning | 记忆 + 泛化 | 适合大规模稀疏特征 |
| 深度因子分解机 | DeepFM、xDeepFM、AutoInt | 自动高阶特征交叉 | 适合用户、影片、上下文组合特征 |
| 用户兴趣模型 | DIN、DIEN、SIM | 根据候选影片动态激活相关历史行为 | 适合长视频偏好历史建模 |
| 多任务学习 | MMoE、PLE、ESMM | 同时优化点击、播放、时长、完播等 | YouTube 多任务排序、腾讯视频 PLE 都属于这一类 |
| 序列模型 | GRU、LSTM、SASRec、BERT4Rec | 建模用户观看顺序和兴趣演化 | 适合追剧和连续观看 |
| 图神经网络 | GNN-based ranking | 引入高阶协同关系和知识图谱关系 | 适合稀疏、长尾、多实体影视内容 |
| 多模态模型 | Vision + Text + Audio Fusion | 理解海报、预告片、剧情、音频风格 | 适合内容语义推荐 |
| LLM 排序器 | Zero-shot LLM Ranking、LLM Reranker | 根据自然语言偏好和内容语义排序 | 适合小候选集重排、解释和冷启动 |
| 生存/流失模型 | Cox Model、Survival Model、Churn Prediction | 预测用户是否续订、流失或弃剧 | 适合长期价值优化 |

### 精排常用目标

在长视频场景中，精排通常不只预测点击率，而是多目标建模：

1. 点击；
2. 开始播放；
3. 播放时长；
4. 完播率；
5. 连续观看；
6. 下一集续看；
7. 收藏/加入片单；
8. 评分；
9. 负反馈；
10. 弃剧概率；
11. 长期留存代理指标。

### 常用多目标结构

- **Shared-Bottom**：简单，任务容易互相干扰；
- **MMoE**：多个专家网络 + 任务 gate，适合多任务学习；
- **PLE**：渐进分层专家，减少任务冲突，腾讯视频推荐中有代表性应用。

## 4. 重排阶段：考虑列表级和页面级效果

目标：**不再只看单个 item 的分数，而是优化整个推荐列表或页面**。

| 算法类型 | 代表方法 | 适合解决的问题 | 长视频场景应用 |
|---|---|---|---|
| 规则重排 | 去重、打散、频控、黑名单 | 防止重复或过度同质化 | 避免同一类型连续刷屏 |
| 多样性重排 | MMR、DPP、Determinantal Point Process | 提升列表多样性 | 避免首页全是悬疑片或同一 IP |
| 业务规则重排 | 新片保量、运营内容加权、版权约束 | 满足平台目标 | 新剧宣传、内容采买回报 |
| 列表级排序 | Listwise Ranking、LambdaMART | 优化整个列表质量 | 首页横向列表、榜单 |
| 上下文重排 | Context-aware Ranking | 根据页面位置和周边内容调整排序 | 首屏、第二屏、详情页不同策略 |
| 强化学习重排 | DQN、Policy Gradient、Bandit-based Re-ranking | 优化长期列表价值 | 探索与利用、长期观看 |
| LLM 重排 | LLM Reranker | 理解语义和解释偏好 | 适合少量候选的高级重排 |
| 封面/文案个性化 | Contextual Bandit、多臂老虎机 | 选择最适合用户的海报或标题 | Netflix artwork personalization 的典型思路 |

### 重排常见约束

- 同类型内容打散；
- 同 IP / 同演员 / 同导演内容限制；
- 重复内容过滤；
- 新内容曝光保量；
- 小众内容公平曝光；
- 页面位置差异；
- 商业和运营目标；
- 用户疲劳控制。

## 5. 上下文决策阶段：根据场景动态调整推荐

目标：**让推荐适配时间、设备、家庭、观看进度和页面状态**。

| 上下文类型 | 常用方法 | 应用示例 |
|---|---|---|
| 时间上下文 | 时间特征 + 用户历史模式 | 周末白天适合家庭片，深夜适合惊悚或成人向内容 |
| 设备上下文 | Device embedding + 场景模型 | 手机、电视、平板、投屏偏好不同 |
| 观看进度 | Sequential State Model | 正在追某剧时优先推荐下一集 |
| 家庭上下文 | Household Model、Group Recommendation | 多人共看时推荐折中内容 |
| 共看场景 | Co-viewing Detection、Group RecSys | 情侣、亲子、家庭观看 |
| 页面上下文 | Page-aware Ranking | 首页、搜索页、详情页、完结页不同推荐策略 |
| 实时行为 | Online Learning、Streaming Update | 刚看完恐怖片后立即更新偏好 |
| 探索与利用 | ε-Greedy、UCB、Thompson Sampling、Contextual Bandit | 探索新偏好，避免过度利用旧偏好 |
| 强化学习 | MAB、DQN、Policy Gradient | 优化长期观看和留存 |

## 6. 各阶段算法选择建议

### 如果目标是基础系统

可以用：

- **召回**：ItemCF + 热门召回 + 双塔召回；
- **粗排**：FM 或轻量 DNN；
- **精排**：Wide & Deep / DeepFM；
- **重排**：规则去重 + 类型打散；
- **上下文**：基础时间、设备、观看进度特征。

### 如果目标是中大型流媒体系统

可以用：

- **召回**：多路召回，包括协同过滤、双塔、序列召回、图召回、多模态召回；
- **粗排**：蒸馏模型或轻量多目标模型；
- **精排**：DIN / MMoE / PLE 等多任务深度模型；
- **重排**：MMR / DPP 多样性重排 + 业务规则；
- **上下文**：设备、时间、家庭、页面、观看进度联合建模。

### 如果目标是前沿研究系统

可以加入：

- **召回**：Semantic ID、生成式检索、TIGER、GPTRec；
- **粗排**：精排蒸馏 + 多目标一致性建模；
- **精排**：多模态 + 多任务 + 长期价值建模；
- **重排**：LLM Reranker、列表级强化学习；
- **上下文**：家庭级模型、共看模型、长期满意度与流失预测。

---

## 7. 一句话总结

> **召回负责“找得全”，粗排负责“筛得快”，精排负责“排得准”，重排负责“排得合理”，上下文决策负责“排得合时宜”。**

在长视频推荐中，最重要的不是每个阶段都用最复杂模型，而是让各阶段目标一致：既要预测用户当下想看什么，也要优化完播、续看、留存和长期满意度。
