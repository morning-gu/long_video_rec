# NGCF、LightGCN、PinSage 原理介绍

这三个都属于 **图神经网络推荐召回算法**，核心思想是：

> 把“用户-影片”交互行为组织成图，让用户和影片的表示沿着图结构传播和聚合，从而学到比传统协同过滤更丰富的用户兴趣和内容相似关系。

它们的区别可以概括为：

| 算法 | 图结构 | 核心思想 | 特点 |
|---|---|---|---|
| **NGCF** | 用户-物品二部图 | 在图卷积中加入非线性变换和特征投影 | 表达能力强，但结构较重 |
| **LightGCN** | 用户-物品二部图 | 简化 NGCF，去掉多余变换，只保留加权邻居聚合 | 更简洁、更稳，常作为图推荐强基线 |
| **PinSage** | 大规模带权图 | 使用 GraphSAGE 式邻居采样和聚合，适合工业级大规模系统 | 重点解决十亿级节点、十亿级边上的训练与推理问题 |

---

## 1. NGCF：Neural Graph Collaborative Filtering

NGCF 的目标是把协同过滤信号显式地注入到用户和物品表示中。

### 1.1 输入图结构

NGCF 构建一个用户-物品交互图：

```text
用户 U1 —— 电影 M1
用户 U1 —— 电影 M2
用户 U2 —— 电影 M1
用户 U3 —— 电影 M3
...
```

图中有两类节点：

- 用户节点；
- 物品节点，如电影、剧集、综艺等。

只有存在交互关系的用户和物品之间才有边，例如用户看过、点击过、收藏过、评分过某影片。

### 1.2 核心思想：高阶协同信号

传统矩阵分解只学习：

```text
用户向量 p_u
物品向量 q_i
```

预测分数通常为：

\[
\hat{y}_{ui} = p_u^T q_i
\]

问题是：用户和物品之间的高阶关系没有被显式建模。

例如：

```text
用户 A 看过电影 X
用户 B 也看过电影 X
用户 B 还看过电影 Y
```

那么用户 A 和电影 Y 之间存在间接关系：

```text
A —— X —— B —— Y
```

NGCF 认为这种多跳关系也包含推荐信号。

### 1.3 图卷积过程

NGCF 的每一层都会让节点聚合邻居信息。

对于用户节点 \(u\)，第 \(l+1\) 层表示为：

\[
e_u^{(l+1)} = \sigma \left(
W_1^{(l)} e_u^{(l)}
+
\sum_{i \in N_u}
\frac{1}{\sqrt{|N_u||N_i|}}
\left(
W_1^{(l)} e_i^{(l)}
+
W_2^{(l)} e_i^{(l)}
\right)
\right)
\]

物品节点的更新方式类似。

其中：

- \(e_u^{(l)}\)：用户 \(u\) 在第 \(l\) 层的表示；
- \(N_u\)：与用户 \(u\) 有交互的物品集合；
- \(N_i\)：与物品 \(i\) 有交互的用户集合；
- \(\frac{1}{\sqrt{|N_u||N_i|}}\)：度归一化，降低高度数节点的影响；
- \(W_1, W_2\)：可学习变换矩阵；
- \(\sigma\)：非线性激活函数，如 LeakyReLU。

NGCF 的设计是：

1. 节点自身表示；
2. 邻居节点表示；
3. 自身与邻居的交互项；
4. 非线性变换；
5. 多层堆叠。

最终把各层表示拼接或加权融合，得到最终用户和物品表示。

### 1.4 预测方式

最终用户表示和物品表示分别为：

\[
e_u = e_u^{(0)} \| e_u^{(1)} \| \cdots \| e_u^{(L)}
\]

\[
e_i = e_i^{(0)} \| e_i^{(1)} \| \cdots \| e_i^{(L)}
\]

然后计算：

\[
\hat{y}_{ui} = e_u^T e_i
\]

### 1.5 优点

- 显式建模高阶协同信号；
- 比 MF、Neural CF 更能利用图结构；
- 对稀疏交互有一定帮助；
- 可以缓解长尾影片缺乏行为的问题。

### 1.6 缺点

- 图卷积层中加入了大量权重矩阵和非线性变换；
- 参数较多；
- 训练成本高；
- 后续研究发现，其中很多变换未必必要，甚至可能伤害推荐效果。

这就引出了 **LightGCN**。

## 2. LightGCN：轻量化图卷积推荐

LightGCN 的核心观点是：

> 推荐系统中的用户-物品交互图本质上是简单的二部图。对这种图做推荐时，NGCF 中的特征变换和非线性激活可能是冗余的，甚至有害的。  
> 可以只保留“邻居加权平均”和“层间融合”。

LightGCN 可以看作 NGCF 的简化和强化版。

### 2.1 核心结构

LightGCN 的每一层非常简单：

对于用户 \(u\)：

\[
e_u^{(l+1)} =
\sum_{i \in N_u}
\frac{1}{\sqrt{|N_u||N_i|}}
e_i^{(l)}
\]

对于物品 \(i\)：

\[
e_i^{(l+1)} =
\sum_{u \in N_i}
\frac{1}{\sqrt{|N_i||N_u|}}
e_u^{(l)}
\]

也就是说：

- 不使用权重矩阵；
- 不使用非线性激活；
- 只做邻居归一化聚合；
- 类似平滑传播。

### 2.2 层融合

LightGCN 不只是使用最后一层表示，而是融合所有层：

\[
e_u =
\sum_{l=0}^{L} \alpha_l e_u^{(l)}
\]

\[
e_i =
\sum_{l=0}^{L} \alpha_l e_i^{(l)}
\]

其中：

\[
\alpha_l = \frac{1}{L+1}
\]

也可以作为可学习参数。

这样做的好处是：

- 第 0 层保留原始 embedding；
- 第 1 层捕捉直接交互；
- 第 2 层捕捉二跳关系；
- 第 3 层捕捉更高阶关系；
- 融合后兼顾局部和全局信息。

### 2.3 预测方式

最终仍然使用内积：

\[
\hat{y}_{ui} = e_u^T e_i
\]

### 2.4 为什么 LightGCN 有效？

LightGCN 的关键不是“更复杂”，而是“更简单”。

它避免了 NGCF 中的几个问题：

| NGCF 中的设计 | LightGCN 的处理 | 原因 |
|---|---|---|
| 权重矩阵 \(W\) | 去掉 | 对推荐图未必有效 |
| 非线性激活 | 去掉 | 二部图推荐中可能引入噪声 |
| 复杂节点变换 | 简化为邻居加权平均 | 推荐图的核心信号是协同连接 |
| 只用最后一层 | 融合多层表示 | 保留不同阶数的协同信号 |

LightGCN 论文中的重要发现是：

> 在 NGCF 去掉特征变换和非线性激活后，效果不仅没有下降，反而更好，参数量也显著减少。

### 2.5 优点

- 参数少；
- 训练更快；
- 效果稳定；
- 容易实现；
- 是图推荐领域非常强的 baseline；
- 适合作为长视频召回中的通用图召回模块。

### 2.6 缺点

- 仍然依赖完整用户-物品图；
- 在超大规模图上直接训练成本高；
- 对动态图、实时交互更新不如工业系统友好；
- 本身不处理内容语义，主要利用行为协同信号。

## 3. PinSage：面向大规模工业系统的图神经网络

PinSage 是 Pinterest 提出的图神经网络推荐算法，基于 GraphSAGE 思想，用于 Pinterest 中的 Pin-Board 图推荐。

在长视频场景中，可以类比理解为：

- Pin → 电影、剧集、海报、视频片段、内容节点；
- Board → 用户收藏夹、播放列表、片单、兴趣主题。

PinSage 的重点不是提出一个全新的图卷积公式，而是解决：

> 如何让 GNN 在十亿节点、百亿边的工业图上训练、推理和上线。

### 3.1 核心思想

PinSage 使用邻居采样和消息传递。

对于目标节点，不使用全部邻居，而是采样一部分重要邻居进行聚合。

基本过程：

1. 选择一个目标节点，例如某部电影；
2. 采样其邻居，例如与该片相关的用户、片单、相似影片；
3. 聚合邻居信息；
4. 更新目标节点表示；
5. 重复多层，得到最终 embedding；
6. 用 embedding 进行召回或相似推荐。

### 3.2 邻居采样：随机游走重要性采样

PinSage 不采用普通随机邻居采样，而是使用 **random-walk based importance sampling**。

其思想是：

> 一个邻居如果通过多次随机游走更容易到达，说明它与目标节点关系更紧密，应赋予更高权重。

相比简单平均采样，这种方式更适合工业图：

- 高度数节点不会被所有邻居均摊权重；
- 更相关的邻居有更高采样概率；
- 能降低训练噪声；
- 能提升效果。

### 3.3 聚合方式

PinSage 使用类似 GraphSAGE 的聚合：

\[
h_v^{(l+1)} = \sigma \left(
W_l h_v^{(l)}
+
W_{agg} \cdot \text{Aggregate}(\{h_u^{(l)} : u \in N(v)\})
\right)
\]

其中：

- \(h_v^{(l)}\)：节点 \(v\) 在第 \(l\) 层的表示；
- \(N(v)\)：采样邻居；
- Aggregate 可以是 mean、weighted pooling 等；
- \(W_l\)、\(W_{agg}\)：可学习参数；
- \(\sigma\)：激活函数。

PinSage 实际采用的是带权聚合和池化操作，使重要邻居对目标节点表示贡献更大。

### 3.4 训练目标：margin-based ranking loss

PinSage 使用排序学习目标，让相关物品的分数高于无关物品：

\[
L =
\max(0,
\gamma - s(q, p_{positive})
+ s(q, p_{negative})
)
\]

含义是：

- \(q\)：query 节点；
- \(p_{positive}\)：相关物品；
- \(p_{negative}\)：无关或负样本物品；
- \(\gamma\)：margin；
- 希望正样本分数比负样本高至少 \(\gamma\)。

PinSage 的负样本不是完全随机采样的，而是采用 hard negative mining，即选择一些“看起来相似但不相关”的负样本，提高模型判别能力。

### 3.5 工程设计：Map-Reduce 推理

PinSage 面向十亿级节点，因此必须解决推理效率问题。

它采用 Map-Reduce 式的多阶段 embedding 计算：

1. 先计算低层节点表示；
2. 将中间结果保存下来；
3. 再基于低层结果计算高层表示；
4. 最终生成全库 item embedding；
5. 建立近似最近邻检索索引。

这样可以避免对每个请求重复计算所有 embedding。

### 3.6 优点

- 专为超大规模工业图设计；
- 支持邻居采样，不要求全图训练；
- 能处理十亿级节点和百亿级边；
- 可离线生成 item embedding；
- 可与 ANN 索引结合，适合线上召回；
- 支持带权图和异构图思想。

### 3.7 缺点

- 工程复杂度高；
- 需要图存储、采样、分布式训练和推理管线；
- 邻居采样可能引入偏差；
- 对实时变化的图更新要求较高；
- 训练和部署成本高于 LightGCN 这类学术基线。

## 4. 三者直观对比

假设我们要为一个用户推荐电影。

### NGCF 的做法

```text
用户节点和电影节点组成二部图
用户表示和电影表示经过多层图卷积
每一层都有权重矩阵、非线性变换和邻居聚合
最终融合多层表示
用内积计算推荐分数
```

特点：表达能力强，但模型较重。

---

### LightGCN 的做法

```text
用户节点和电影节点组成二部图
每层只做邻居加权平均
不加权重矩阵
不加非线性激活
最后融合各层表示
用内积计算推荐分数
```

特点：简单、高效、稳定，是学术图推荐的强 baseline。

---

### PinSage 的做法

```text
构建大规模内容图、用户图、交互图
对目标节点采样重要邻居
使用 GraphSAGE 式聚合
训练目标是让相关内容分数高于不相关内容
通过 Map-Reduce 离线生成 embedding
线上用 ANN 检索相似内容
```

特点：面向工业大规模系统，重点解决可扩展性。

## 5. 在长视频推荐中的适用方式

### 5.1 NGCF 适合的场景

- 中小规模电影数据集；
- 用户-影片交互较完整；
- 希望显式建模高阶协同关系；
- 作为研究或实验模型。

不太适合直接用于超大规模线上系统，因为计算和存储成本较高。

---

### 5.2 LightGCN 适合的场景

- 通用图召回 baseline；
- 电影、剧集交互数据规模适中；
- 希望在参数量和效果之间取得平衡；
- 平台已有较完整的用户-内容交互图。

在长视频场景中，LightGCN 常用于：

- 用户相似兴趣扩展；
- 长尾影片召回；
- 基于观看图的协同召回；
- 图 embedding 离线生成。

---

### 5.3 PinSage 适合的场景

- 超大规模内容平台；
- 节点数量达到千万级、亿级；
- 图中包含影片、用户、片单、标签、演员、IP、话题等多种节点；
- 需要离线生成 embedding 并线上 ANN 召回；
- 需要处理工业级图规模。

在长视频平台中，PinSage 类方法可用于：

- 大规模电影相似召回；
- 剧集相似召回；
- 片单推荐；
- 基于演员、导演、题材、IP 的高阶关系召回；
- 用户兴趣图召回。

---

## 6. 一句话总结

> **NGCF 把图卷积引入协同过滤，LightGCN 把它简化到更适合推荐任务的形式，PinSage 则把 GNN 推荐推向十亿级工业系统。**

如果做研究 baseline，优先考虑 **LightGCN**；  
如果做学术比较，可以同时使用 **NGCF / LightGCN**；  
如果要构建大规模长视频平台的图召回系统，则更适合参考 **PinSage** 的邻居采样、分布式训练和离线 embedding 架构。
