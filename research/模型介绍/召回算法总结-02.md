# 序列召回三算法：GRU4Rec、SASRec、BERT4Rec

这三个算法都属于 **sequential recommendation / 序列推荐**，核心思想是：

> 不再把用户偏好当成一个静态向量，而是把用户历史行为看成一个有时间顺序的序列，用序列中较早的行为预测用户下一个可能感兴趣的 item。

在长视频场景中，用户行为可能是：

```text
电影A → 剧集B第1集 → 剧集B第2集 → 纪录片C → 电影D
```

序列推荐模型希望根据这条历史，预测下一个可能被点击或观看的内容。

---

## 1. GRU4Rec：用 GRU 建模用户会话

### 1.1 原始问题

GRU4Rec 主要面向 **session-based recommendation**，即根据用户当前 session 内的行为预测下一个 item。

例如一个 session：

```text
点击剧A → 点击电影B → 点击剧C → 预测下一个？
```

早期方法常用 item co-occurrence 或近邻方法，但它们难以捕捉序列中的顺序依赖。GRU4Rec 的贡献是用循环神经网络来建模 session 内的行为顺序。

---

### 1.2 核心思想

GRU4Rec 使用 **GRU，Gated Recurrent Unit** 处理用户行为序列。

GRU 是一种简化的 RNN。它通过门控机制决定：

- 哪些历史信息应该保留；
- 哪些历史信息应该遗忘；
- 当前行为如何更新用户状态。

其结构可以概括为：

```text
上一个时刻的隐状态 h_{t-1}
        ↓
当前行为 item embedding x_t
        ↓
GRU 单元
        ↓
当前隐状态 h_t
        ↓
预测下一个 item
```

在每个时间步，模型都会生成一个用户兴趣表示：

```text
h_t = GRU(h_{t-1}, x_t)
```

然后用 `h_t` 对候选 item 打分：

```text
score(i) = h_t · item_embedding(i)
```

最后对全库或候选集中的 item 做 softmax，选择分数最高的作为下一个推荐。

---

### 1.3 为什么适合长视频

GRU4Rec 对追剧和连续观看场景比较有用，因为用户的当前兴趣往往与最近几个行为强相关。

例如：

```text
剧A第1集 → 剧A第2集 → 剧A第3集
```

这种连续行为天然适合 RNN 或 GRU 建模。

它也能捕捉短期偏好变化，例如用户最近连续看悬疑剧，那么当前 session 内的 GRU 隐状态会更偏向悬疑内容。

---

### 1.4 局限

1. **长序列建模能力有限**  
   GRU 逐个时间步压缩历史信息，距离较远的行为容易被遗忘。

2. **串行计算，训练和推理较慢**  
   RNN 类模型难以像 Transformer 一样大规模并行训练。

3. **主要建模短期 session 兴趣**  
   原始 GRU4Rec 更偏 session-based recommendation，不适合直接建模用户几个月甚至几年的完整历史。

4. **item 通常只作为离散 ID**  
   它不天然理解电影内容、演员、剧情、风格等语义信息。

---

## 2. SASRec：用自注意力建模用户历史

### 2.1 原始问题

SASRec，Self-Attentive Sequential Recommendation，是为了解决 RNN 类序列推荐的几个问题：

- 训练难以并行；
- 长距离依赖建模弱；
- 对历史行为的加权方式不够灵活。

SASRec 将 Transformer 中的 self-attention 引入推荐系统。

---

### 2.2 核心思想

SASRec 的输入是用户最近的行为序列：

```text
item_1, item_2, item_3, ..., item_t
```

每个 item 会被转成 embedding：

```text
x_1, x_2, x_3, ..., x_t
```

然后加入位置编码：

```text
x_i = item_embedding(i) + position_embedding(i)
```

接着通过多层 self-attention 学习哪些历史行为对预测下一个 item 更重要。

例如用户历史是：

```text
科幻电影A → 爱情电影B → 科幻剧C → 纪录片D
```

当预测下一个 item 时，SASRec 可以自动判断：

- 科幻电影A 更重要；
- 爱情电影B 权重较低；
- 科幻剧C 可能也重要；
- 纪录片D 权重一般。

---

### 2.3 注意力机制

在 self-attention 中，每个历史行为会生成三个向量：

- Query；
- Key；
- Value。

简单理解为：

```text
Query: 我现在想找什么？
Key: 每个历史行为代表什么？
Value: 每个历史行为能提供什么信息？
```

模型先计算当前 Query 与每个历史 Key 的相关性，再根据相关性加权聚合 Value。

直觉上：

```text
当前兴趣 = 权重1 × 历史行为1
         + 权重2 × 历史行为2
         + ...
         + 权重n × 历史行为n
```

这些权重通过 softmax 归一化。

---

### 2.4 因果遮蔽：只看过去，不看未来

SASRec 是 next-item prediction，因此在第 `t` 个位置预测第 `t+1` 个 item 时，只能使用前 `t` 个行为，不能使用未来行为。

所以它使用 causal mask：

```text
位置1 只能看位置1
位置2 只能看位置1、2
位置3 只能看位置1、2、3
...
```

训练时每个位置都可以同时训练：

```text
根据 item_1 预测 item_2
根据 item_1、item_2 预测 item_3
根据 item_1、item_2、item_3 预测 item_4
```

这使模型可以并行训练，效率比 GRU 高很多。

---

### 2.5 为什么适合长视频

SASRec 更适合建模较长的用户观看历史。

例如：

```text
三个月前看的科幻片
上个月看的犯罪剧
上周看的科幻纪录片
昨天看的悬疑剧
```

对于预测下一个推荐，SASRec 可以自动决定历史中哪些行为相关，而不是像 GRU 那样逐层压缩。

它对以下情况较有优势：

- 用户长期偏好；
- 题材偏好漂移；
- 最近观看行为影响较大；
- 历史中只有部分行为与当前意图相关。

---

### 2.6 局限

1. **仍然是 ID-based 模型为主**  
   如果一个新电影没有交互数据，SASRec 难以直接学出高质量 embedding。

2. **序列长度有限**  
   通常只取最近几十个或几百个行为，无法处理特别长的历史。

3. **训练目标仍是 next-item prediction**  
   它预测下一个 item，但不直接优化完播率、观看时长、续订等业务目标。

4. **对强序列结构剧集建模不足**  
   如果把整部剧当作一个 item，SASRec 可以学习追剧行为；但如果需要 episode-level 建模，还需要额外结构设计。

---

## 3. BERT4Rec：用双向 Transformer 建模序列

### 3.1 原始问题

SASRec 使用因果注意力，只能根据过去预测未来。但在推荐数据中，历史序列中间的某些行为可能被缺失、乱序或记录不完整。BERT4Rec 的出发点是：

> 推荐不一定只能从左到右预测下一个 item，也可以像 BERT 一样，通过上下文补全缺失位置。

BERT4Rec 将 BERT 的 masked language modeling 思想引入推荐系统。

---

### 3.2 核心思想

BERT4Rec 的输入也是用户行为序列：

```text
item_1, item_2, item_3, item_4, item_5
```

训练时随机遮住某些 item：

```text
item_1, [MASK], item_3, [MASK], item_5
```

模型需要根据上下文预测被遮住的 item：

```text
item_1, [MASK], item_3, [MASK], item_5
              ↓
       预测 item_2 和 item_4
```

由于每个位置都能看到左右两侧信息，因此它是 **双向序列建模**。

---

### 3.3 与 SASRec 的关键区别

| 维度 | SASRec | BERT4Rec |
|---|---|---|
| 建模方式 | 从左到右，因果注意力 | 双向上下文建模 |
| 训练目标 | 预测下一个 item | 预测被 mask 的 item |
| 能否看未来 | 不能 | 训练时可以，推理时需特殊处理 |
| 优势 | 更贴近 next-item recommendation | 上下文建模更强 |
| 风险 | 可能低估上下文信息 | 线上推理时如果使用不当，会造成信息泄漏或目标不一致 |

BERT4Rec 更像：

```text
根据完整上下文补全缺失行为
```

SASRec 更像：

```text
根据过去行为预测未来行为
```

---

### 3.4 为什么适合长视频

BERT4Rec 可以利用前后文更好地理解用户观看行为中的中间状态。

例如：

```text
科幻电影A → [缺失] → 科幻剧C
```

BERT4Rec 可以根据前后行为推测中间可能是什么类型的电影。

它对以下情况有帮助：

- 用户行为序列中有缺失记录；
- 用户兴趣存在主题段；
- 多个观看行为共同指向同一偏好；
- 需要更完整的上下文表示。

---

### 3.5 局限

1. **线上推理目标不完全一致**  
   训练时预测被 mask 的中间 item，但线上通常仍要预测下一个 item。训练目标和部署目标之间存在差异。

2. **直接使用未来信息会造成泄漏风险**  
   训练时双向注意力可以看左右上下文，但线上真实场景不知道未来。因此实现时要谨慎设计 mask 和推理方式。

3. **推理成本更高**  
   双向 Transformer 的上下文建模通常比轻量因果模型更重。

4. **仍以离散 item ID 为主**  
   对新片冷启动、多模态语义和 episode-level 结构支持不足。

---

## 4. 三者直观对比

| 维度 | GRU4Rec | SASRec | BERT4Rec |
|---|---|---|---|
| 模型结构 | GRU / RNN | 因果 self-attention | 双向 self-attention |
| 建模方式 | 顺序递归 | 从左到右 | 上下文补全 |
| 输入 | 用户行为序列 | 用户行为序列 | 用户行为序列 |
| 核心预测 | 下一个 item | 下一个 item | 被 mask 的 item |
| 长距离依赖 | 较弱 | 较强 | 强 |
| 并行训练 | 弱 | 强 | 强 |
| 适合场景 | 短期 session、连续观看 | 长期历史、next-item 推荐 | 上下文补全、缺失行为建模 |
| 主要缺点 | 长序列遗忘、串行计算 | 冷启动弱、序列长度受限 | 训练/推理目标可能不一致 |

---

## 5. 用一个例子解释三者差异

假设用户历史观看序列是：

```text
1. 科幻电影A
2. 科幻剧B
3. 爱情电影C
4. 悬疑剧D
5. 科幻纪录片E
```

现在的任务是预测用户接下来想看什么。

### GRU4Rec

GRU4Rec 会逐步更新用户状态：

```text
科幻电影A → 更新兴趣
科幻剧B → 更新兴趣
爱情电影C → 更新兴趣
悬疑剧D → 更新兴趣
科幻纪录片E → 得到最终兴趣状态
```

然后预测下一个 item。

它的特点是：越靠后的行为通常影响越大，但较早行为可能被压缩或遗忘。

---

### SASRec

SASRec 会为每个位置计算注意力权重，例如预测下一个 item 时：

```text
科幻电影A：0.25
科幻剧B：0.20
爱情电影C：0.05
悬疑剧D：0.10
科幻纪录片E：0.40
```

它会自动发现：科幻相关行为和最近行为更重要。

---

### BERT4Rec

BERT4Rec 训练时可能会遮住某个位置：

```text
科幻电影A
科幻剧B
爱情电影C
[MASK]
科幻纪录片E
```

然后根据左右上下文预测被遮住的位置。它学到的是整个序列的上下文关系，而不仅是“从过去预测未来”。

---

## 6. 在长视频推荐中的实际用法

这三个算法通常不是直接作为完整推荐系统，而是作为 **序列召回通道** 或 **精排中的用户兴趣表示模块**。

### 6.1 作为序列召回

流程如下：

```text
用户历史观看序列
   ↓
GRU4Rec / SASRec / BERT4Rec
   ↓
得到当前用户兴趣向量
   ↓
与所有候选影片 embedding 做内积或近似检索
   ↓
返回 Top-K 候选
```

例如：

```text
用户最近看了三部科幻剧
   ↓
序列模型生成 sci-fi 偏好向量
   ↓
从片库中召回科幻电影、科幻剧集、科幻纪录片
```

---

### 6.2 作为精排中的用户兴趣特征

序列模型输出的用户兴趣向量可以输入精排模型：

```text
用户画像特征
设备特征
时间特征
影片特征
序列模型兴趣向量
   ↓
MMoE / PLE / DeepFM 精排模型
   ↓
点击、播放、完播、续看预测
```

这样可以同时利用：

- 长期偏好；
- 短期兴趣；
- 序列依赖；
- 上下文信息。

---

## 7. 三算法的选择建议

### 如果关注短 session 行为

例如：

- 一次连续观看 session；
- 当前页面内连续点击；
- 追剧过程中的下一集推荐；

可以优先考虑：

```text
GRU4Rec
```

或更现代的轻量序列模型。

---

### 如果关注较长的用户历史和 next-item 预测

例如：

- 用户过去几个月的观看历史；
- 长期题材偏好；
- 偏好漂移；

可以优先考虑：

```text
SASRec
```

它比 GRU4Rec 更适合长序列，也更容易并行训练。

---

### 如果希望利用完整上下文

例如：

- 用户序列记录不完整；
- 想根据前后行为推测中间偏好；
- 想构建更强的序列表示；

可以尝试：

```text
BERT4Rec
```

但要注意线上推理时的目标一致性，避免未来信息泄漏。

---

## 8. 总结

三个算法的共同点是：

> 都把推荐问题从静态画像建模转成序列行为建模。

它们的区别在于：

```text
GRU4Rec：用循环网络逐步压缩历史，适合短期连续行为。
SASRec：用因果注意力自动选择相关历史，适合 next-item 推荐。
BERT4Rec：用双向注意力补全上下文，适合更强的序列表示学习。
```

在长视频推荐中，它们可以用于：

- 追剧行为建模；
- 连续观看预测；
- 用户兴趣漂移建模；
- 长期观看历史召回；
- 精排中的兴趣特征生成；
- 下一部电影或下一集推荐。

但它们也有共同限制：原始版本主要是 **item ID 序列模型**，对电影内容语义、新片冷启动、家庭共看、episode-level 结构和长期留存目标的支持不足。因此现代工业系统通常会将它们与多模态 embedding、知识图谱、多任务学习和长期价值模型结合使用。
