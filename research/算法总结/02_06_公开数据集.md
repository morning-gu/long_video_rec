# 长视频推荐模型可用的公开数据集分析

## 1. 先说结论

公开数据集可以支持 **研究原型和离线 benchmark**，但很难完整训练一个工业级长视频推荐系统，因为公开数据普遍缺少：

- 曝光日志；
- 页面位置信息；
- 点击、播放、完播、弃剧等多行为信号；
- 设备、时间、家庭、共看等上下文；
- 订阅、留存、churn 等长期价值标签；
- 封面点击实验数据；
- 线上时延和成本约束。

最实用的研究组合是：

> **MovieLens / Netflix Prize / Amazon Movies and TV 提供用户行为；IMDb / TMDB / Wikidata 提供影视知识图谱；MM-IMDb / MovieNet 提供多模态内容；ReDial 提供对话式推荐；Trakt 或 UMAP TV 数据补充剧集级和上下文信息。**

---

## 2. 核心用户行为数据集

这些数据集可以直接用于训练协同过滤、矩阵分解、序列推荐、图推荐等基础模型。

### 2.1 MovieLens

- **类型**：电影评分数据集；
- **主要信号**：用户、电影、评分、时间戳、标签；
- **规模**：有 100K、1M、10M、20M、25M、32M 等版本；
- **官网**：[MovieLens Datasets](https://grouplens.org/datasets/movielens/)

#### 可训练模型

| 模型类型 | 可用性 | 说明 |
|---|---|---|
| UserCF / ItemCF | 高 | 可基于评分或隐式正反馈构造共现关系 |
| Matrix Factorization / ALS | 高 | 经典评分预测任务 |
| BPR / implicit CF | 高 | 可将评分 ≥4 视为正反馈，未交互视为未知 |
| Neural CF | 高 | MovieLens 是 NCF 常用 benchmark |
| SASRec / BERT4Rec | 高 | 有时间戳，可构造观看序列 |
| LightGCN / NGCF | 高 | 可构造用户-电影二部图 |
| 知识图谱推荐 | 高 | 可通过 MovieLens 的 `links.csv` 关联 IMDb / TMDB |
| 多模态推荐 | 中高 | 需要额外关联海报、剧情、演员等信息 |
| LLM 推荐 | 中 | 可将历史电影和元数据转成自然语言 prompt |

#### 局限

- 是显式评分，不是真实观看行为；
- 没有曝光日志，负样本只能采样；
- 没有完播率、播放时长、弃剧、续看；
- 没有家庭账号、设备、页面位置和真实推荐反馈；
- 电影 item 粒度为主，缺少剧集 episode / season 结构。

**结论**：MovieLens 是长视频推荐研究最常用的起点，但只适合作为离线研究基准，不能代表真实流媒体系统。

---

### 2.2 Netflix Prize Dataset

- **类型**：电影评分竞赛数据；
- **主要信号**：用户、电影、评分、日期；
- **规模**：约 1 亿条评分、48 万用户、1.77 万部电影；
- **状态**：历史公开数据集，但当前分发和授权情况需谨慎确认。

#### 可训练模型

| 模型类型 | 可用性 | 说明 |
|---|---|---|
| Matrix Factorization | 高 | Netflix Prize 时代的核心任务 |
| SVD / SVD++ / time-aware MF | 高 | 可利用评分日期建模偏好变化 |
| ensemble / blending | 高 | 竞赛方案大量使用模型融合 |
| ItemCF / UserCF | 高 | 可作为传统 baseline |
| 序列推荐 | 中 | 有日期但没有精确时间戳和行为顺序细节 |
| 多任务排序 | 低 | 缺少点击、播放、完播等行为标签 |

#### 局限

- 目标是 RMSE，而不是 Top-N 推荐或长期观看价值；
- 没有真实曝光和推荐策略日志；
- 没有剧集结构和多模态内容；
- 数据较老，和当前流媒体场景差异大。

**结论**：适合研究经典矩阵分解和评分预测，但不适合训练现代工业推荐系统。

---

### 2.3 Amazon Movies and TV Reviews

- **类型**：电影 / 电视剧评论和评分数据；
- **主要信号**：用户、商品、评分、评论文本、时间戳；
- **获取方式**：Amazon review data 公开版本。

#### 可训练模型

| 模型类型 | 可用性 | 说明 |
|---|---|---|
| 协同过滤 | 高 | 用户-影片交互 |
| 序列推荐 | 高 | 有时间戳 |
| 文本增强推荐 | 高 | 可利用评论文本 |
| 情感分析辅助推荐 | 高 | 可从评论中抽取偏好 |
| LLM 推荐 | 中高 | 可构造“用户评论历史 + 推荐请求”的数据 |
| 多模态推荐 | 中 | 需要额外关联影片图像和元数据 |

#### 局限

- 评论行为不等于观看行为；
- 用户可能评论但没有真实消费记录；
- 电影和 TV 商品粒度不统一；
- 缺少播放时长和完播信号；
- 评论存在选择偏差，愿意写评论的用户不代表普通观众。

**结论**：适合研究文本增强和评论驱动的电影推荐，尤其是 LLM-based recommendation。

---

### 2.4 MyAnimeList 类动画评分数据

- **类型**：动画 / 剧集评分和观看列表；
- **主要信号**：用户、作品、评分、观看状态、集数信息；
- **公开形态**：存在多个 Kaggle / 社区整理版本，授权需确认。

#### 可训练模型

| 模型类型 | 可用性 | 说明 |
|---|---|---|
| 协同过滤 | 高 | 用户-作品评分 |
| 序列推荐 | 中高 | 可按用户观看时间构造序列 |
| 长内容结构建模 | 中 | 动画常有季、集、连载状态 |
| 完播 / 弃番预测 | 中 | 部分数据包含观看状态，但质量依赖来源 |
| 图推荐 | 中 | 可结合作品类型、制作公司、声优等元数据 |

#### 局限

- 领域局限于动画；
- 数据来自用户自报告，存在偏差；
- 不同公开快照的字段和质量差异较大；
- 授权和更新状态不稳定。

**结论**：如果研究“剧集连载、追番、弃番”这类长视频行为，MyAnimeList 数据比 MovieLens 更接近长内容结构，但领域泛化性有限。

---

### 2.5 Trakt.tv API 数据

- **类型**：个人电影 / 剧集观看记录；
- **主要信号**：观看历史、进度、评分、episode-level 记录；
- **官网**：[Trakt API](https://trakt.docs.apiary.io/)

#### 可训练模型

| 模型类型 | 可用性 | 说明 |
|---|---|---|
| episode-level 推荐 | 高 | 少数可获取剧集级观看行为的公开来源 |
| season-level 推荐 | 高 | 可按季聚合 |
| 追剧行为建模 | 高 | 可分析连续观看和中断 |
| binge watching 建模 | 中高 | 有时间戳和剧集进度时可分析 |
| 上下文推荐 | 中 | 可结合时间、 weekday / weekend 等特征 |
| 长期偏好建模 | 中高 | 有长期观看历史 |

#### 局限

- 不是标准静态学术 benchmark；
- 需要 API 授权和合规使用；
- 用户是主动记录型用户，存在自选择偏差；
- 不一定能获得完整曝光和负反馈；
- 隐私限制较强。

**结论**：Trakt 是研究 episode-level 长视频推荐的重要现实数据来源，但更适合构建自有研究数据集，而不是直接引用一个统一公开 benchmark。

## 3. 影视元数据与知识图谱数据集

这些数据集没有用户行为，不能单独训练推荐模型，但非常适合作为内容侧特征、知识图谱和冷启动增强。

### 3.1 IMDb Datasets

- **类型**：影视元数据；
- **主要信号**：标题、类型、年份、演职人员、剧集结构、别名等；
- **官网**：[IMDb Datasets](https://datasets.imdbws.com/)

#### 可增强的模型

| 模型类型 | 用途 |
|---|---|
| Knowledge Graph Recommendation | 构建电影-演员-导演-类型图 |
| KGCN / KGAT | 提供实体和关系 |
| 冷启动推荐 | 新片可利用元数据表示 |
| 图神经网络 | 构造异构图或二部图 |
| LLM 语义推荐 | 将元数据转成自然语言描述 |
| episode-level 建模 | 提供 TV series / season / episode 元数据 |

#### 局限

- 无用户行为；
- 字段质量不完全一致；
- 需要与 MovieLens、Trakt、Amazon 等行为数据关联。

**结论**：IMDb 是构建长视频知识图谱推荐的基础数据源。

---

### 3.2 TMDB

- **类型**：电影 / 电视剧元数据 API；
- **主要信号**：海报、简介、类型、演员、剧组、季节、集数、评分、流行度；
- **官网**：[TMDB API](https://www.themoviedb.org/documentation/api)

#### 可增强的模型

| 模型类型 | 用途 |
|---|---|
| 多模态推荐 | 海报、剧照、简介 |
| 内容召回 | 根据剧情、类型、风格找相似影片 |
| 知识图谱推荐 | 演职人员、系列、类型关系 |
| LLM 推荐 | 生成影片自然语言画像 |
| 新片冷启动 | 新片有丰富元数据但缺乏交互 |

#### 局限

- 无用户观看行为；
- API 有调用限制；
- 海报和简介不能完全代表影片风格；
- 需要处理 ID 对齐问题。

**结论**：TMDB 是连接 MovieLens 与多模态 / 知识图谱特征的关键数据源。

---

### 3.3 Wikidata / DBpedia

- **类型**：开放知识图谱；
- **主要信号**：电影、剧集、演员、导演、制作公司、获奖、主题、系列关系。

#### 可增强的模型

| 模型类型 | 用途 |
|---|---|
| KGAT / KGCN / TransE | 构建实体-关系图 |
| 跨语言推荐 | Wikidata 有多语言标签 |
| 冷启动推荐 | 新片可连接到已有知识图谱节点 |
| 可解释推荐 | 生成“因为同一导演 / 同一系列 / 同一题材”的解释 |

#### 局限

- 影视相关关系覆盖不完整；
- 需要清洗和实体对齐；
- 知识图谱关系不总是与用户偏好相关。

**结论**：适合增强知识图谱推荐和可解释推荐，但需要较重的数据工程。

---

## 4. 多模态影视数据集

这些数据集适合训练内容表示模型，再迁移到推荐系统中。

### 4.1 MM-IMDb

- **类型**：多模态电影数据；
- **主要信号**：电影海报、剧情简介、类型标签；
- **规模**：约 2.6 万部电影；
- **官网**：[MM-IMDb](https://archive.ics.uci.edu/dataset/603/multimodal+imdb+dataset)

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| 多模态电影分类 | 高 |
| 海报 + 文本 fusion | 高 |
| 内容 embedding | 高 |
| 多模态推荐 | 中高，需与用户行为数据关联 |
| 冷启动推荐 | 中高 |

#### 局限

- 无用户行为；
- 任务本身是类型分类，不是推荐；
- 只包含海报和剧情文本，缺少预告片、音频、字幕等信号。

**结论**：适合训练电影内容 encoder，然后迁移到 MovieLens / Amazon / Trakt 的推荐任务。

---

### 4.2 MovieNet

- **类型**：电影理解数据集；
- **主要信号**：电影片段、帧、人物、剧情、字幕、海报等；
- **官网**：[MovieNet](https://movienet.github.io/)

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| 视频内容理解 | 高 |
| 电影风格 / 场景 embedding | 高 |
| 多模态推荐 | 中高 |
| 预告片 / 片段召回 | 中 |
| LLM 多模态推荐 | 中 |

#### 局限

- 不是用户行为数据集；
- 主要用于电影理解，不是推荐 benchmark；
- 需要较多计算资源处理视频。

**结论**：适合训练长视频内容表示，再作为推荐系统的 item embedding。

---

### 4.3 RAG-VisualRec

- **类型**：视觉和文本增强的电影推荐资源；
- **主要信号**：电影海报、简介、元数据、检索增强生成设置；
- **相关论文**：arXiv:2506.20817。

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| RAG-based movie recommendation | 高 |
| 视觉 + 文本电影检索 | 高 |
| LLM 电影推荐 | 中高 |
| 冷启动推荐 | 中高 |

#### 局限

- 主要面向电影推荐研究；
- 多模态深度仍以海报和文本为主；
- 需要注意与线上推荐目标的差距。

**结论**：这是目前较直接面向“多模态 + LLM + 电影推荐”的公开研究资源之一。

---

## 5. 剧集结构与上下文数据集

### 5.1 Serial Speakers

- **类型**：电视剧多模态标注数据集；
- **主要信号**：角色、对话、情节结构；
- **规模**：161 集，覆盖 3 部美剧；
- **来源**：[ACL Anthology](https://aclanthology.org/2020.lrec-1.525/)

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| 剧情结构理解 | 高 |
| 角色关系建模 | 高 |
| episode-level 内容表示 | 高 |
| 推荐模型 | 低，需结合用户行为 |

#### 局限

- 规模小；
- 没有用户行为；
- 不是推荐数据集。

**结论**：适合研究 episode-level 内容理解，不能单独训练推荐模型。

---

### 5.2 TVSeries Dataset

- **类型**：电视剧视频动作检测数据；
- **主要信号**：视频片段、动作类别；
- **规模**：约 16 小时视频、6 部电视剧、30 个动作类别。

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| 视频动作识别 | 高 |
| 长视频内容分段 | 高 |
| 视频 embedding | 中高 |
| 个性化推荐 | 低，需结合行为数据 |

#### 局限

- 不是推荐数据；
- 规模有限；
- 与用户偏好无直接联系。

**结论**：可作为剧集内容表示的辅助数据源。

---

### 5.3 UMAP TV Context Dataset

- **类型**：电视观看上下文偏好数据；
- **主要信号**：用户、观看行为、上下文；
- **来源**：UMAP 2018 论文。

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| 上下文感知推荐 | 中高 |
| 时间 / 场景建模 | 中 |
| TV 推荐研究 | 中 |
| 家庭 / 共看建模 | 视数据字段而定 |

#### 局限

- 公开程度和规模有限；
- 上下文定义依赖采集平台；
- 不一定覆盖现代流媒体场景。

**结论**：适合研究上下文感知 TV 推荐，但难以支撑大规模工业模型训练。

---

## 6. 对话式推荐数据集

### 6.1 ReDial

- **类型**：电影推荐对话数据集；
- **主要信号**：多轮对话、电影推荐、用户偏好表达；
- **官网**：[ReDial](https://github.com/ReDialData/ReDial)

#### 可训练模型

| 模型类型 | 可用性 |
|---|---|
| Conversational Recommender | 高 |
| LLM 电影推荐 | 高 |
| 偏好澄清 | 高 |
| 推荐解释生成 | 高 |
| 多轮偏好建模 | 高 |
| 传统 Top-N 推荐 | 中 |

#### 局限

- 对话场景和真实平台推荐不同；
- 用户样本和对话标注有限；
- 缺少播放、完播和长期留存反馈；
- 不能训练工业级排序系统。

**结论**：ReDial 是研究 LLM 对话式电影推荐的关键数据集。

---

## 7. 可用于架构迁移的非长视频推荐数据集

这些数据集不是电影 / 电视剧数据，但可以用来训练或预训练推荐模型架构，再迁移到长视频场景。

### 7.1 MIND

- **类型**：新闻推荐数据；
- **主要信号**：用户点击、新闻内容、时间戳；
- **官网**：[MIND](https://msnews.github.io/)

#### 可训练模型

- 双塔召回；
- 序列推荐；
- 内容推荐；
- 多任务排序；
- 新闻文本 embedding。

#### 局限

- 领域是新闻，不是长视频；
- 新闻消费是短周期行为，电影 / 剧集是长周期行为；
- 用户偏好模式不同。

**结论**：适合做架构预训练，不能直接代表长视频推荐。

---

### 7.2 Yoochoose / RetailRocket / Diginetica

- **类型**：电商 session 数据；
- **主要信号**：用户点击序列、购买行为、时间戳。

#### 可训练模型

- session-based recommendation；
- GRU4Rec；
- SASRec / BERT4Rec；
- 粗排和重排的架构实验。

#### 局限

- 电商 item 生命周期和电影 / 剧集完全不同；
- 缺少播放时长和完播概念；
- session 长度短，长视频观看周期更长。

**结论**：可用于序列推荐和重排架构研究，但领域迁移成本高。

---

### 7.3 Open Bandit Dataset

- **类型**：带 logging policy 的 bandit 数据；
- **主要信号**：动作、奖励、位置、曝光策略。

#### 可训练模型

- contextual bandit；
- off-policy evaluation；
- 位置偏差建模；
- 探索与利用。

#### 局限

- 不是长视频数据；
- 奖励语义与观看满意度不同。

**结论**：适合研究 bandit 和反事实评估方法，但需要迁移到长视频场景。

---

## 8. 按推荐阶段匹配数据集

### 8.1 召回阶段

| 召回算法 | 推荐数据集 |
|---|---|
| ItemCF / UserCF | MovieLens、Netflix Prize、Amazon Movies and TV |
| Matrix Factorization | MovieLens、Netflix Prize |
| BPR / implicit CF | MovieLens、Amazon Movies and TV |
| 双塔召回 | MovieLens、Amazon、MIND、Trakt |
| 序列召回 | MovieLens、Amazon、Trakt、MyAnimeList |
| 图召回 | MovieLens + IMDb / TMDB / Wikidata |
| 知识图谱召回 | MovieLens + IMDb / TMDB / Wikidata |
| 多模态召回 | MovieLens + MM-IMDb / TMDB / MovieNet |
| 语义 / LLM 召回 | MovieLens + TMDB + ReDial + RAG-VisualRec |

### 8.2 粗排阶段

| 粗排算法 | 可用数据 |
|---|---|
| FM / FFM | MovieLens 隐式反馈、Amazon 数据 |
| 轻量 DNN | MovieLens、Amazon、MIND |
| 双塔粗排 | MovieLens、MIND、Trakt |
| 多目标轻量模型 | MovieLens 的评分 / 标签可做弱代理；MIND 点击数据可做架构迁移 |
| 精排蒸馏 | 无真实公开视频平台日志，只能用模拟数据或迁移数据 |

### 8.3 精排阶段

| 精排算法 | 可用数据 |
|---|---|
| Wide & Deep | MovieLens、Amazon、MIND |
| DeepFM / xDeepFM | MovieLens、Amazon |
| DIN / DIEN / SIM | MovieLens、Amazon、Trakt |
| SASRec / BERT4Rec | MovieLens、Amazon、Trakt、MyAnimeList |
| LightGCN / NGCF | MovieLens |
| KGAT / KGCN | MovieLens + IMDb / TMDB / Wikidata |
| 多任务模型 MMoE / PLE | 公开长视频数据不足；可用 MovieLens 弱标签或 MIND / Amazon 迁移 |
| 多模态精排 | MovieLens + MM-IMDb / TMDB / MovieNet |
| LLM 排序器 | MovieLens + TMDB + ReDial |

### 8.4 重排阶段

| 重排算法 | 可用数据 |
|---|---|
| MMR / DPP 多样性重排 | MovieLens、Amazon、Trakt 构造候选列表 |
| 规则重排 | 任意用户行为数据 |
| Listwise ranking | MovieLens、Amazon、电商 session 数据 |
| LLM reranker | MovieLens + TMDB + ReDial |
| 页面级重排 | 公开数据严重不足，需要平台日志 |
| 封面个性化 | 公开数据不足，可用 contextual bandit 方法做模拟 |

### 8.5 上下文决策阶段

| 上下文类型 | 可用数据 |
|---|---|
| 时间上下文 | MovieLens、Amazon、Trakt 的 timestamp |
| 观看进度 | Trakt、MyAnimeList |
| 设备上下文 | 公开数据基本缺失 |
| 家庭 / 共看 | 公开数据严重缺失 |
| 页面上下文 | 公开数据基本缺失 |
| 探索与利用 | Open Bandit Dataset、模拟环境 |
| 长期价值 / churn | 公开数据基本缺失 |

## 9. 一个可落地的研究数据组合

如果要在公开数据上搭建一个较完整的长视频推荐研究 pipeline，推荐使用：

### 第一层：用户行为

- **MovieLens 25M 或 32M**
- **Amazon Movies and TV**
- 如能合规获取：**Trakt.tv episode-level 数据**

### 第二层：内容元数据

- **IMDb Datasets**
- **TMDB API**
- **Wikidata**

### 第三层：多模态内容

- **MM-IMDb**：海报 + 简介；
- **MovieNet**：视频帧、字幕、剧情；
- **RAG-VisualRec**：视觉 + 文本电影推荐资源。

### 第四层：对话式推荐

- **ReDial**
- 可选：OpenDialKG 等知识图谱对话数据。

### 第五层：实验设置

- 用 MovieLens `links.csv` 关联 IMDb / TMDB；
- 将评分 ≥4 视为隐式正反馈；
- 按时间切分 train / validation / test；
- 负采样时注意曝光偏差；
- 用 HR@K、NDCG@K、Recall@K 做离线评估；
- 用多样性、覆盖率、流行度偏差、serendipity 做 beyond-accuracy 评估；
- 若研究 LLM，可加入自然语言偏好解释和推荐理由评估。

## 10. 公开数据无法覆盖的关键空白

### 10.1 真实曝光日志缺失

公开数据通常只知道“用户评过什么”，不知道“用户看过什么推荐、忽略了什么内容”。因此无法准确训练曝光偏差模型和位置偏差模型。

### 10.2 多行为目标缺失

工业长视频系统需要同时建模：

- 曝光；
- 点击；
- 开始播放；
- 播放时长；
- 完播；
- 下一集续看；
- 收藏；
- 评分；
- 负反馈；
- 弃剧；
- churn。

这些标签在公开数据中几乎都不完整。

### 10.3 页面级推荐日志缺失

真实系统优化的是首页、榜单、详情页和横向列表，而公开数据通常是独立的 user-item 交互。

### 10.4 家庭与共看数据缺失

智能电视和家庭账号场景缺少公开数据，导致 group recommendation 和 co-viewing 研究难以规模化验证。

### 10.5 长期价值标签缺失

公开数据没有订阅续费、取消、长期满意度、内容投资回报等标签，因此很难研究 long-term value optimization。

### 10.6 封面个性化数据缺失

Netflix 的 artwork personalization 依赖线上实验和图像点击反馈，公开数据中几乎没有等价数据。

## 11. 最终建议

### 如果目标是做基础推荐研究

使用：

> **MovieLens + IMDb + TMDB**

可以覆盖：

- 协同过滤；
- 矩阵分解；
- 序列推荐；
- 图推荐；
- 知识图谱推荐；
- 冷启动实验。

### 如果目标是做多模态长视频推荐

使用：

> **MovieLens + MM-IMDb + TMDB + MovieNet**

可以覆盖：

- 海报；
- 剧情；
- 字幕；
- 视频帧；
- 多模态 item embedding；
- 内容相似召回。

### 如果目标是研究剧集级推荐

使用：

> **Trakt + TMDB episode metadata + MyAnimeList**

可以研究：

- episode-level recommendation；
- season-level recommendation；
- 追剧行为；
- 弃剧预测；
- binge watching。

### 如果目标是研究 LLM / 对话式电影推荐

使用：

> **MovieLens + TMDB + ReDial + RAG-VisualRec**

可以研究：

- 自然语言偏好理解；
- 多轮推荐对话；
- 推荐解释；
- LLM reranking；
- 冷启动电影推荐。

### 如果目标是模拟工业系统

需要组合：

> **MovieLens / Trakt 提供行为 + TMDB / IMDb 提供内容 + MIND / Open Bandit 提供架构迁移 + 自建模拟曝光环境**

但要注意：这仍然是模拟系统，不能替代真实流媒体平台日志。

---

## 12. 一句话总结

> **公开数据集可以训练“推荐研究原型”，尤其是协同过滤、序列推荐、图推荐、知识图谱推荐和多模态推荐；但要训练完整的工业级长视频推荐系统，还缺曝光日志、多行为标签、页面上下文、家庭场景、封面反馈和长期价值数据。**
