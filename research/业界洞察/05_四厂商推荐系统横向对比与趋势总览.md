# 四厂商推荐系统横向对比与趋势总览

> 对比对象：火山引擎 / 字节跳动、爱奇艺、Netflix、YouTube / Google  
> 研究范围：公开论文、官方技术博客、公开演讲、官方文档和可追溯的工程社区分享。  
> 证据原则：只描述公开可验证方案，不将论文或博客等同于完整生产系统。

## 1. 总对比表

| 维度 | 火山引擎 / 字节跳动 | 爱奇艺 | Netflix | YouTube / Google |
|---|---|---|---|---|
| 业务形态 | 短视频、信息流、高实时反馈 | 长视频、剧集、综艺、会员与广告混合 | 订阅制流媒体、长视频、全球化影视 | UGC 视频、长短视频、搜索与推荐耦合 |
| 公开架构主线 | 多阶段漏斗 + 实时特征 + 在线训练 | 召回 + 粗排 + 精排 + 多目标融合 | Foundation model + sequence modeling + LLM ranker | Candidate generation + multi-objective ranking + Semantic ID |
| 召回重点 | 多路召回、实时行为、冷启动、Next-User Retrieval | 多路召回、多兴趣召回 | 长期行为序列、foundation model 表征 | embedding retrieval、two-tower、Semantic ID、generative retrieval |
| 粗排证据 | 较明确，且有候选异质性讨论 | 明确，短视频链路公开较多 | 不如中文工业界公开突出，但可能存在轻量排序层 | 公开材料中不常显式强调，但工程上应存在 |
| 精排重点 | 神经网络行为预估，具体结构披露有限 | MMoE、多目标融合、Pareto、PSO | multi-task、FM-Intent、LLM-backed ranker | multi-objective ranking、观看时长、满意度、互动 |
| 序列建模 | 公开证据有限，但实时行为系统强 | 公开证据不足 | 核心，foundation model 的基础 | 用户历史是核心，最新细节披露有限 |
| 实时性 | 最强公开证据：Flink、Kafka、Monolith 在线训练 | 公开证据不足 | 持续预训练和微调，但不等同秒级在线训练 | 公开证据偏算法，不突出实时训练细节 |
| LLM / 生成式推荐 | 冷启动方向有生成式建模证据 | 公开证据不足 | GenRec、generative recommender、artwork LLM post-training | Gemini / LRM、Semantic ID、generative retrieval |
| 长期价值 | 公开证据不足 | 公开证据不足 | 证据最强：长期满意度、proxy reward、delayed feedback | 有长期价值方向，但生产细节公开不足 |
| 评估证据 | online A/B test 出现在论文中 | AUC、完播、互动等业务指标描述 | 离线实验、A/B、长期满意度体系较完整 | 经典论文和大规模系统评估较强，最新细节有限 |
| 公开证据强度 | 中高，偏工程系统 | 中低，存在 2024—2026 断层 | 高 | 高 |

## 2. 架构对比

### 2.1 火山引擎 / 字节跳动

```text
实时行为流
  → Flink / Kafka / Spark / Abase 特征体系
  → 多路召回
  → 过滤
  → 粗排
  → 精排
  → 重排 / 混排
  → A/B 实验
  → 在线训练与反馈回流
```

核心特点：

- 实时特征；
- 在线训练；
- 大规模稀疏 embedding；
- collisionless embedding table；
- 冷启动和粗排专项优化。

### 2.2 爱奇艺

```text
用户 / 视频特征
  → 多路召回
  → 多兴趣召回
  → 粗排
  → 精排
  → 多目标融合
  → 展示
```

核心特点：

- 多兴趣召回；
- 粗排优化；
- MMoE 多目标建模；
- Pareto / PSO 融合参数搜索；
- 通用排序框架；
- 2024—2026 公开证据不足。

### 2.3 Netflix

```text
会员长期交互历史
  → interaction tokenization
  → foundation model / sequence encoder
  → embeddings / fine-tuning / shared weights
  → FM-Intent
  → homepage / search / recommendation / artwork
  → contextual bandit + reward engineering
  → A/B 实验
```

核心特点：

- foundation model；
- 长序列建模；
- sparse attention；
- KV caching；
- intent-aware multi-task；
- 长期满意度；
- generative recommender；
- LLM-backed ranker。

### 2.4 YouTube / Google

```text
用户观看 / 搜索 / 上下文
  → 多路 candidate generation
  → embedding / two-tower / ANN
  → Semantic ID / generative retrieval
  → multi-objective ranking
  → 页面级重排
  → Home / Watch Next / Shorts
```

核心特点：

- 超大规模候选生成；
- multi-objective ranking；
- Semantic ID；
- Gemini 适配；
- 生成式检索；
- 搜索与推荐协同。

## 3. 技术趋势对比

### 趋势 1：多阶段漏斗仍是主流

四家厂商公开证据都支持推荐系统不是单一模型，而是多阶段系统。

主流结构为：

```text
召回
  → 粗排
  → 精排
  → 重排
```

不同厂商对阶段的命名和披露粒度不同：

- 字节跳动公开材料更强调 retrieval、pre-ranking、ranking、re-ranking；
- 爱奇艺公开材料强调召回、粗排、精排；
- YouTube 经典论文强调 candidate generation 和 ranking；
- Netflix 近期更强调 foundation model 与下游任务，而不是传统漏斗的每一层。

因此，趋势不是“漏斗消失”，而是：

> **漏斗仍存在，但每层之间的表征、目标和训练样本正在更深度共享。**

### 趋势 2：排序从单目标走向 multi-objective / long-term value

早期推荐系统常以 CTR 为核心目标。现在公开方案普遍转向：

- 观看概率；
- 观看时长；
- 完播；
- 互动；
- 满意度；
- 留存；
- 长期会员价值；
- 创作者生态；
- 内容安全与公平性。

代表性证据：

- YouTube 2019 年 multi-objective ranking；
- 爱奇艺 MMoE、Pareto、PSO 多目标融合；
- Netflix 长期满意度和 reward engineering；
- 字节跳动实时行为预估和多目标方向，虽然公开细节较少。

### 趋势 3：sequence modeling 成为核心底座

用户历史行为不再只是若干离散特征，而是被组织成序列。

公开证据最强的是 Netflix：

- interaction tokenization；
- transformer；
- sparse attention；
- sliding window sampling；
- KV caching。

YouTube 也长期使用用户历史观看行为，但最新 sequence model 细节公开较少。

爱奇艺在该方向公开不足。

字节跳动有实时行为系统，但完整 sequence model 架构公开有限。

### 趋势 4：Foundation model 化

Netflix 是该方向公开最明确的公司：

- 一个 foundation model 服务多个个性化任务；
- 下游通过 embeddings、fine-tuning、shared weights 复用；
- homepage、search、recommendation、artwork personalization 共享用户与内容理解。

YouTube 的对应方向是：

- Gemini-based Large Recommender Model；
- Semantic ID；
- 视频语义 token 化；
- generative retrieval。

字节跳动和爱奇艺目前没有同等强度的公开证据。

### 趋势 5：Semantic ID 与 generative retrieval 兴起

Google / YouTube 方向最明确：

- item 被表示为 semantic ID；
- 推荐可以变成生成 semantic ID 的任务；
- 与传统 ANN retrieval 形成互补。

Netflix 则将其扩展为 generative recommender：

- 用户行为序列上的 next-event prediction；
- 从 O(1M) 到 O(1B) 参数规模；
- 探索推荐系统自己的 scaling law。

这说明推荐系统正在出现一个新的范式：

> **从“向量检索 + 排序”走向“语义 token + 生成式检索 + 排序”。**

### 趋势 6：实时化与在线学习仍是短视频系统的关键优势

字节跳动公开证据中最突出的是：

- Kafka / Flink 流式特征；
- Monolith online training；
- collisionless embedding table；
- 实时反馈闭环。

这与短视频场景高度匹配：

- 用户兴趣变化快；
- 内容生命周期短；
- 新内容冷启动压力大；
- 实时反馈信号密集。

相比之下：

- Netflix 更强调周期性预训练与持续微调；
- YouTube 公开资料更偏算法和大规模检索；
- 爱奇艺公开证据不足。

### 趋势 7：LLM 进入推荐系统，但不是简单调用通用 LLM

Netflix GenRec 和 YouTube Gemini 方向都表明，LLM 化推荐的关键不是直接问 LLM“推荐什么”，而是解决：

- catalog 约束；
- 推理延迟；
- 用户长期行为序列压缩；
- reward alignment；
- context engineering；
- 语义 token 表示；
- 与现有系统融合。

因此，更准确的技术路线是：

```text
通用 LLM / foundation model
   ↓
领域适配
   ↓
推荐数据后训练
   ↓
catalog-aware 输出
   ↓
低延迟 serving
   ↓
与既有推荐漏斗融合
```

## 4. 四厂商技术定位

### 火山引擎 / 字节跳动

**定位：实时推荐工程与在线学习体系。**

优势公开证据：

- 实时特征链路；
- 在线训练；
- 大规模稀疏 embedding；
- 冷启动；
- 粗排优化。

不确定处：

- LLM 推荐主链路；
- 精排结构；
- 重排机制；
- 长期价值建模。

### 爱奇艺

**定位：长视频多目标推荐与通用排序框架。**

优势公开证据：

- 多兴趣召回；
- 粗排；
- 多目标排序；
- MMoE；
- Pareto / PSO；
- 通用排序框架。

不确定处：

- 2024—2026 最新推荐系统；
- foundation model；
- LLM ranker；
- 序列建模；
- 重排；
- 长期价值。

### Netflix

**定位：个性化 foundation model、长期满意度与 LLM-native recommendation。**

优势公开证据：

- foundation model；
- sequence modeling；
- FM-Intent；
- contextual bandit；
- reward engineering；
- generative recommender；
- GenRec；
- artwork personalization。

不确定处：

- 完整生产模型结构；
- search 个性化细节；
- 某些实验结果的具体线上幅度；
- 是否所有场景均已迁移到 foundation model。

### YouTube / Google

**定位：超大规模多任务排序、Semantic ID 与 Gemini 化推荐。**

优势公开证据：

- candidate generation；
- multi-objective ranking；
- two-tower / embedding retrieval；
- Semantic ID；
- generative retrieval；
- Gemini-based Large Recommender Model。

不确定处：

- 2026 年完整生产架构；
- 负反馈建模细节；
- 长期价值 RL；
- 公平性与创作者生态评估；
- Gemini / LRM 的具体上线范围。

## 5. 共同架构判断

四家厂商虽然业务形态不同，但公开技术方案呈现共同结构：

```text
数据与特征层
  - 用户行为
  - 内容特征
  - 上下文
  - 实时 / 离线特征

召回层
  - 多路召回
  - embedding retrieval
  - sequence retrieval
  - semantic ID / generative retrieval

排序层
  - multi-task
  - multi-objective
  - long-term value
  - LLM ranker

重排层
  - 多样性
  - 页面级组合
  - 业务约束

评估层
  - offline metrics
  - A/B test
  - 长期价值
  - 用户满意度

反馈层
  - 用户行为回流
  - 模型更新
  - 特征更新
  - 实验迭代
```

## 6. 对研究问题的回答

### RQ1：各厂商最新公开方案是什么？

| 厂商 | 公开可确认方案 |
|---|---|
| 火山引擎 / 字节跳动 | 多阶段推荐漏斗、实时特征、Flink / Kafka 链路、Monolith 在线训练、collisionless embedding、冷启动生成式建模 |
| 爱奇艺 | 多路召回、多兴趣召回、粗排、MMoE 多目标精排、Pareto / PSO、通用排序框架、在线知识蒸馏 |
| Netflix | Foundation model、sequence modeling、FM-Intent、contextual bandit、reward engineering、generative recommender、GenRec LLM ranker、artwork personalization |
| YouTube / Google | Candidate generation、multi-objective ranking、two-tower / embedding retrieval、Semantic ID、Gemini / LRM、generative retrieval |

### RQ2：共同趋势与差异是什么？

**共同趋势：**

1. 多阶段推荐漏斗仍是基础；
2. 多目标排序成为标配；
3. 用户长期价值逐渐取代单一短期互动目标；
4. sequence modeling 越来越重要；
5. semantic ID / generative retrieval 开始进入主流；
6. LLM 被用于推荐排序和语义理解，但需解决延迟、catalog 约束和 reward alignment；
7. 系统与算法协同设计成为关键。

**实质差异：**

1. **字节跳动偏实时工程**
   - 在线训练、实时特征、大规模稀疏 embedding 是公开证据最强的部分。

2. **爱奇艺偏传统工业推荐演进**
   - 公开证据集中在多目标排序、粗排和通用排序框架，最新细节不足。

3. **Netflix 偏 foundation model 与长期满意度**
   - 从模型整合走向个性化基础模型，并进一步探索 LLM-native recommendation。

4. **YouTube 偏超大规模检索、多任务排序与 Semantic ID**
   - 传统漏斗成熟，同时向 Gemini / generative retrieval 演进。

### RQ3：2024—2026 年主流演进方向是什么？

主流方向可以概括为六个词：

```text
实时化
序列化
多目标
长期价值
语义 token
生成式推荐
```

更具体地说：

1. **实时化**
   - 实时特征、实时反馈、在线训练。

2. **序列化**
   - 用户历史从离散特征变成行为序列。

3. **多目标**
   - 点击、时长、完播、满意度、留存、生态目标共同优化。

4. **长期价值**
   - 从短期 engagement 转向长期满意度、长期 utility 和用户生命周期价值。

5. **语义 token**
   - item 不再只有 ID embedding，而是被表示为 semantic ID 或行为 token。

6. **生成式推荐**
   - 召回和排序开始引入 generative retrieval、LLM ranker、foundation model。

## 7. 总判断

如果要用一句话概括四家厂商的最新方案：

> **推荐系统正在从“多路召回 + 特征工程 + 多任务精排”的传统工业范式，演进为“实时数据闭环 + 长序列建模 + foundation model + 多目标长期价值优化 + Semantic ID / generative recommendation”的新范式。**

但四家厂商所处阶段不同：

- **字节跳动**：实时化与在线学习体系证据最强；
- **爱奇艺**：传统多目标推荐证据较清楚，但最新公开断层明显；
- **Netflix**：foundation model 与 LLM-native recommendation 公开推进最深；
- **YouTube / Google**：超大规模检索、排序与 Semantic ID / Gemini 化方向最明确。

最终，生成式推荐并不是完全替代传统推荐漏斗，而是与漏斗融合：

```text
传统推荐系统
  + 实时特征与在线学习
  + 长序列建模
  + foundation model
  + Semantic ID
  + LLM ranker
  + 长期价值 reward
= 下一代推荐系统
```
