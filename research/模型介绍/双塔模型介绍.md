# 双塔召回模型怎么训练

双塔模型的核心训练目标是：

> 让**用户向量**和**他真正会看 / 点击 / 喜欢的电影向量**更接近，  
> 让他和**不感兴趣的电影向量**更远。

模型有两个塔：

```text
User Tower:
用户 ID、观看历史、设备、时间、会员状态等
        ↓
   User Embedding

Item Tower:
电影 ID、类型、演员、导演、剧情、海报 embedding 等
        ↓
   Item Embedding

Score = cosine_similarity(user_embedding, item_embedding)
```

训练时用正样本和负样本构造一个对比学习 / 分类问题。

---

## 1. 准备训练样本

一个常见样本是：

```text
user: 用户特征
positive item: 用户真实看过 / 点击 / 完播的电影
negative item: 用户没有看过的电影
```

### 正样本怎么选？

在长视频推荐中，正样本不一定只是“点击”。

可以选择：

- 点击；
- 开始播放；
- 播放超过一定时长；
- 完播；
- 加入片单；
- 评分较高；
- 连续追看；
- 二刷。

但不同正样本代表的意义不同。比如：

| 行为 | 适合作为正样本吗 | 说明 |
|---|---|---|
| 点击 | 可以 | 噪声较大，可能标题党 |
| 播放超过 30 秒 | 较好 | 比点击更能代表真实兴趣 |
| 完播 | 很好 | 强兴趣信号 |
| 加入片单 | 很好 | 明确偏好 |
| 评分 5 分 | 很好 | 显式偏好 |
| 仅仅曝光未看 | 不能作正样本 | 应作未观察或负样本候选 |

工业系统中常用加权标签，例如：

```text
label =
0.2 × 点击
0.3 × 播放超过 50%
0.3 × 完播
0.2 × 收藏或加入片单
```

或者直接用多任务模型分别预测多个行为。

---

## 2. 负样本怎么选？

双塔模型训练效果高度依赖负样本设计。

常见负样本有以下几种。

### 2.1 随机负采样

从电影库中随机抽一部用户没有看过的电影作为负样本。

优点：

- 简单；
- 覆盖广；
- 能让模型区分“用户兴趣”和“随机内容”。

缺点：

- 有些随机负样本太简单，模型容易学会；
- 可能抽到用户其实会看但尚未被曝光的电影。

适合作为基础负样本。

---

### 2.2 Batch 内负采样

这是双塔模型最常用的方法之一。

假设一个 batch 里有 1024 个正样本：

```text
(user_1, movie_A)
(user_2, movie_B)
(user_3, movie_C)
...
```

那么对 `user_1` 来说：

- `movie_A` 是正样本；
- `movie_B`、`movie_C`、`movie_D` 等同 batch 内其他电影可以当负样本。

也就是：

```text
score_matrix = User Embeddings × Item Embeddings^T
```

得到一个 `batch_size × batch_size` 的相似度矩阵。

对角线上是正样本，非对角线是负样本。

优点：

- 训练效率高；
- 一个 batch 内可以产生大量负样本；
- 工业界广泛使用。

缺点：

- batch 内负样本分布不是全局真实分布；
- 可能出现“假负样本”，即 batch 里某部电影其实用户也喜欢；
- 需要修正 popularity bias，因为热门电影更容易被当作负样本。

常见改进：

- log Q correction；
- 去重修正；
- 大 batch 训练；
- cross-batch negative sampling。

---

### 2.3 热门物品负采样

热门电影曝光多，用户没看不代表不喜欢。

例如某用户没看《沙丘 2》，可能只是还没被推荐到，而不是不喜欢。

因此训练时要对热门电影做修正。

常见思路：

- 降低热门负样本权重；
- 使用 log Q correction；
- 对曝光次数多的 item 做概率校正；
- 避免模型过度惩罚热门电影。

---

### 2.4 曝光未点击负样本

使用系统真实曝光过但用户没有点击的电影作为负样本。

优点：

- 更接近线上推荐场景；
- 能刻画用户在真实候选中拒绝了什么。

缺点：

- 会继承旧推荐系统的曝光偏差；
- 冷门内容曝光少，训练不充分；
- 可能导致模型越来越像旧系统。

适合作为补充，不建议只用这一种。

---

### 2.5 Hard Negative Mining

主动选择一些“难负样本”。

例如：

- 和用户兴趣很像但用户没看的电影；
- 同类型、同演员、同导演但用户未观看的电影；
- 双塔模型当前打分很高但真实没有互动的电影。

优点：

- 提升模型区分能力；
- 对精排前的召回质量很有帮助。

缺点：

- 如果难负样本选择错误，会伤害召回；
- 容易把“未曝光”误当“不喜欢”。

常用策略：

```text
先训练基础双塔模型
        ↓
用模型从库中召回一批高分但未观看的电影
        ↓
人工/规则过滤明显假负样本
        ↓
加入训练集作为 hard negatives
        ↓
继续训练
```

---

## 3. 损失函数

### 3.1 Pointwise Loss

把每个 user-item pair 当作二分类问题。

```text
label = 1: 用户看了
label = 0: 用户没看
```

常用：

- Binary Cross Entropy；
- Weighted BCE；
- Regression Loss。

例如：

```text
score = sigmoid(cosine(user_vec, movie_vec))
loss = binary_cross_entropy(score, label)
```

优点：

- 简单；
- 容易加权重。

缺点：

- 不能直接优化排序；
- 对负样本比例敏感。

---

### 3.2 Pairwise Loss

目标不是预测用户是否喜欢，而是：

> 正样本电影应该排在负样本电影前面。

常用：

- BPR Loss；
- Hinge Loss。

BPR 形式：

```text
loss = -log(sigmoid(score_positive - score_negative))
```

优点：

- 更适合 Top-N 推荐；
- 强调相对排序。

缺点：

- 需要构造正负样本对；
- 负样本质量很关键。

---

### 3.3 Listwise / Softmax Loss

这是双塔召回最常用的方法之一。

对一个用户，构造候选列表：

```text
1 个正样本 + N 个负样本
```

模型输出 N+1 个分数，用 softmax 让正样本概率最大：

```text
loss = -log(
    exp(score_positive) /
    (exp(score_positive) + sum(exp(score_negative)))
)
```

如果使用 batch 内负采样，就是：

```text
batch_size × batch_size 的 score matrix
```

对每个用户做 softmax。

优点：

- 直接优化排序；
- 和线上 ANN 召回目标一致；
- 训练稳定。

缺点：

- 对负样本偏差敏感；
- 大 batch 训练成本高。

## 4. 双塔模型典型结构

## 4.1 User Tower

用户塔输入通常包括：

### 用户特征

- 用户 ID；
- 年龄段；
- 性别；
- 地区；
- 语言；
- 会员状态；
- 注册时长；
- 设备类型。

### 行为序列特征

- 最近看过的电影；
- 最近追的剧；
- 最近搜索词；
- 最近点击类型；
- 最近完播内容；
- 负反馈历史。

### 上下文特征

- 请求时间；
- 星期几；
- 节假日；
- 设备；
- 页面来源；
- 是否首页；
- 是否详情页。

处理方式通常是：

```text
用户 ID embedding
+ 电影 ID sequence embedding
+ 类型 embedding
+ 演员 embedding
+ 上下文 embedding
        ↓
Pooling / Attention / DNN
        ↓
User Embedding
```

对于观看历史，可以用：

- mean pooling；
- sum pooling；
- DIN-style attention；
- Transformer；
- SASRec-style sequence encoder。

长视频场景中，观看序列非常重要，因为用户可能正处于追剧状态。

---

## 4.2 Item Tower

电影塔输入通常包括：

### 电影基础特征

- 电影 / 剧集 ID；
- 类型；
- 上映年份；
- 语言；
- 国家；
- 时长；
- 评分；
- 是否热门；
- 是否新片。

### 内容特征

- 导演；
- 演员；
- 编剧；
- IP；
- 关键词；
- 剧情简介 embedding；
- 海报图像 embedding；
- 预告片视频 embedding；
- 字幕或文本 embedding。

### 统计特征

- 最近 7 天点击率；
- 播放完成率；
- 平均观看时长；
- 收藏率；
- 男性/女性偏好分布；
- 年龄段偏好分布。

处理方式：

```text
电影 ID embedding
+ 类型 embedding
+ 演员 embedding
+ 剧情 embedding
+ 海报 embedding
+ 统计特征
        ↓
DNN
        ↓
Item Embedding
```

---

## 4.3 相似度计算

常用相似度函数：

### 内积

```text
score = user_vec · item_vec
```

优点：

- 计算快；
- 适合 ANN。

缺点：

- 向量范数可能影响分数。

### Cosine similarity

```text
score = cosine(user_vec, item_vec)
```

优点：

- 只关注方向，不关注向量长度；
- 常用于语义检索。

工业界常用做法：

```text
先 L2 normalize
再内积
```

这样内积等价于 cosine similarity，并且方便 ANN 索引。

---

## 5. 双塔训练流程

一个典型流程如下。

### Step 1：构造样本

从日志中抽取：

```text
(user, clicked_or_watched_movie)
```

作为正样本。

再采样负样本：

```text
(user, random_movie)
(user, batch 内其他 movie)
(user, hard negative movie)
```

---

### Step 2：编码用户和电影

```text
user_embedding = UserTower(user_features)
item_embedding = ItemTower(item_features)
```

---

### Step 3：计算相似度

```text
score = cosine(user_embedding, item_embedding)
```

如果使用 batch 内负采样：

```text
scores = UserEmbeddingMatrix × ItemEmbeddingMatrix^T
```

---

### Step 4：计算损失

例如 softmax loss：

```text
loss = -log(
    exp(score_positive) /
    sum(exp(score_all_candidates))
)
```

---

### Step 5：反向传播更新两个塔

注意：

- User Tower 和 Item Tower 是分开编码的；
- 训练时可以同时更新；
- 最终相似度计算前，两个塔不能做特征交叉。

这是双塔和精排模型最大的区别。

---

## 6. 双塔模型的约束：两个塔不能提前交互

双塔模型要求：

```text
User Tower 独立输出 user embedding
Item Tower 独立输出 item embedding
最后才计算相似度
```

因此不能用类似：

```text
concat(user_features, item_features) → DNN
```

因为线上召回时，不可能让用户和百万电影逐个拼接后过 DNN。

双塔的优势就是：

```text
电影 embedding 离线预计算
用户 embedding 线上实时计算
然后 ANN 快速检索
```

代价是：

- 无法建模复杂的 user-item 交叉特征；
- 精度不如精排模型；
- 通常只用于召回或粗排。

---

## 7. 训练后怎么上线？

训练完成后，通常分两步。

### 7.1 离线生成电影向量

对所有电影、剧集、纪录片等 item 跑 Item Tower：

```text
movie_id = M001
features = ...
item_vector = ItemTower(features)
```

保存到向量索引：

```text
M001 → [0.12, -0.34, 0.88, ...]
M002 → [0.05, 0.21, -0.77, ...]
M003 → [0.91, -0.12, 0.33, ...]
```

常见索引：

- Faiss；
- HNSW；
- ScaNN；
- Milvus；
- Vespa；
- Elasticsearch vector search。

---

### 7.2 线上生成用户向量

用户请求到来时：

```text
user_features = {
    user_id,
    最近观看,
    设备,
    时间,
    页面,
    会员状态
}

user_vector = UserTower(user_features)
```

然后执行 ANN 检索：

```text
Top-K movies = ANN(user_vector, item_vectors)
```

例如召回 500 或 1000 部电影，再交给粗排 / 精排模型。

---

## 8. 双塔训练中的关键问题

## 8.1 负样本偏差

如果负样本来自随机采样，模型学到的是：

> 用户喜欢的电影 vs 随机电影。

但线上真实任务可能是：

> 从很多看似相关的电影中选出最相关的一部。

所以需要加入 hard negatives。

如果负样本全部来自曝光未点击，模型又会继承旧系统偏差。

工业上常见做法是混合：

```text
随机负采样
+ batch 内负采样
+ 曝光未点击
+ 少量 hard negatives
```

---

## 8.2 热门偏差

热门电影更容易出现在训练数据里，也更容易被 batch 内负采样当成负样本。

如果不校正，模型会学到：

> 热门电影大概率是负样本。

这会导致热门内容被系统性低估。

解决方法：

- log Q correction；
- 按曝光频率修正负样本权重；
- 控制热门样本比例；
- 对 item 进行频次分层采样。

---

## 8.3 冷启动

新电影没有行为数据，但 Item Tower 可以使用：

- 电影 ID；
- 类型；
- 演员；
- 导演；
- 剧情 embedding；
- 海报 embedding；
- 预告片 embedding。

这样即使没有用户行为，也能生成 item embedding。

这也是双塔模型对冷启动友好的原因之一。

---

## 8.4 向量更新

电影特征会变化，例如：

- 热度上升；
- 播放完成率变化；
- 新增演员信息；
- 海报更换；
- 新上线剧集。

因此需要定期更新 item embedding：

- 每小时更新；
- 每天更新；
- 新片实时写入；
- 热门片高频更新；
- 长尾片低频更新。

---

## 8.5 多样性不足

双塔召回容易找出一批相似电影，例如全是悬疑片。

所以召回后通常要：

- 多路召回；
- 类别打散；
- MMR / DPP 重排；
- 加入探索性召回；
- 控制同 IP、同演员、同类型比例。

---

## 9. 简化伪代码

下面是一个 batch 内负采样的双塔训练伪代码。

```python
for user_features, positive_item_features in dataloader:

    # User Tower
    user_vec = user_tower(
        user_id=user_features["user_id"],
        history=user_features["watch_history"],
        context=user_features["context"]
    )

    # Item Tower
    item_vec = item_tower(
        item_id=positive_item_features["item_id"],
        genres=positive_item_features["genres"],
        actors=positive_item_features["actors"],
        plot_embedding=positive_item_features["plot_embedding"]
    )

    # L2 normalize
    user_vec = normalize(user_vec)
    item_vec = normalize(item_vec)

    # Batch 内负采样
    # user_vec: [B, D]
    # item_vec: [B, D]
    scores = torch.matmul(user_vec, item_vec.T)  # [B, B]

    # 对角线是正样本
    labels = torch.arange(batch_size)

    # Softmax loss
    loss = cross_entropy(scores / temperature, labels)

    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

其中：

```text
temperature 控制向量空间分布
```

- temperature 越小，正负样本差异被放大；
- temperature 越大，分布更平滑。

## 10. 训练目标示例

假设用户 U 看过《盗梦空间》。

训练样本：

```text
User: U
Positive item: 盗梦空间
Negative items:
- 浪漫喜剧 A
- 纪录片 B
- 悬疑片 C
- 科幻片 D
```

模型希望：

```text
similarity(U, 盗梦空间) > similarity(U, 其他电影)
```

经过大量样本训练后，用户向量可能表示为：

```text
喜欢：科幻、悬疑、非线性叙事、高概念设定
不喜欢：低龄向、轻松爱情、纯喜剧
```

电影向量则会表示为：

```text
盗梦空间：科幻、悬疑、高概念、梦境、复杂叙事
星际穿越：科幻、太空、亲情、史诗
信条：科幻、悬疑、时间反转、动作
```

线上用户请求时：

```text
user_vec = UserTower(U)
ANN(item_vectors, user_vec)
        ↓
返回：星际穿越、信条、降临、源代码 等
```

## 11. 双塔训练和精排训练的区别

| 维度 | 双塔召回 | 精排模型 |
|---|---|---|
| 样本规模 | 很大，覆盖全库 | 通常来自召回后的候选集 |
| 目标 | 从海量库中找出可能相关内容 | 在小候选集中精确排序 |
| 结构 | 用户和物品分开编码 | 用户和物品特征可以充分交叉 |
| 负样本 | 随机、batch 内、hard negative | 曝光未点击更多 |
| 损失 | 常用 softmax / contrastive loss | 常用 BCE / 多任务 loss |
| 线上方式 | ANN 向量检索 | 逐条打分 |
| 精度 | 较粗但快 | 更准但贵 |

---

## 12. 总结

双塔模型的训练过程可以概括为：

1. 收集用户行为日志；
2. 构造正样本，例如点击、播放、完播、收藏；
3. 构造负样本，例如随机负采样、batch 内负采样、hard negative；
4. User Tower 将用户特征编码为用户向量；
5. Item Tower 将电影特征编码为电影向量；
6. 计算用户向量和电影向量的 cosine similarity；
7. 用 softmax / contrastive / BPR / BCE loss 拉近正样本、推远负样本；
8. 离线计算所有电影 embedding；
9. 建立 ANN 索引；
10. 线上实时计算用户 embedding，并用 ANN 召回 Top-K 候选。

一句话总结：

> **双塔模型训练的本质，是把“用户会不会看这部电影”的问题，转化为“用户向量和电影向量是否接近”的向量对比学习问题。**

# 双塔模型：训练 vs 推理的输入输出

双塔模型有两个“推理场景”：

1. **训练阶段内部的前向传播**：输入样本，输出向量、分数和 loss；
2. **线上真实推理**：输入用户实时特征，输出用户向量，再和提前算好的电影向量做 ANN 检索。

---

## 1. 训练阶段

训练时的目标不是直接输出电影名，而是学习两个塔：

```text
User Features → User Tower → User Embedding
Item Features → Item Tower → Item Embedding
```

然后训练模型让：

```text
用户向量 · 正样本电影向量 > 用户向量 · 负样本电影向量
```

---

## 2. 训练时的一条样本

训练集里的一条样本通常是：

```text
{
  user_features,
  positive_item_features,
  negative_item_features,
  label
}
```

如果是 batch 内负采样，则显式负样本可能不需要提前构造，而是从同一个 batch 中复用其他电影：

```text
{
  user_features,
  positive_item_features
}
```

然后在 batch 内生成负样本对。

---

## 3. User Tower 的训练输入

User Tower 输入的是用户侧特征，例如：

```text
user_id
age_group
gender
region
language
device_type
member_type
recent_watched_items
recent_searched_keywords
favorite_genres
watch_time_context
request_time
```

在长视频推荐中，最重要的是行为序列：

```text
最近看过：星际穿越 → 盗梦空间 → 沙丘 → 信条
最近搜索：诺兰、太空科幻
最近收藏：银翼杀手 2049
```

User Tower 输出：

```text
user_embedding = [
  0.23,
  -0.11,
  0.87,
  0.05,
  ...
]
```

例如维度可能是：

```text
user_embedding: [batch_size, 128]
```

或：

```text
user_embedding: [batch_size, 256]
```

---

## 4. Item Tower 的训练输入

Item Tower 输入的是电影 / 剧集侧特征，例如：

```text
movie_id
title
genres
actors
director
release_year
country
language
duration
plot_embedding
poster_embedding
trailer_embedding
average_rating
popularity
completion_rate
```

例如：

```text
movie_id: M1001
genres: 科幻, 悬疑
actors: 莱昂纳多, ...
director: 诺兰
release_year: 2010
plot_embedding: [...]
poster_embedding: [...]
```

Item Tower 输出：

```text
item_embedding = [
  0.19,
  0.44,
  -0.32,
  0.08,
  ...
]
```

维度通常与 user embedding 相同：

```text
item_embedding: [batch_size, 128]
```

---

## 5. 训练时的中间输出：相似度分数

两个塔分别输出向量后，计算相似度：

```text
score = cosine_similarity(user_embedding, item_embedding)
```

如果使用内积：

```text
score = user_embedding · item_embedding
```

对于一个样本：

```text
(user_i, item_j)
```

输出：

```text
score_ij = 0.87
```

这个分数越高，表示模型认为用户 i 对电影 j 越可能感兴趣。

---

## 6. 训练时的最终输出：loss 和概率

如果用二分类训练：

```text
score = sigmoid(user_vec · item_vec)
loss = BCE(score, label)
```

其中：

```text
label = 1：用户看过 / 点击 / 完播
label = 0：负样本
```

输出可能是：

```text
predicted_click_probability = 0.92
label = 1
```

如果用 softmax / 对比学习：

```text
scores = [
  score(user, 正样本),
  score(user, 负样本1),
  score(user, 负样本2),
  ...
]
```

经过 softmax：

```text
probabilities = softmax(scores)
```

希望正样本概率最大：

```text
positive_sample_probability = 0.78
```

然后计算：

```text
loss = -log(positive_sample_probability)
```

---

## 7. 一个 batch 内的训练示例

假设 batch 里有 4 个用户和 4 部正样本电影：

```text
用户 U1 → 盗梦空间
用户 U2 → 爱在黎明破晓前
用户 U3 → 星际穿越
用户 U4 → 寄生虫
```

两个塔分别输出：

```text
User Embeddings:
U1 → [0.2, 0.8, ...]
U2 → [0.9, -0.1, ...]
U3 → [0.3, 0.7, ...]
U4 → [-0.4, 0.6, ...]

Item Embeddings:
盗梦空间 → [0.2, 0.9, ...]
爱在黎明破晓前 → [0.8, -0.2, ...]
星际穿越 → [0.3, 0.8, ...]
寄生虫 → [-0.3, 0.7, ...]
```

计算相似度矩阵：

```text
            盗梦空间  爱在黎明  星际穿越  寄生虫
U1            0.92     0.10     0.88     0.20
U2            0.12     0.90     0.15     0.30
U3            0.85     0.12     0.94     0.18
U4            0.20     0.35     0.17     0.91
```

对 U1 来说：

```text
正样本：盗梦空间
负样本：爱在黎明破晓前、星际穿越、寄生虫
```

训练目标就是让：

```text
sim(U1, 盗梦空间) > 其他分数
```

同理，对 U2、U3、U4 也让各自对角线上的正样本分数最高。

---

## 8. 训练阶段的输入输出总结

| 部分 | 输入 | 输出 |
|---|---|---|
| User Tower | 用户 ID、历史观看、搜索、设备、时间等 | `user_embedding` |
| Item Tower | 电影 ID、类型、演员、导演、剧情、海报等 | `item_embedding` |
| 相似度层 | `user_embedding`、`item_embedding` | 相似度分数 |
| Loss 层 | 相似度分数、正负样本标签 | 概率 / loss，用于反向传播 |
| 整体训练 | 历史用户行为日志 + 电影特征 | 更新后的 User Tower 和 Item Tower 参数 |

训练时最重要的中间输出是：

```text
user_embedding
item_embedding
```

最重要的最终输出是：

```text
loss
```

训练不是直接输出推荐列表，而是通过 loss 更新模型参数。

# 9. 推理阶段

线上推理时，双塔模型不需要重新遍历所有电影做复杂计算，而是分成两步：

```text
1. 离线：Item Tower 提前计算所有电影向量
2. 在线：User Tower 实时计算用户向量，再做 ANN 检索
```

---

## 10. 离线 Item Tower 推理

输入：

```text
所有电影 / 剧集的 item features
```

例如：

```text
movie_001:
{
  movie_id: "M001",
  title: "盗梦空间",
  genres: ["科幻", "悬疑"],
  actors: [...],
  director: "诺兰",
  release_year: 2010,
  plot_embedding: [...],
  poster_embedding: [...]
}
```

输出：

```text
item_embedding
```

例如：

```text
M001 → [0.12, -0.35, 0.88, ...]
M002 → [0.45, 0.12, -0.67, ...]
M003 → [-0.21, 0.76, 0.33, ...]
```

这些向量会被写入向量索引：

```text
ANN Index:
M001 → vector_001
M002 → vector_002
M003 → vector_003
...
```

离线推理的输入输出：

| 阶段 | 输入 | 输出 |
|---|---|---|
| Item Tower 离线推理 | 每部电影的特征 | 每部电影的 item embedding |
| ANN 索引构建 | 所有 item embedding | 可快速检索的向量索引 |

---

## 11. 在线 User Tower 推理

当用户打开首页时，系统实时构造用户特征：

```text
user_features = {
  user_id: "U100",
  age_group: "25-34",
  region: "Shanghai",
  device: "Smart TV",
  time: "2026-09-15 21:30",
  recent_watched: ["星际穿越", "盗梦空间", "沙丘"],
  recent_searched: ["诺兰", "太空科幻"],
  favorite_genres: ["科幻", "悬疑"],
  is_member: true
}
```

User Tower 输出：

```text
user_embedding = [0.31, -0.18, 0.82, ...]
```

注意：

> 在线 user embedding 是实时计算的，因为用户行为、时间、设备、页面上下文会不断变化。

---

## 12. ANN 检索

输入：

```text
user_embedding
所有 item embedding 的 ANN 索引
```

输出：

```text
Top-K 相似电影
```

例如：

```text
Top 500 候选：
1. 信条
2. 星际穿越
3. 沙丘
4. 盗梦空间
5. 银翼杀手 2049
6. 降临
...
```

同时可能返回相似度分数：

```text
信条：0.94
星际穿越：0.92
沙丘：0.90
盗梦空间：0.89
银翼杀手 2049：0.86
降临：0.85
```

线上推理的输入输出：

| 阶段 | 输入 | 输出 |
|---|---|---|
| User Tower | 实时用户特征 | user embedding |
| ANN 检索 | user embedding + item embedding 索引 | Top-K 候选电影及分数 |
| 召回出口 | Top-K 候选 | 交给粗排 / 精排 / 重排 |

---

## 13. 推理时不会输出什么？

线上双塔召回通常不会直接输出：

```text
最终推荐列表
```

它输出的是：

```text
召回候选集
```

例如：

```text
召回 1000 部电影
        ↓
粗排筛到 300 部
        ↓
精排筛到 50 部
        ↓
重排生成首页推荐列表
        ↓
最终展示 10-20 部
```

所以双塔推理的输出更准确地说是：

> **Top-K candidate items，而不是最终推荐结果。**

---

## 14. 训练和推理输入输出的完整对比

| 维度 | 训练 | 推理 |
|---|---|---|
| 输入 | 历史行为样本：`user_features + item_features + label/negatives` | 在线用户特征 + 离线电影向量索引 |
| User Tower 输出 | `user_embedding` | `user_embedding` |
| Item Tower 输出 | `item_embedding` | 离线预计算的 `item_embedding` |
| 相似度输出 | 正负样本分数矩阵 | 用户与候选电影的相似度 |
| 最终输出 | loss，用于更新模型 | Top-K 候选电影及分数 |
| 是否需要 label | 需要 | 不需要 |
| 是否需要负样本 | 需要，或 batch 内自动生成 | 不显式需要 |
| 是否遍历全库 | 不需要，只看训练样本 | 不精确遍历，用 ANN 近似检索 |
| 是否实时计算 item embedding | 是，与 user embedding 一起训练 | 通常离线预计算 |
| 是否实时计算 user embedding | 是 | 是 |
| 目标 | 学习参数 | 召回候选 |

---

## 15. 一图理解

### 训练

```text
用户特征 ─────→ User Tower ─────→ user_vec
                                      │
                                      │ cosine / dot product
                                      ↓
电影特征 ─────→ Item Tower ─────→ item_vec

正负样本分数 → softmax / BCE / BPR → loss → 更新参数
```

### 线上推理

```text
实时用户特征 → User Tower → user_vec
                              ↓
                              ANN
                              ↑
电影库特征 → Item Tower → item_vecs → 向量索引

ANN 输出 → Top-K 候选电影 → 粗排 / 精排 / 重排
```

---

## 16. 一句话总结

> **训练时，输入是“用户特征 + 正/负电影特征 + 标签”，输出是 loss，用于更新两个塔；推理时，输入是“实时用户特征”和“离线电影向量索引”，输出是用户向量对应的 Top-K 候选电影。**
