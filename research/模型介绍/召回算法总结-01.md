这三类不是完全并列的算法，而更像是推荐系统中的三种技术路线 / 架构层次。

## 1. 协同过滤：ItemCF、UserCF、矩阵分解、ALS

核心思想：**利用用户-物品交互关系做推荐，不依赖内容特征**。

### ItemCF：基于物品的协同过滤

逻辑是：

> 如果很多用户同时喜欢电影 A 和电影 B，那么 A 和 B 被认为相似。你看过 A，就推荐 B。

例子：

- 你看过《盗梦空间》
- 很多用户同时看《盗梦空间》和《星际穿越》
- 系统判断这两部片相似
- 给你推荐《星际穿越》

特点：

- 偏好稳定、可解释性强；
- 适合“片与片相似”的推荐；
- 通常基于共现矩阵、余弦相似度、Jaccard 等方法。

### UserCF：基于用户的协同过滤

逻辑是：

> 找到和你观影口味相似的用户，把他们看过而你没看过的电影推荐给你。

例子：

- 用户 X 和你都看过很多诺兰电影；
- 用户 X 又看了《沙丘 2》；
- 系统把《沙丘 2》推荐给你。

特点：

- 偏好“人以群分”；
- 适合发现相似用户群体的兴趣；
- 用户数量大时计算相似用户开销较高。

### 矩阵分解：MF

矩阵分解是把“用户-电影评分矩阵”分解成两个低维矩阵：

```text
用户-电影矩阵 ≈ 用户矩阵 × 电影矩阵
```

每个用户和每部电影都被表示成一个低维向量，用向量内积预测偏好。

例子：

- 用户向量：`[0.8, -0.2, 0.5, ...]`
- 电影向量：`[0.7, 0.1, 0.4, ...]`
- 内积越大，表示用户越可能喜欢这部电影。

### ALS：交替最小二乘法

ALS 是训练矩阵分解模型的一种优化算法。

它不是一种新的推荐思想，而是求解 MF 的方法：

- 先固定用户向量，更新电影向量；
- 再固定电影向量，更新用户向量；
- 交替迭代直到误差收敛。

特点：

- 适合大规模稀疏数据；
- 常用于显式评分或隐式反馈；
- Spark MLlib 中的 ALS 是工业界经典实现。

### 小结

| 方法 | 推荐逻辑 | 代表场景 |
|---|---|---|
| ItemCF | 找相似电影 | “看过 A 推荐 B” |
| UserCF | 找相似用户 | “和你相似的人也在看” |
| MF | 学用户/电影隐向量 | 评分预测、Top-N 推荐 |
| ALS | 训练 MF 的优化算法 | 大规模稀疏矩阵分解 |

## 2. 隐向量召回：MF、BPR、FM、Neural CF

这一类的核心思想是：

> 把用户和物品映射到同一个低维语义空间，用向量表示兴趣和内容，再通过相似度召回。

注意：**MF 本身既属于协同过滤，也属于隐向量方法**，所以两类有重叠。

### MF：Matrix Factorization

MF 是最基础的隐向量模型，通常用内积计算用户对电影的偏好：

```text
score = user_embedding · item_embedding
```

优点：

- 简单；
- 效果稳定；
- 适合评分数据。

缺点：

- 内积表达能力有限；
- 不擅长自动捕捉复杂非线性关系。

### BPR：Bayesian Personalized Ranking

BPR 主要解决的不是评分预测，而是 **Top-N 排序问题**。

它的优化目标是：

> 用户看过的电影，应该排在没看过的电影前面。

也就是说，BPR 关注的是“正样本是否排在负样本前面”，而不是预测具体评分。

适合：

- 隐式反馈；
- 只有观看、点击、购买等行为；
- 没有明确评分。

### FM：Factorization Machines

FM 的核心是学习**特征之间的交叉关系**。

MF 只处理用户和物品两个 ID，而 FM 可以加入更多特征：

- 用户 ID；
- 电影 ID；
- 类型；
- 演员；
- 导演；
- 时间；
- 设备；
- 地区。

例如：

```text
用户 A × 悬疑片 × 周末晚上
```

FM 可以学习这种组合特征的影响。

优点：

- 适合稀疏特征；
- 能建模特征交叉；
- 工程上容易部署。

### Neural CF：神经协同过滤

Neural CF 用神经网络替代 MF 中的简单内积。

MF 假设用户和电影的关系可以用内积表达，而 Neural CF 用多层神经网络学习更复杂的交互函数：

```text
score = MLP(user_embedding, item_embedding)
```

优点：

- 表达能力更强；
- 能学习非线性偏好关系。

缺点：

- 参数更多；
- 需要更多数据；
- 有时不如调优好的 MF 稳定。

### 小结

| 方法 | 核心特点 | 适用场景 |
|---|---|---|
| MF | 用户/物品向量内积 | 经典评分预测 |
| BPR | 优化正负样本排序 | 隐式反馈 Top-N 推荐 |
| FM | 特征交叉 | 用户、物品、上下文组合建模 |
| Neural CF | 用神经网络学习交互 | 复杂非线性偏好关系 |

## 3. 双塔召回：User Tower + Item Tower + ANN

双塔召回是工业界大规模推荐系统中最常用的架构之一。

### 结构

双塔模型有两个独立塔：

```text
User Tower：
用户 ID、历史观看、设备、时间、会员状态等
        ↓
   User Embedding

Item Tower：
电影 ID、类型、演员、导演、剧情 embedding、海报特征等
        ↓
   Item Embedding
```

然后用相似度计算匹配程度：

```text
score = cosine_similarity(user_embedding, item_embedding)
```

### 为什么叫双塔？

因为用户和物品分别经过一个深度神经网络，各自输出一个向量，像两座塔。

### 为什么工业界常用？

因为它可以解决大规模召回的效率问题。

电影库可能有几十万、几百万个条目。如果每次请求都让用户模型和每个电影模型做完整交互，计算量太大。

双塔的做法是：

1. **离线预计算 item embedding**  
   把所有电影、剧集 embedding 提前算好。

2. **建立 ANN 索引**  
   例如 Faiss、HNSW、ScaNN。

3. **线上实时计算 user embedding**。

4. **在 ANN 中查找与用户向量最相似的 item embedding**。

这样系统不用对全库做暴力计算，可以快速召回 Top-K 候选。

### ANN 是什么？

ANN 是 Approximate Nearest Neighbor，近似最近邻检索。

作用是从百万级 item embedding 中快速找到与用户向量最相似的电影。

常见方法包括：

- Faiss；
- HNSW；
- IVF；
- ScaNN。

### 双塔召回的优缺点

优点：

- 速度快；
- 适合大规模内容库；
- item embedding 可离线更新；
- 方便接入向量数据库。

缺点：

- 用户塔和物品塔在最后相似度计算前不能交互；  
- 因此难以建模复杂的交叉特征；
- 精度通常不如精排模型；
- 常作为召回或粗排，而不是最终精排模型。

## 4. 三类方法的本质区别

### 第一层区别：是否使用隐向量

| 类别 | 是否使用隐向量 | 代表方法 |
|---|---|---|
| 传统协同过滤 | 不一定使用 | ItemCF、UserCF |
| 隐向量模型 | 使用 | MF、BPR、FM、Neural CF |
| 双塔召回 | 使用 | User Tower + Item Tower |

ItemCF、UserCF 可以直接基于共现关系计算相似度，不一定需要 embedding。  
MF、FM、Neural CF、双塔都会学习 embedding。

---

### 第二层区别：推荐对象粒度不同

| 方法 | 主要学习什么 |
|---|---|
| ItemCF | 电影和电影之间的相似关系 |
| UserCF | 用户和用户之间的相似关系 |
| MF | 用户隐向量和电影隐向量 |
| FM | 用户、电影、上下文等特征之间的关系 |
| Neural CF | 用户和电影之间的非线性交互 |
| 双塔 | 用户向量和电影向量 |

---

### 第三层区别：线上服务效率不同

| 方法 | 线上效率 |
|---|---|
| ItemCF | 较高，通常预先构建相似电影表 |
| UserCF | 用户多时开销较大 |
| MF | 可通过向量检索召回 |
| FM / Neural CF | 更常用于排序或小候选集打分 |
| 双塔 + ANN | 最适合大规模实时召回 |

## 5. 一个形象类比

可以把它们理解为三种不同的推荐方式：

### ItemCF：找相似电影

> “你看过《盗梦空间》，喜欢它的人也喜欢《星际穿越》。”

### UserCF：找相似用户

> “和你口味相似的人最近都在看《奥本海默》。”

### MF / 隐向量模型：学口味坐标

> 把你的口味表示成一个向量，把每部电影也表示成一个向量，看谁离你的口味近。

### 双塔召回：工业化的向量匹配器

> 用户塔实时生成你的兴趣向量，物品塔提前算好电影向量，再用 ANN 快速找最匹配的一批电影。

---

## 6. 在长视频推荐中的实际定位

在一个现代流媒体推荐系统中，它们通常会同时存在：

| 模块 | 常用方法 |
|---|---|
| 召回 | ItemCF、双塔、序列召回、图召回、多模态召回 |
| 粗排 | FM、轻量 DNN、双塔粗排 |
| 精排 | DIN、MMoE、PLE、DeepFM、多任务模型 |
| 重排 | MMR、DPP、业务规则、多样性控制 |

所以它们不是互斥关系。

更准确地说：

> **协同过滤是思想基础，隐向量模型是表示学习方法，双塔召回是工业级向量检索架构。**

---

## 7. 一句话总结

- **协同过滤**：根据用户和物品的交互关系找相似用户或相似物品；
- **隐向量召回**：把用户和电影映射成向量，用向量表示偏好；
- **双塔召回**：用两个深度模型分别生成用户向量和电影向量，再用 ANN 快速大规模召回。
