# 演示脚本（约 6 分钟）

> 面向评审的完整演示流程。每步含【操作】与【话术要点】；话术要点标注了对应
> 研究文档依据，可按需展开。故障预案见文末。

## 准备（演示前）

```bash
python scripts/build.py && python scripts/enrich_posters.py   # 已完成可跳过
python scripts/run.py                                          # http://localhost:8000
```

- 用下拉框选**高活跃用户**（如用户 4277，1400+ 部正反馈）——冷启动用户体验差（风险 R3）；
- 确认 LLM 增强开关为开（✨ 紫色）；若 LLM 不可用，徽标会显示"AI 降级"，主链路不受影响。

---

## 1. 开场定位（30 秒）

【话术】
> 这是基于 `research/` 下 30 余份研究洞察构建的长视频推荐系统 Demo。
> 架构采用四家头部厂商（字节/爱奇艺/Netflix/YouTube）公开证据共同支持的四段式
> 漏斗：多路召回 → 粗排 → 精排 → 重排，并叠加了研究文档判断的核心趋势——
> LLM 与传统链路互补而非替代。数据为 MovieLens-1M，评分 ≥4 视为隐式正反馈。

## 2. 首页与多路召回（1 分钟）

【操作】指向"为你推荐"行的来源徽标（序列/双塔/ItemCF/热门）。

【话术】
> 四路召回各有分工：SASRec 序列建模捕捉兴趣演化（评测中最强通道）、双塔做
> 向量召回、ItemCF 利用共现相似、热门兜底冷启动。配额交错融合，跨通道不做
> 分数加权（量纲不一致，研究文档明确的问题）。卡片上的徽标就是各候选的来源。

## 3. 实时回流（1 分钟）——最有冲击力的演示点

【操作】点击"为你推荐"里的任意一部电影 → 页面立即刷新。

【话术】
> 点击即时进入用户状态实时层：这部电影从推荐中消失（已看过滤），并成为
> ItemCF 的最新种子——"因为你看过"行随之变化，主行整体向该片的相似内容偏移。
> 注意主行变化的幅度：三路个性化通道（双塔用户向量/SASRec 序列/精排特征）
> 同时响应了这次点击。这是"实时化"趋势的单机替身：在线更新输入状态、
> 离线训练模型权重——工业对应物是 Kafka/Flink 流式特征与 Monolith 在线训练。

【操作】再演示 ✕ 负反馈按钮（悬停卡片右上角）：电影进入抑制集合，不再出现。

## 4. LLM 增强层（1 分钟）

【操作】等"AI 增强中…"徽标流转为"✓ AI 已增强"（首次约 6~12 秒，缓存后即时）；
指向卡片上的金色推荐理由。

【话术】
> LLM 层做两件事：对 Top-20 重排、为 Top-12 生成推荐理由。两个工程要点：
> 一是**候选集白名单约束**——LLM 只能从候选中重排、输出必须是全排列，
> 否则丢弃，杜绝幻觉（对应 Netflix GenRec 的 catalog-aware scoring）；
> 二是**完全异步可降级**——LLM 挂掉时主链路毫秒级照常服务，评审现场零风险。
> 理由会引用用户真实看过的电影（"延续《X》的…"），这是 LLM 语义理解与
> 传统行为信号互补的直接体现。

## 5. 自然语言查询（45 秒）

【操作】在搜索框输入「来部轻松的科幻片」回车。

【话术】
> LLM 把自然语言解析为结构化偏好（类型映射到片库白名单，防幻觉），再走
> 类型过滤 + 双塔个性化检索——结果既符合"轻松科幻"的语义，又贴合该用户的
> 口味。解析失败时自动退化为热度检索。

## 6. 消融对比 + 评测报告（1.5 分钟）

【操作】点「⚖️ 对比」开关 → 展示同屏对比与指标条；再点「📊 评测报告」新开页面。

【话术】
> 同屏对比是消融实验的直观版：同一用户同一时刻，完整链路 vs 纯热门——
> 类型覆盖、长尾占比的差异一眼可见。评测报告页是完整的漏斗逐级指标：
> 最终链路 HR@10 = 0.198，是纯热门基线的 8.6 倍；长尾占比 46.6% vs 0%
> （多样性是业务需求，不是道德附加项）。
> 特别指出精排一行：DeepFM 与序列信号做了分数级融合，γ 由验证集选择。
> 报告备注里如实记录了一个发现：纯序列排序（0.258）略高于融合排序（0.226）——
> 特征交叉模型在本数据规模无净增量，这正是研究文档引用的 Ferrari Dacrema
> 批评的本地复现；工业精排需要以漏斗曝光分布训练才能超越。我们没有隐藏它。

## 7. 收尾：架构与局限（30 秒）

【话术】
> 局限也如实说明：MovieLens 无曝光日志、无完播/弃剧等多行为标签、无剧集
> 结构与家庭场景——这些是公开数据的已知空白，设计文档的非目标清单里逐条
> 列出，多任务结构已预留接口。完整设计依据见 `docs/` 下的设计草案、评测
> 报告与本脚本，全部结论可溯源到 `research/` 的研究文档。

## 故障预案

| 状况 | 表现 | 处理 |
|---|---|---|
| LLM 不可用/超时 | 徽标显示"AI 降级 · 模型排序" | 无需处理，主链路不受影响；话术转为讲降级设计 |
| 无外网 | 海报回退为渐变占位、LLM/查询降级 | 系统本地化运行；评测报告页本地数据 |
| 点击后列表变化不明显 | 主行重合度高 | 换一部类型差异大的电影点击；或演示 ✕ 负反馈 |
| 用户切换后加载慢 | 首次请求略慢 | 正常现象（在线前向含首次分配），第二次起毫秒级 |
