# 长视频推荐重排阶段：几类算法详解

重排阶段的输入通常是精排模型已经打分过的一批候选内容，例如 50 个电影/剧集。精排模型回答的是：

> “这个用户喜不喜欢这个 item？”

重排回答的是：

> “这一页、这一行、这个位置、这个时刻，应该展示哪些内容，按什么顺序展示，用什么封面和文案展示？”

因此重排不是简单重新排序，而是从单点预估转向**列表级、页面级、业务级和长期价值优化**。

下面逐一介绍。

---

## 1. 规则重排：去重、打散、频控、黑名单

### 1.1 核心思想

规则重排是最基础、最常用、也是工业系统中不可替代的一类方法。它不主要依赖模型，而是用人工规则保证推荐列表满足基本可用性和安全性。

常见规则包括：

| 规则类型 | 作用 | 例子 |
|---|---|---|
| 去重 | 避免重复推荐同一内容 | 用户刚看过《沙丘 2》，短期内不再推荐 |
| 打散 | 避免同类内容连续出现 | 连续 3 个位置不都是悬疑片 |
| 频控 | 控制某类内容出现频率 | 同一 IP、同一演员、同一题材最多出现 N 次 |
| 黑名单 | 过滤不适合内容 | 版权受限、审核问题、下架内容 |
| 位置保护 | 保证某些内容不出现在特定位置 | 儿童内容不出现在深夜成人推荐位 |
| 新鲜度控制 | 避免重复曝光同一推荐理由 | 首页不要连续几天都用同一个榜单标题 |

### 1.2 典型实现方式

假设精排后得到：

```text
候选列表：
1. 悬疑片 A
2. 悬疑片 B
3. 悬疑片 C
4. 喜剧片 D
5. 科幻片 E
```

如果直接展示，会出现三连悬疑。规则重排可以要求：

```text
同类型内容最多连续出现 2 次
```

重排后可能变成：

```text
1. 悬疑片 A
2. 悬疑片 B
3. 喜剧片 D
4. 悬疑片 C
5. 科幻片 E
```

这并没有提升单个 item 的点击率，但提升了列表整体体验。

### 1.3 长视频场景中的典型规则

- 同一剧集不重复出现；
- 同一 IP 不连续出现；
- 同一类型内容连续出现次数限制；
- 同一主演内容限制频率；
- 正在追看的剧集优先放在“继续观看”而不是普通推荐流；
- 成人向、惊悚、恐怖内容避开家庭模式；
- 某些版权内容只对特定地区可见；
- 新片需要保证一定曝光量；
- 付费内容与免费内容的比例控制。

### 1.4 优点

- 可解释性强；
- 上线快；
- 稳定可控；
- 可以直接满足业务、审核、版权和安全要求；
- 能弥补模型无法理解的硬约束。

### 1.5 局限

- 规则过多后维护困难；
- 容易互相冲突；
- 无法自动学习最优排序；
- 可能过度干预模型结果；
- 难以处理复杂的用户偏好权衡。

### 1.6 适用场景

规则重排适合作为所有重排系统的底层保障。即使系统中有高级多样性模型、强化学习模型，通常也仍然保留一层规则。

## 2. 多样性重排：MMR、DPP、Determinantal Point Process

多样性重排的目标是：在保证相关性的同时，避免推荐列表过于相似。

### 2.1 为什么长视频需要多样性

如果用户看过几部悬疑片，精排模型可能会认为：

> “该用户最喜欢悬疑片。”

于是推荐列表可能是：

```text
悬疑片 1
悬疑片 2
悬疑片 3
悬疑片 4
悬疑片 5
```

单看每个 item 都合理，但整页看会很乏味。用户可能想偶尔换换口味。多样性重排要解决的就是这个问题。

---

## 2.2 MMR：Maximal Marginal Relevance

#### 核心思想

MMR 的思想是：选择下一个内容时，不仅要看它相关，还要看它和已经选中的内容是否太相似。

经典公式可以写成：

```text
MMR_score =
λ × relevance(item, user)
-
(1 - λ) × max similarity(item, selected_items)
```

其中：

- `relevance(item, user)`：精排分数或相关性分数；
- `similarity(item, selected_items)`：候选 item 和已选集合的最大相似度；
- `λ`：平衡相关性和多样性的参数。

#### 参数含义

当 `λ` 接近 1：

```text
更重视相关性，列表可能更同质化
```

当 `λ` 接近 0：

```text
更重视多样性，列表可能偏离用户主兴趣
```

#### 示例

假设用户喜欢悬疑片，精排结果如下：

| item | 相关性 | 与已选内容相似度 |
|---|---:|---:|
| 悬疑片 A | 0.95 | 0.20 |
| 悬疑片 B | 0.93 | 0.90 |
| 喜剧片 C | 0.80 | 0.30 |
| 科幻片 D | 0.82 | 0.35 |

如果只看相关性，会选择悬疑片 B。但如果使用 MMR，可能会选择喜剧片 C 或科幻片 D，因为它们虽然相关性略低，但能带来列表差异。

#### 优点

- 简单有效；
- 易于工程实现；
- 可以直接结合精排分数；
- 不需要复杂训练。

#### 局限

- 相似度定义很关键，相似度不准会导致打散错误；
- 每次只能贪心选择一个 item，不一定得到全局最优列表；
- `λ` 需要调参；
- 对复杂业务约束支持较弱。

#### 长视频应用

适合首页横向推荐位、类型频道页、搜索结果页，避免一整页都是同一类型、同一 IP、同一演员或同一风格的内容。

## 2.3 DPP：Determinantal Point Process

### 核心思想

DPP 是一种概率模型，用来描述从一个候选集合中选出子集的概率。它的特点是：

> 如果集合中的 items 越相似，它们同时被选中的概率越低；如果 items 越多样，它们同时被选中的概率越高。

DPP 常用一个核矩阵 `L` 表示 item 之间的关系。对于一个子集 `S`，其被选中的概率与：

```text
det(L_S)
```

成正比。

其中：

- `L_S` 是子集 `S` 中 items 之间的相关性矩阵；
- 行列式越大，通常表示这些 items 更“分散”；
- 行列式越小，表示这些 items 更相似或冗余。

### 直观理解

如果有三个电影：

```text
A：悬疑犯罪片
B：悬疑犯罪片
C：爱情喜剧片
```

A 和 B 很相似，C 与它们差异较大。

在 DPP 中，同时选择 A、B 的概率较低，因为它们高度重复；而选择 A、C 的概率较高，因为它们组合更具多样性。

### DPP 与 MMR 的区别

| 维度 | MMR | DPP |
|---|---|---|
| 优化方式 | 贪心选择 | 子集概率建模 |
| 是否考虑整体列表 | 逐步考虑已选集合 | 可以直接建模整个子集 |
| 多样性表达 | 最大相似度惩罚 | 矩阵行列式 |
| 实现难度 | 较低 | 较高 |
| 业务可解释性 | 更直观 | 更数学化 |
| 工程应用 | 更常见 | 在部分大规模系统中使用 |

### 优点

- 能从集合层面建模多样性；
- 数学性质好；
- 适合优化整个推荐列表，而不只是逐个选择；
- 可以同时考虑相关性和相似性。

### 局限

- 概念较抽象，工程实现和调试难度高于 MMR；
- 核矩阵设计很关键；
- 大规模候选集上计算成本较高；
- 可解释性不如规则和 MMR；
- 需要线上验证多样性是否真的带来长期收益。

### 长视频应用

适合优化首页大列表、推荐流、搜索结果页，避免内容过度集中于热门题材或同一内容簇。

## 3. 业务规则重排：新片保量、运营加权、版权约束

### 3.1 核心思想

业务规则重排不是单纯追求个性化效果，而是让推荐系统满足平台层面的经营目标。

推荐系统通常需要同时服务多个主体：

- 用户；
- 平台；
- 内容方；
- 版权方；
- 运营方；
- 广告或会员业务；
- 长期生态。

因此，重排阶段经常要加入业务约束。

### 3.2 常见业务目标

| 业务目标 | 说明 | 示例 |
|---|---|---|
| 新片保量 | 新上线内容必须获得一定曝光 | 新剧首周需要被足够多用户看到 |
| 运营加权 | 某些内容临时提高权重 | 平台重点采购的独家剧集 |
| 版权约束 | 只推荐当前地区有版权的内容 | 某电影只在部分国家可看 |
| 内容生命周期 | 老片与新片的曝光分配 | 经典片库与新片宣传平衡 |
| 会员转化 | 会员内容与免费内容比例 | 付费内容不能过度压制免费内容 |
| 生态公平 | 小众内容获得一定曝光 | 独立电影、纪录片、非热门语言内容 |
| 内容成本 | 推荐高成本内容需考虑回报 | 高版权费内容需要足够消费 |
| 合规要求 | 避免违规内容或不当组合 | 儿童模式、家庭模式、地区合规 |

### 3.3 实现方式

#### 方式一：硬规则

直接限制结果：

```text
新片 A 必须出现在前 5 位
同一 IP 最多出现 2 次
付费内容占比不超过 30%
```

优点是可控，缺点是可能破坏个性化体验。

#### 方式二：分数加权

在精排分数上增加业务分：

```text
final_score =
α × personalization_score
+ β × business_score
+ γ × freshness_score
+ δ × diversity_score
```

其中每个权重代表一种目标。

这种方式灵活，但权重需要通过实验调整。

#### 方式三：约束优化

把重排写成优化问题：

```text
最大化个性化总收益
约束：
- 新片曝光量满足要求
- 同类型内容不超过限制
- 版权内容满足区域规则
- 付费内容比例在范围内
```

可以通过线性规划、整数规划或贪心算法求解。

#### 方式四：分层保量

先为不同内容池分配位置，例如：

```text
前 3 位：强个性化内容
第 4-6 位：新片保量内容
第 7-9 位：多样性探索内容
第 10-12 位：长尾内容
```

这种方式常用于首页、频道页或搜索页。

### 3.4 优点

- 能直接服务业务目标；
- 可以保证关键内容曝光；
- 可解释性强；
- 便于运营干预；
- 能处理版权、合规、安全等硬约束。

### 3.5 局限

- 业务目标过多时容易冲突；
- 过度加权会伤害用户体验；
- 需要谨慎评估长期影响；
- 短期曝光提升不一定带来长期收益；
- 规则复杂后维护成本高。

### 3.6 长视频应用

典型场景包括：

- 新剧上线首周保曝光；
- 独家内容重点推荐；
- 自制内容提高权重；
- 付费内容与免费内容平衡；
- 小众电影和纪录片获得最低曝光；
- 不同国家、地区、语言的内容分发策略；
- 儿童模式、家庭模式下的内容限制。

## 4. 列表级排序：Listwise Ranking、LambdaMART

### 4.1 核心思想

传统精排模型通常对每个 item 单独打分：

```text
score(user, item A)
score(user, item B)
score(user, item C)
```

然后按分数排序。

但这种做法忽略了一个问题：

> 用户看到的不是单个 item，而是一个列表。

同一个内容在不同列表中的价值可能不同。例如：

```text
列表 1：悬疑片 A，悬疑片 B，悬疑片 C
列表 2：悬疑片 A，喜剧片 D，科幻片 E
```

悬疑片 A 在两个列表中的精排分数可能相同，但用户点击它的概率和后续体验可能不同。

列表级排序的目标就是直接优化整个列表的效果，而不是单个 item 的分数。

---

## 4.2 Listwise Ranking

### 基本思想

Listwise ranking 不把推荐当作多个独立的 item 分类问题，而是把整个候选列表作为输入，直接优化列表排序质量。

输入：

```text
用户 + 页面上下文 + 候选 item 集合
```

输出：

```text
整个列表的排序
```

模型可以考虑：

- item 本身的相关性；
- item 之间的相似性；
- 位置关系；
- 前后内容组合；
- 页面整体多样性；
- 用户的浏览习惯。

### 常见方法

- ListNet；
- ListMLE；
- LambdaRank / LambdaMART；
- Set Transformer；
- Listwise neural ranking；
- Sequence-aware reranking。

### 与 pointwise / pairwise 的区别

| 类型 | 建模单位 | 优化目标 | 特点 |
|---|---|---|---|
| Pointwise | 单个 item | 预测点击/播放概率 | 简单高效，但忽略列表关系 |
| Pairwise | item pair | 判断 A 是否应排在 B 前面 | 比 pointwise 更关注顺序 |
| Listwise | 整个列表 | 优化整个列表指标 | 更接近真实页面体验 |

---

## 4.3 LambdaMART

### 简介

LambdaMART 是经典的 learning to rank 算法，结合了：

- LambdaRank 的梯度调整思想；
- MART / GBDT 决策树模型。

它常用于搜索、推荐和广告排序。

### 核心思想

LambdaMART 优化排序指标，例如 NDCG，而不是单纯优化点击概率。

传统模型可能只问：

> “用户会不会点击这个电影？”

LambdaMART 更关注：

> “正确的电影是否排在靠前的位置？高质量结果是否被排在低质量结果前面？”

### NDCG 是什么

NDCG 是常用排序指标，核心思想是：

> 越相关的结果排在越前面，得分越高。

在长视频推荐中，相关性可以是：

- 点击；
- 播放；
- 完播；
- 高评分；
- 长时间观看；
- 用户后续收藏。

### Lambda 梯度的作用

LambdaMART 会为不同 pair 计算一个特殊的梯度权重 `lambda`，用于调整交换两个 item 顺序的强度。

直觉上：

- 如果一个高价值内容排在低价值内容后面，模型会强烈调整；
- 如果两个内容价值差距小，调整力度较弱；
- 如果一个 item 本应排在非常靠前的位置，却排在很后面，惩罚更大。

### 优点

- 直接优化排序质量；
- 对位置敏感；
- 适合搜索和榜单类任务；
- 工程成熟，效果稳定；
- 可解释性相对神经网络模型更好。

### 局限

- 传统 LambdaMART 主要基于特征工程，不如深度模型容易吸收 raw feature；
- 对实时序列关系建模能力有限；
- 通常需要明确标注或构造好的排序目标；
- 对复杂页面上下文的表达不如深度列表模型灵活。

### 长视频应用

适合：

- 搜索结果排序；
- 首页推荐列表；
- 类型频道页；
- 榜单排序；
- “为你推荐”横向列表；
- 相似影片列表。

## 5. 上下文重排：Context-aware Ranking

### 5.1 核心思想

上下文重排认为：

> 同一个 item 在不同上下文中的价值不同。

例如，同一部喜剧片：

- 周末白天适合家庭观看；
- 深夜可能不如惊悚片合适；
- 在手机上适合短时长内容；
- 在电视大屏上适合大片；
- 在用户刚看完一部悲剧后，可能适合换轻松内容；
- 在家庭账户下，可能适合合家欢内容。

### 5.2 常见上下文类型

| 上下文类型 | 例子 |
|---|---|
| 时间 | 工作日、周末、节假日、早晨、深夜 |
| 设备 | 手机、平板、电视、投屏、网页 |
| 场景 | 通勤、睡前、家庭共看、独自观看 |
| 页面位置 | 首屏、第二屏、详情页、搜索页 |
| 周边内容 | 前一个 item、当前行、整个页面 |
| 观看状态 | 未看、刚点开、看到一半、追到第三季、弃剧边缘 |
| 用户状态 | 疲劳、探索欲强、只想轻松、想追剧情 |
| 家庭状态 | 单人、情侣、亲子、多人共看 |
| 地区/语言 | 国家、文化、语言偏好 |
| 网络环境 | 弱网、离线下载、高码率 |

### 5.3 实现方式

#### 方式一：特征拼接

把上下文作为特征输入排序模型：

```text
features =
user_features
+ item_features
+ time_features
+ device_features
+ page_features
+ sequence_features
```

这是最基础的实现方式。

#### 方式二：上下文感知打分模型

模型输入不再是单个 user-item，而是：

```text
user + item + context + 已展示内容列表
```

输出：

```text
在当前上下文中展示该 item 的价值
```

例如：

```text
P(play | user, item, time, device, page, previous_items)
```

#### 方式三：页面级模型

模型直接输入整个页面或一行候选：

```text
page = [item1, item2, item3, ...]
```

输出整个页面或整行排序。

这通常可以使用：

- Transformer；
- Set Transformer；
- Sequence model；
- Graph neural network；
- Listwise ranking model。

#### 方式四：场景化模型

为不同场景训练独立模型：

- 首页模型；
- 搜索模型；
- 详情页推荐模型；
- 完结页推荐模型；
- 电视大屏模型；
- 移动端模型。

也可以使用共享底座 + 场景头的多任务结构。

### 5.4 长视频场景中的典型例子

- 深夜更倾向推荐成人向悬疑、惊悚或犯罪片；
- 周末白天更适合家庭片、动画、综艺；
- 电视端更适合高视觉质量电影；
- 手机端更适合短剧集或轻量内容；
- 用户刚看完第一季结局，优先推荐第二季第一集；
- 家庭模式下避免推荐过于暴力或惊悚的内容；
- 用户连续看了多部同类型影片，推荐探索性内容；
- 详情页推荐应与当前内容相关，但首页推荐应更多样。

### 5.5 优点

- 更贴近真实用户场景；
- 能提升长期满意度；
- 可以处理不同设备和页面形态；
- 能结合家庭、时间和观看状态。

### 5.6 局限

- 上下文数据难以获取；
- 家庭账户和共看场景难以识别；
- 特征稀疏；
- 模型复杂度更高；
- 离线评估难以模拟真实页面上下文；
- 需要大量在线实验验证。

---

## 6. 强化学习重排：DQN、Policy Gradient、Bandit-based Re-ranking

### 6.1 核心思想

传统排序通常优化即时目标：

```text
用户现在会不会点击？
会不会播放？
```

强化学习重排优化的是长期累积收益：

```text
这次推荐对用户未来的观看、留存、满意度有什么影响？
```

推荐系统可以被建模成一个序列决策问题：

- 状态：用户历史、当前上下文、已展示内容；
- 动作：选择展示哪个内容、什么顺序、什么封面；
- 奖励：点击、播放、完播、续看、评分、留存；
- 目标：最大化长期累计奖励。

---

## 6.2 Bandit-based Re-ranking

### 基本思想

Bandit 是最常用、最容易上线的强化学习形式。它解决的是：

> 探索与利用的平衡。

也就是：

- 利用：推荐已知用户喜欢的内容；
- 探索：尝试用户可能喜欢但尚未确认的内容。

### 常见方法

| 方法 | 思想 | 特点 |
|---|---|---|
| ε-Greedy | 大多数时候选最优，少数时候随机探索 | 简单但探索效率低 |
| UCB | 选择“期望收益 + 不确定性”最高的选项 | 主动探索不确定 item |
| Thompson Sampling | 从后验分布采样后选择 | 工程效果好，常用 |
| Contextual Bandit | 根据上下文选择动作 | 适合推荐系统 |
| LinUCB | 用线性模型估计上下文收益 | 经典 contextual bandit |
| Neural Bandit | 用神经网络估计收益和不确定性 | 适合复杂特征 |

### Contextual Bandit 示例

系统面对用户：

```text
用户：深夜、电视端、看过两部犯罪剧
候选：
A. 犯罪剧续集
B. 新上线悬疑电影
C. 纪录片
```

模型不只估计哪个点击率高，还考虑：

- 如果推荐 A，短期收益高，但可能继续强化同类型偏好；
- 如果推荐 B，可能发现新兴趣；
- 如果推荐 C，短期点击可能低，但可能提升长期满意度。

### 优点

- 比 DQN 简单稳定；
- 适合实时反馈；
- 常用于新内容、新封面、新文案探索；
- 工程落地成熟。

### 局限

- 通常只优化短期或中期奖励；
- 对长期序列依赖建模有限；
- 奖励设计非常关键；
- 探索过多会伤害用户体验。

---

## 6.3 DQN：Deep Q-Network

### 基本思想

DQN 用神经网络估计每个动作的长期价值：

```text
Q(state, action)
```

在重排中：

- state：用户状态、页面状态、已展示内容；
- action：选择某个 item、改变排序、选择封面；
- reward：点击、播放、完播、留存等；
- Q 值：该动作在当前状态下的长期价值。

DQN 的目标不是最大化当前点击，而是最大化未来累计奖励：

```text
maximize expected future reward
```

### 典型流程

1. 观察当前用户状态和候选集；
2. 对每个可行动作估计 Q 值；
3. 选择 Q 值最高的动作，例如展示某电影；
4. 观察用户反馈，得到 reward；
5. 更新 Q 网络；
6. 继续下一轮推荐。

### 优点

- 能考虑长期价值；
- 能建模序列决策；
- 可以优化留存、满意度等长期目标；
- 适合复杂推荐环境。

### 局限

- 训练不稳定；
- 需要 replay buffer、target network 等技巧；
- 离线数据和线上分布不一致；
- reward 难以设计；
- 延迟奖励很难归因；
- 工程成本高。

### 长视频应用

DQN 类方法理论上适合优化：

- 连续追剧行为；
- 用户长期兴趣；
- 内容疲劳控制；
- 探索新题材；
- 留存和流失风险。

但在工业系统中，通常不会直接把 DQN 作为主排序模型，而是用于小范围策略优化或长期价值建模。

---

## 6.4 Policy Gradient

### 基本思想

Policy Gradient 不估计每个动作的 Q 值，而是直接学习一个策略：

```text
π(action | state)
```

也就是：

> 在给定用户和页面状态下，选择某个展示策略的概率。

模型输出一个动作分布，然后根据实际反馈调整策略。

### 代表方法

- REINFORCE；
- Actor-Critic；
- PPO；
- TRPO；
- A2C / A3C；
- Sequence policy learning。

### 示例

当前状态：

```text
用户连续看了三部悬疑剧
```

策略可以输出：

```text
P(继续推荐悬疑片) = 0.45
P(推荐同导演其他类型片) = 0.25
P(推荐新题材) = 0.20
P(推荐纪录片) = 0.10
```

系统采样一个动作后，根据用户反馈更新策略。

### 优点

- 适合大规模离散和连续动作空间；
- 可以直接优化长期目标；
- 能学习多样化推荐策略；
- 与序列模型结合较自然。

### 局限

- 样本效率低；
- 训练方差大；
- 线上探索风险高；
- 需要可靠的 reward；
- 难以调试和解释。

### 长视频应用

适合优化：

- 长期观看策略；
- 推荐节奏；
- 用户疲劳控制；
- 内容探索策略；
- 首页多样性策略。

---

## 7. LLM Reranker：大模型重排

### 7.1 核心思想

LLM Reranker 用大语言模型对少量候选内容进行更高级的语义理解和排序。

传统模型主要依赖：

- ID embedding；
- 行为统计；
- 类别特征；
- 用户历史；
- 多模态特征。

LLM 可以额外理解：

- 电影剧情；
- 题材氛围；
- 表演风格；
- 导演风格；
- 用户自然语言偏好；
- 推荐理由；
- 内容之间的语义差异。

例如用户输入：

> “我想看一部节奏慢、有社会隐喻、演员表演很强的亚洲电影。”

这类需求用传统标签很难准确匹配，但 LLM 可以理解语义。

### 7.2 常见用法

#### 用法一：Pointwise LLM 打分

对每个候选电影单独提问：

```text
用户偏好：节奏慢、有社会隐喻、演员表演强
候选电影：《寄生虫》
请判断匹配度，输出 0-100 分。
```

优点是简单，缺点是没有直接比较 item 之间的关系。

#### 用法二：Pairwise LLM 比较

每次比较两个候选：

```text
根据用户偏好，判断电影 A 和电影 B 哪个更适合？
```

优点是排序效果通常比 pointwise 更好，缺点是候选多时调用次数多、成本高。

#### 用法三：Listwise LLM 排序

把所有候选一次性给 LLM：

```text
候选：
1. 《电影 A》
2. 《电影 B》
3. 《电影 C》
4. 《电影 D》

用户偏好：……

请输出从最推荐到最不推荐的顺序。
```

优点是效率较高，缺点是受上下文长度、注意力和输出稳定性影响。

#### 用法四：解释生成

让 LLM 生成推荐理由：

```text
为什么给该用户推荐这部电影？
```

例如：

> “因为你近期看了多部社会派犯罪片，这部作品延续了类似主题，但叙事节奏更慢，更强调人物关系。”

### 7.3 优点

- 语义理解能力强；
- 可以理解自然语言偏好；
- 对冷启动内容友好；
- 可以生成解释；
- 能融合剧情、风格、情绪等复杂信息；
- 适合小候选集高级重排。

### 7.4 局限

- 推理成本高；
- 延迟高；
- 不适合全库召回和大规模粗排；
- 可能产生幻觉，比如推荐不存在的电影；
- 可能无法精确识别版权库中的 item ID；
- 稳定性不如传统排序模型；
- 需要强约束和后校验；
- 用户隐私和 prompt 安全需要处理。

### 7.5 工程上的合理用法

LLM Reranker 通常不适合直接处理上万候选，而适合：

- 精排后前 20-50 个候选；
- 搜索意图理解；
- 对话式推荐；
- 少量候选的语义比较；
- 推荐解释生成；
- 冷启动新片内容理解；
- 海报或文案候选选择。

更现实的架构是：

```text
传统召回 → 粗排 → 深度精排 → 规则/多样性重排 → LLM 小范围高级重排
```

## 8. 封面/文案个性化：Contextual Bandit 与多臂老虎机

### 8.1 核心思想

同一个电影，不同封面、标题或推荐理由对用户的吸引力可能完全不同。

例如同一部电影可以有不同封面：

- 封面 A：主角特写；
- 封面 B：动作场面；
- 封面 C：浪漫场景；
- 封面 D：恐怖氛围；
- 封面 E：导演风格强烈的艺术构图。

不同用户可能被不同封面吸引。Netflix 的 artwork personalization 就是这类思想的代表。

### 8.2 问题建模

对每个内容，平台有多个可选封面：

```text
电影 X：
- 封面 A
- 封面 B
- 封面 C
```

对每个用户，系统要选择一个封面。

这里可以用 Contextual Bandit 建模：

- 状态：用户特征、设备、时间、上下文；
- 动作：选择哪个封面；
- 奖励：点击、播放、完播、满意度。

目标是学习：

```text
P(click | user, item, artwork)
```

而不是只学习：

```text
P(click | user, item)
```

### 8.3 多臂老虎机视角

可以把每个封面看成一个 arm：

```text
arm 1：封面 A
arm 2：封面 B
arm 3：封面 C
```

系统尝试不同封面，观察反馈，逐渐学习哪个封面更适合哪类用户。

但推荐系统不是简单多臂老虎机，因为不同用户、不同场景下最优 arm 不同，因此更适合 Contextual Bandit。

### 8.4 Contextual Bandit 的优势

相比静态 A/B test，Contextual Bandit 可以：

- 根据用户特征选择封面；
- 根据设备选择封面；
- 根据时间选择封面；
- 根据内容类型选择封面；
- 持续探索新封面；
- 自动停止低效封面。

### 8.5 封面个性化的关键问题

封面个性化不只是提升点击率，还要避免误导。

如果一个封面突出浪漫，但电影实际是恐怖片，短期点击可能提升，但用户满意度会下降。因此奖励不能只包括点击，还应包括：

- 开始播放；
- 播放时长；
- 完播率；
- 退出率；
- 负反馈；
- 用户评分；
- 后续留存。

### 8.6 文案个性化

除了封面，还可以个性化：

- 标题；
- 副标题；
- 推荐理由；
- 榜单名称；
- 标签；
- 播放按钮文案；
- 推荐卡片描述。

例如：

```text
文案 A：本季最强悬疑神剧
文案 B：根据真实事件改编
文案 C：适合周末一口气追完
文案 D：导演代表作
```

不同文案会吸不同用户。

### 8.7 优点

- 直接影响用户第一眼决策；
- 可以在不改变推荐 item 的情况下提升体验；
- 适合 A/B test 和 bandit 快速迭代；
- 能捕捉视觉偏好和情绪偏好。

### 8.8 局限

- 可能造成标题党；
- 短期点击提升可能伤害长期信任；
- 封面与内容不符会降低满意度；
- 需要大量素材和实验；
- 家庭账户下封面选择更复杂；
- 版权和品牌规范可能限制素材使用。

## 9. 各类重排算法的对比总结

| 算法族 | 主要优化目标 | 优点 | 局限 | 长视频典型应用 |
|---|---|---|---|---|
| 规则重排 | 安全、可用性、基础体验 | 稳定、可控、可解释 | 规则难维护，效果有限 | 去重、打散、频控、黑名单 |
| MMR | 相关性 + 多样性 | 简单、易实现、效果好 | 相似度定义关键，贪心不保证全局最优 | 首页类型打散、搜索结果多样化 |
| DPP | 列表整体多样性 | 集合级建模，数学性质好 | 复杂、可解释性弱 | 大列表、推荐流、搜索页 |
| 业务规则重排 | 平台经营目标 | 直接服务业务 | 可能伤害用户体验 | 新片保量、运营加权、版权约束 |
| Listwise Ranking | 整个列表质量 | 直接优化排序结果 | 数据和模型要求更高 | 首页列表、榜单、搜索排序 |
| LambdaMART | 排序指标如 NDCG | 成熟稳定，位置敏感 | 特征工程要求高 | 搜索排序、推荐列表排序 |
| Context-aware Ranking | 场景适配性 | 贴近真实使用场景 | 上下文获取难 | 时间、设备、页面、家庭场景 |
| Bandit Re-ranking | 探索与利用 | 稳定易上线 | 长期建模有限 | 新内容、新封面、新文案探索 |
| DQN / Policy Gradient | 长期价值 | 可优化长期收益 | 训练难、成本高、风险高 | 留存、疲劳、长期观看策略 |
| LLM Reranker | 语义理解与解释 | 能理解复杂偏好 | 延迟高、成本高、可能幻觉 | 小候选集高级重排、推荐理由 |
| 封面/文案个性化 | 展示层点击与体验 | 直接影响第一眼决策 | 可能误导用户 | Netflix artwork personalization 类场景 |

---

## 10. 实际系统中如何组合

工业系统通常不会只用一种重排算法，而是分层组合：

```text
精排结果
    ↓
业务规则过滤
    ↓
多样性重排：MMR / DPP
    ↓
列表级排序：Listwise / LambdaMART
    ↓
上下文重排：时间、设备、页面、家庭
    ↓
强化学习或 Bandit：长期价值与探索
    ↓
LLM 小范围重排或解释生成
    ↓
封面/文案个性化
```

更现实的组合方式是：

1. **先用规则保证安全与合规**；
2. **再用 MMR / DPP 提升列表多样性**；
3. **用 Listwise 模型优化整体排序**；
4. **用上下文模型适配场景**；
5. **用 Bandit 探索新内容和新素材**；
6. **在少量候选上使用 LLM 提升语义理解**；
7. **最后进行封面和文案个性化**。

---

## 11. 一句话总结

> **规则重排保证不出错，多样性重排保证不单调，业务重排保证平台目标，列表级排序保证整体效果，上下文重排保证合时宜，强化学习优化长期价值，LLM 重排增强语义理解，封面文案个性化优化用户第一眼决策。**
