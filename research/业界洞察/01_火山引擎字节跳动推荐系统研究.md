# 火山引擎 / 字节跳动推荐系统研究文档

> 研究问题：
> 1. 抖音 / TikTok / 火山引擎推荐系统的公开架构与关键算法有哪些？
> 2. 召回、粗排、精排、重排、实时特征、多目标、序列建模、LLM / 生成式推荐、长期价值与实验平台如何组合？
> 3. 从公开证据看，2024—2026 年其最新方案与技术演进是什么？

## 摘要

从公开证据看，字节跳动 / 抖音 / 火山引擎推荐系统的技术主线可以概括为：

> **多阶段推荐漏斗 + 实时数据链路 + 在线训练 + 大规模稀疏 embedding + 冷启动与粗排专项优化。**

与其他厂商相比，字节跳动公开披露的重点不在“完整推荐算法体系”，而在：

1. 推荐系统的实时性；
2. 大规模 embedding 表的存储、更新和冲突处理；
3. 流式特征生产链路；
4. 在线训练与反馈闭环；
5. 冷启动、粗排等具体子问题。

因此，公开证据中最具代表性的不是某个单点排序模型，而是 **Monolith** 及其背后的实时推荐系统实践。

## 1. 公开架构主线

根据公开论文与工程资料，抖音 / TikTok / 字节跳动推荐系统可以概括为：

```text
用户行为日志
   ↓
实时 / 离线特征生产
Kafka / BMQ / Flink / Spark / Hive / HDFS / Abase / RPC
   ↓
多路召回 Retrieval
   ↓
过滤 Filtering
   ↓
粗排 Pre-ranking
   ↓
精排 Ranking
   ↓
重排 / 混排 Re-ranking / Blending
   ↓
线上 A/B 实验
   ↓
反馈回流与模型更新
```

需要强调：这是根据不同公开材料拼合出的公开技术图景，不等于完整生产系统。

## 2. 关键技术模块

### 2.1 Monolith：实时推荐系统与 collisionless embeddings

字节跳动公开论文 **《Monolith: Real Time Recommendation System With Collisionless Embeddings》** 是其推荐系统公开资料中的关键证据。

论文核心主题包括：

1. **Real-time recommendation**
   - 系统强调实时反馈和在线更新；
   - 用户行为变化可以较快进入模型训练链路。

2. **Collisionless embedding table**
   - 传统 embedding hashing 可能造成不同 ID 映射到同一个槽位，带来冲突；
   - Monolith 强调使用 collisionless embedding table，保证稀疏特征表示的唯一性和稳定性。

3. **Online training**
   - 不是单纯离线训练后定期上线；
   - 系统支持在线训练与滚动更新。

4. **大规模稀疏特征**
   - 用户 ID、内容 ID、行为序列、上下文特征形成超大规模稀疏 embedding；
   - Monolith 关注如何在大规模稀疏条件下高效训练和 serving。

5. **工程容错与可用性**
   - 在线训练要求系统具备故障恢复、训练一致性、服务稳定性等能力。

因此，Monolith 揭示的是字节跳动推荐系统在工程层的核心竞争力：

> **实时反馈 + 大规模稀疏建模 + 在线训练 + 低延迟服务。**

### 2.2 实时特征链路：Flink、Kafka、Spark、Abase

火山引擎开发者社区文章《5 年迭代 5 次，抖音基于 Flink 的推荐系统演进历程》提供了较明确的特征工程证据。

文中提到的组件包括：

- Kafka
- BMQ
- Hive
- HDFS
- Abase
- RPC
- Spark
- Flink
- Flink SQL
- 有状态流式计算

这说明抖音推荐特征生产不是单纯离线批处理，而是：

```text
日志采集
   ↓
流式 / 离线特征计算
   ↓
特征存储
   ↓
在线特征服务
   ↓
模型训练与推理
   ↓
反馈回流
```

其中，Flink 承担实时流式计算和状态维护，Spark / Hive / HDFS 承担离线批处理，Abase / RPC 等组件参与在线特征服务。

这与短视频场景高度相关：用户兴趣和内容热度变化快，系统必须让实时行为尽快进入模型。

### 2.3 冷启动：Next-User Retrieval

2025 年论文 **《Next-User Retrieval: Enhancing Cold-Start Recommendations via Large Language Models》** 直接指向 Douyin 推荐系统的冷启动问题。

公开摘要显示，该方案的核心思想是：

- 受 lookalike algorithms 启发；
- 通过 generative next-user modeling 缓解冷启动；
- 面向新用户或新内容等行为稀疏场景；
- 论文包含 offline experiments 和 online A/B tests。

这说明字节跳动 / 抖音在冷启动方向已经公开探索：

> **用生成式建模和相似用户扩展，缓解新用户 / 新内容信号不足的问题。**

但该论文属于局部模块研究，不能说明整个抖音推荐系统已经全面转向 LLM 推荐架构。

### 2.4 粗排：Pre-ranking 与候选异质性

公开研究还出现针对推荐系统 pre-ranking 的讨论，核心问题是：

- 大规模推荐系统通常包含 retrieval、pre-ranking、ranking、re-ranking；
- 粗排需要从大量召回候选中快速筛选；
- 候选来源不同，分布可能高度异质；
- 如果用一个统一粗排模型处理所有候选，可能低估或高估某些来源的候选。

公开证据显示，粗排正在从简单轻量模型演化为：

- 与精排目标更一致；
- 候选分布感知；
- 支持更大候选规模；
- 兼顾延迟和效果。

这符合工业推荐系统的一般趋势：**粗排越来越像“压缩版精排”**。

## 3. 技术演进判断

### 阶段 1：离线特征 + 批量训练

早期推荐系统通常依赖：

- 离线日志；
- 批量样本拼接；
- 离线训练；
- 定期发布模型。

### 阶段 2：实时特征 + 流式计算

随着短视频反馈周期缩短，系统开始强调：

- Kafka / Flink 流式处理；
- 实时特征更新；
- 用户短期兴趣快速捕捉。

### 阶段 3：在线训练与实时更新

Monolith 的公开意义在于：

- 在线训练成为核心工程能力；
- embedding 表可以动态更新；
- 模型能更快响应用户兴趣和内容热度变化。

### 阶段 4：冷启动与生成式建模

2025 年 Next-User Retrieval 表明：

- 生成式建模开始进入冷启动子问题；
- LLM 或 generative modeling 被用于扩展用户 / 内容表征；
- 但公开证据尚未证明整个推荐主链路已经 LLM 化。

## 4. 模块级证据表

| 模块 | 公开证据强度 | 主要发现 |
|---|---:|---|
| 多阶段漏斗 | 中高 | retrieval、filtering、pre-ranking、ranking、re-ranking 在公开资料中反复出现 |
| 实时特征 | 高 | Flink、Kafka、Spark、Hive、Abase、RPC 等组件证据明确 |
| 在线训练 | 高 | Monolith 论文明确讨论 online training |
| 大规模 embedding | 高 | collisionless embedding、expirable embeddings、frequency filtering 等被公开讨论 |
| 冷启动 | 中高 | Next-User Retrieval 论文包含 offline experiments 与 online A/B tests |
| 粗排 | 中高 | 公开论文讨论 pre-ranking 与候选异质性 |
| 精排 | 中 | 抖音公开说明推荐系统通过神经网络预估用户行为，但精排结构细节披露有限 |
| 重排 | 低 | 公开链路中存在该阶段，但具体机制披露不足 |
| LLM / 生成式推荐 | 低中 | 有冷启动方向的生成式建模证据，但缺少完整生产主链路证据 |

| 实验平台 | 低中 | 有 online A/B tests 证据，但平台架构细节公开不足 |

## 5. 关键局限

1. **公开资料远小于真实系统。** 抖音 / TikTok 的生产推荐系统规模极大，公开论文只披露局部模块。
2. **不同证据层次不能直接拼接。** Monolith 是训练与 embedding 系统，Flink 文章是特征链路，Next-User Retrieval 是冷启动研究，它们不能简单等同于同一个完整生产架构。
3. **LLM 推荐证据不足。** 招聘信息或媒体报道中出现“推荐大模型”“多模态大模型”等表述，但不能作为生产系统架构的证据。
4. **长期价值与实验平台细节公开不足。** 虽然有 A/B test 证据，但完整实验平台、长期价值建模、用户留存优化方案尚未系统公开。

## 6. 结论

火山引擎 / 字节跳动推荐系统的核心竞争力是：

> **实时化、系统化、在线学习和大规模稀疏特征处理。**

其技术路线可概括为：

```text
实时行为流
  → 实时特征
  → 在线训练
  → 大规模稀疏 embedding
  → 多阶段推荐漏斗
  → A/B 实验反馈
```

它和 Netflix、YouTube 的差异在于：

- Netflix 公开重点更偏 foundation model、长期满意度、LLM ranker；
- YouTube 公开重点更偏大规模排序、Semantic ID、Gemini 适配；
- 字节跳动公开重点更偏实时工程系统、在线训练和特征链路。
