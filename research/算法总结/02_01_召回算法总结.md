# 长视频推荐召回算法逐一详解

这些算法都属于推荐系统中的**召回 / 候选生成阶段**：目标不是精确判断用户最喜欢哪一部电影，而是从百万级片库中快速找出“值得进入后续排序的候选集合”。它们解决的是不同类型的偏好信号问题。

---

## 1. 协同过滤召回：ItemCF、UserCF、矩阵分解、ALS

### 1.1 ItemCF：基于物品相似度的召回

**核心思想**：如果很多用户同时看过电影 A 和电影 B，那么 A 和 B 相似。当用户看过 A 时，系统推荐与 A 最相似的电影。

**例子**：

- 大量用户同时看过《盗梦空间》和《星际穿越》；
- 用户刚看完《盗梦空间》；
- ItemCF 会推荐《星际穿越》《信条》《源代码》等相似影片。

### 计算方式

ItemCF 通常会计算电影之间的相似度：

\[
sim(i,j)=\frac{|U_i \cap U_j|}{\sqrt{|U_i| \times |U_j|}}
\]

其中：

- \(U_i\) 是看过电影 \(i\) 的用户集合；
- \(U_j\) 是看过电影 \(j\) 的用户集合；
- 分子表示两部电影共同受众规模；
- 分母用于惩罚热门电影，避免热门片和所有电影都“相似”。

### 召回过程

1. 离线计算所有电影之间的相似度矩阵；
2. 找到用户最近看过或高互动的电影；
3. 取这些电影的相似电影；
4. 聚合打分；
5. 去重后输出 Top-K 候选。

### 优点

- 简单稳定；
- 可解释性强；
- 对热门、经典电影效果好；
- 容易大规模离线计算；
- 不需要复杂内容理解。

### 缺点

- 冷启动弱：新电影没有交互数据时无法计算相似度；
- 偏向热门内容；
- 只能捕捉“共现相似”，不能理解语义相似；
- 用户兴趣变化较慢，难以捕捉短期意图。

### 长视频适用性

ItemCF 很适合电影推荐，因为电影之间确实存在强共现关系。例如：

- 同导演；
- 同类型；
- 同 IP；
- 同受众群。

但对于新上线电影、小众电影、刚上线剧集，ItemCF 表现会明显受限。

---

### 1.2 UserCF：基于用户相似度的召回

**核心思想**：找到和目标用户兴趣相似的其他用户，推荐这些相似用户看过而目标用户还没看过的电影。

**例子**：

- 用户 A 喜欢科幻悬疑片；
- 用户 B 也喜欢科幻悬疑片，并且看过《降临》；
- 用户 A 还没看过《降临》；
- UserCF 会推荐《降临》给用户 A。

### 计算方式

先计算用户相似度，例如：

\[
sim(u,v)=\frac{|I_u \cap I_v|}{\sqrt{|I_u| \times |I_v|}}
\]

其中：

- \(I_u\) 是用户 \(u\) 看过的电影集合；
- \(I_v\) 是用户 \(v\) 看过的电影集合。

然后根据相似用户的历史行为生成推荐。

### 优点

- 能发现“同类人群”偏好；
- 适合兴趣社群明显的场景；
- 对非个性化内容、群体趋势捕捉较好。

### 缺点

- 用户数量通常远大于电影数量，用户相似度矩阵更大；
- 用户兴趣不稳定；
- 隐私敏感；
- 在流媒体场景中不如 ItemCF 高效；
- 容易受家庭账户、共看行为干扰。

### 长视频适用性

UserCF 在电影推荐中历史上很重要，但现代工业系统使用较少，更多是作为离线实验或特定场景召回。因为长视频平台更常用物品相似、向量召回和多路召回。

---

### 1.3 矩阵分解：Matrix Factorization

**核心思想**：把用户-电影评分矩阵分解成用户向量和电影向量，用向量内积预测用户对电影的偏好。

假设评分矩阵为 \(R\)，矩阵分解希望找到：

\[
R \approx U \times V^T
\]

其中：

- \(U\) 是用户隐向量矩阵；
- \(V\) 是电影隐向量矩阵；
- 每个用户和电影都被表示成低维向量；
- 用户向量与电影向量的内积代表预测评分。

### 例子

某个用户向量可能隐含表示：

- 喜欢科幻；
- 喜欢复杂叙事；
- 喜欢视觉大片；
- 不喜欢恐怖片。

某部电影向量可能表示：

- 科幻；
- 太空题材；
- 情感浓度高；
- 节奏较慢。

如果两个向量方向接近，系统就认为用户可能喜欢这部电影。

### 优点

- 能学习潜在偏好；
- 比显式相似度更灵活；
- 可以泛化到没有直接共现的用户-电影组合；
- 是 Netflix Prize 时代的核心技术。

### 缺点

- 原始 MF 主要面向显式评分；
- 对隐式观看行为的建模不足；
- 难以加入上下文特征；
- 冷启动弱；
- 内积表达能力有限。

---

### 1.4 ALS：交替最小二乘法

**ALS** 是训练矩阵分解模型的常用优化方法，尤其适合隐式反馈和大规模并行计算。

**核心思想**：

1. 固定用户向量，优化电影向量；
2. 固定电影向量，优化用户向量；
3. 反复交替，直到收敛。

在隐式反馈场景中，ALS 会区分“用户看过”和“用户没看过”的可信度。没看过不等于不喜欢，可能只是没有被曝光。

### 优点

- 适合大规模分布式训练；
- 稳定；
- 常用于工业推荐；
- 能处理百万用户、百万物品的矩阵。

### 缺点

- 特征表达能力有限；
- 难以直接建模序列；
- 对实时兴趣变化响应慢；
- 需要精心设计正则和置信度。

### 长视频适用性

ALS 适合作为基础召回通道，尤其是“基于长期观看偏好”的召回。它对经典电影和有稳定偏好的用户效果较好，但难以处理新片、新用户和短期情境。

---

## 2. 隐向量召回：MF、BPR、FM、Neural CF

这一类方法的核心都是：**把用户和影片映射到同一个隐向量空间，然后用向量距离或相似度召回**。

---

### 2.1 MF 用于隐向量召回

MF 不仅可以做评分预测，也可以做召回：

1. 为每个用户学习一个向量；
2. 为每部电影学习一个向量；
3. 用户向量与电影向量点积越高，表示越可能喜欢；
4. 对所有电影打分；
5. 取 Top-K。

优点是简单、稳定、容易部署。缺点是表达能力有限，只适合线性偏好关系。

---

### 2.2 BPR：Bayesian Personalized Ranking

**适用场景**：Top-N 推荐。

**核心思想**：不是预测评分，而是优化“用户更喜欢正样本而不是负样本”。

例如：

- 用户看过了电影 A；
- 没看电影 B；
- 系统希望模型输出：

\[
score(u,A) > score(u,B)
\]

BPR 使用 pairwise loss，更适合“排序”而不是“预测分数”。

### 优点

- 更符合推荐系统的排序目标；
- 比 RMSE 更适合 Top-N 推荐；
- 适合隐式反馈。

### 缺点

- 负样本选择很关键；
- 如果负样本来自未曝光内容，会引入曝光偏差；
- 对长期兴趣和短期兴趣区分较弱。

### 长视频适用性

BPR 适合隐式观看行为，例如“看完、收藏、追剧、完播”为正样本，“未看”为负样本。但长视频场景中的未看行为含义复杂，因此负采样必须谨慎。

---

### 2.3 FM：Factorization Machines

**核心思想**：在特征之间学习低阶交叉关系。

推荐系统中有很多稀疏特征，例如：

- 用户年龄段；
- 设备类型；
- 地区；
- 时间；
- 电影类型；
- 导演；
- 演员；
- IP；
- 语言；
- 是否新片。

FM 可以自动学习特征组合，例如：

- “科幻 + 视觉大片 + 年轻男性用户”；
- “悬疑 + 慢节奏 + 深夜观看”；
- “家庭动画 + 周末 + 电视端”。

### 优点

- 能处理高维稀疏特征；
- 自动特征交叉；
- 训练效率高；
- 适合工业系统；
- 常用于召回和排序。

### 缺点

- 主要是二阶交叉为主；
- 对高阶复杂关系表达能力有限；
- 无法像深度模型一样学习复杂非线性结构。

### 长视频适用性

FM 很适合融合用户、内容、上下文特征，例如：

- 用户画像；
- 电影类型；
- 设备；
- 时间；
- 地区；
- 是否会员；
- 是否新片。

它常作为粗排或轻量精排模型，也可以用于召回打分。

---

### 2.4 Neural CF：神经协同过滤

**核心思想**：用神经网络替代矩阵分解中的简单内积。

传统 MF 用：

\[
score(u,i)=p_u^T q_i
\]

Neural CF 使用多层神经网络：

\[
score(u,i)=MLP(p_u, q_i)
\]

这样可以学习非线性的用户-影片交互。

### 优点

- 表达能力强于 MF；
- 能学习复杂偏好关系；
- 容易扩展到深度模型。

### 缺点

- 训练成本更高；
- 容易过拟合；
- 需要更精细的正则和负采样；
- 实际工业收益不一定稳定。

### 长视频适用性

Neural CF 适合作为从传统 MF 到深度推荐模型的过渡方案。现代系统往往会进一步使用双塔、多任务模型或图模型。

---

## 3. 双塔召回：User Tower + Item Tower + ANN

双塔召回是现代工业推荐系统最重要的召回架构之一。

### 3.1 核心思想

系统分别学习两个塔：

1. **用户塔**：把用户特征编码成向量；
2. **物品塔**：把电影或剧集编码成向量。

训练目标是让用户向量和用户喜欢的内容向量接近，让用户向量和不喜欢的内容向量远离。

### 结构

```text
用户特征：
- 用户 ID
- 历史观看
- 人口属性
- 设备
- 地区
- 会员状态
- 实时行为
        ↓
    User Tower
        ↓
    User Embedding

电影特征：
- 电影 ID
- 类型
- 演员
- 导演
- 语言
- 年份
- 简介
- 海报
- 预告片特征
        ↓
    Item Tower
        ↓
    Item Embedding

相似度 = cosine / dot product
```

### 3.2 为什么双塔适合大规模召回

双塔的关键优势是：**用户向量和物品向量可以分别计算**。

线上流程通常是：

1. 实时计算用户向量；
2. 从 ANN 索引中查找最近的 item 向量；
3. 返回 Top-K 候选。

ANN 常用算法包括：

- Faiss；
- HNSW；
- IVF；
- ScaNN；
- Annoy。

### 3.3 优点

- 线上延迟低；
- 适合百万级甚至亿级内容库；
- item embedding 可离线预计算；
- 容易结合多模态特征；
- 方便做向量索引和多路召回。

### 3.4 缺点

- 用户塔和物品塔在最后打分前没有交叉；
- 难以建模细粒度用户-内容交互；
- 通常需要负采样；
- 容易受曝光偏差影响；
- 对实时上下文建模有限。

### 3.5 长视频适用性

双塔召回非常适合长视频平台，因为：

- 片库规模大；
- 需要低延迟；
- 电影和剧集有丰富内容特征；
- 可以把海报、简介、演员、类型、语言、地区等全部编码到 item embedding。

常见例子：

- 根据用户长期偏好召回相似电影；
- 根据近期观看序列召回相关剧集；
- 根据设备、时间和地区动态调整召回向量。

## 4. 序列召回：GRU4Rec、SASRec、BERT4Rec

序列召回的核心是：**用户的兴趣不是静态的，而是随时间变化的**。

长视频场景尤其明显：

- 用户上周看科幻；
- 最近开始看犯罪剧；
- 今天想看轻松喜剧；
- 正在追某部剧的第 3 季；
- 深夜和周末偏好不同。

---

### 4.1 GRU4Rec

**核心思想**：用 RNN / GRU 建模用户的观看序列。

输入：

```text
电影 A → 电影 B → 电影 C → 电影 D
```

模型预测下一个可能观看的影片：

```text
电影 E
```

GRU 能记住前面的观看历史，并根据最近行为更新隐藏状态。

### 优点

- 适合 session-based recommendation；
- 能捕捉短期兴趣；
- 对连续观看和追剧行为有效。

### 缺点

- 长序列记忆能力有限；
- 训练较慢；
- 对很久以前的行为可能遗忘；
- 对稀疏长视频行为不如注意力模型灵活。

### 长视频适用性

GRU4Rec 适合一个观看 session 内的推荐，例如：

- 用户连续看了三部科幻片；
- 预测下一部想看的电影；
- 用户正在追剧；
- 预测下一集或相关剧集。

---

### 4.2 SASRec：Self-Attentive Sequential Recommendation

**核心思想**：用 self-attention 建模用户历史行为，对每一步历史动态分配权重。

与 GRU 不同，SASRec 可以直接看完整序列，并判断哪些历史行为与当前预测最相关。

### 例子

用户历史：

```text
《绝命毒师》《风骚律师》《毒枭》《火线》《怪奇物语》
```

当前预测下一部剧时，模型可能更关注：

```text
《风骚律师》《毒枭》《火线》
```

因为它们都是犯罪题材，而《怪奇物语》权重较低。

### 优点

- 能捕捉长期依赖；
- 支持并行训练；
- 对关键历史行为动态加权；
- 比传统 RNN 更适合长序列。

### 缺点

- 计算成本高于 GRU；
- 对数据量要求较高；
- item 仍然主要是离散 ID，语义不足；
- 容易受训练数据曝光偏差影响。

### 长视频适用性

SASRec 适合捕捉用户长期观看偏好和题材迁移。例如：

- 用户从科幻转向犯罪剧；
- 用户长期喜欢慢节奏剧情片；
- 用户偏好某类导演或演员。

---

### 4.3 BERT4Rec

**核心思想**：借鉴 BERT 的 masked language modeling，把序列推荐变成“遮住某个观看行为，让模型预测它”。

例如用户序列：

```text
电影 A → 电影 B → [MASK] → 电影 D
```

模型需要预测被遮住的影片 C。

### 特点

BERT4Rec 使用双向注意力，因此能看到目标前后的行为。这让它更像一种序列表示学习方法，而不只是严格自回归预测下一部影片。

### 优点

- 建模能力强；
- 能学习双向上下文；
- 适合离线训练用户行为表示；
- 对复杂观看模式敏感。

### 缺点

- 线上推理时要避免未来信息泄漏；
- 计算成本高；
- 与真实“预测下一个 item”的任务存在偏差；
- 对稀疏长视频数据不一定总是优于 SASRec。

### 长视频适用性

BERT4Rec 适合作为预训练或表示学习模型，用来学习用户观看序列的深层次兴趣表示。但在实际线上系统中，需要谨慎处理训练目标和推理目标的一致性。

---

## 5. 图召回：NGCF、LightGCN、PinSage 类 GNN

图召回把推荐问题建模为图结构。

图中的节点包括：

- 用户；
- 电影；
- 剧集；
- 类型；
- 演员；
- 导演；
- IP；
- 标签。

边表示关系，例如：

- 用户看过电影；
- 用户收藏电影；
- 用户追剧；
- 电影属于某类型；
- 电影由某导演执导；
- 电影包含某演员。

---

### 5.1 NGCF：Neural Graph Collaborative Filtering

**核心思想**：把用户-物品交互建模成二部图，用图神经网络传播协同信号。

例如：

```text
用户 A —— 电影 X —— 用户 B —— 电影 Y
```

即使用户 A 没有直接看过电影 Y，但如果：

- A 看过 X；
- B 也看过 X；
- B 看过 Y；

那么电影 Y 的信息可以通过图传播给用户 A。

### 优点

- 能利用高阶协同关系；
- 对稀疏数据有帮助；
- 能挖掘间接兴趣。

### 缺点

- 原始设计较复杂；
- 计算成本高；
- 全图训练在大规模系统中有挑战。

---

### 5.2 LightGCN：轻量化图卷积推荐

**核心思想**：简化 NGCF，去掉部分非线性变换和权重矩阵，只保留邻域聚合。

LightGCN 认为，在推荐任务中，过多复杂结构不一定带来收益，简单聚合反而更有效。

### 优点

- 参数更少；
- 更容易训练；
- 效果稳定；
- 是图推荐的重要基线。

### 缺点

- 仍然依赖交互图质量；
- 冷启动物品缺边；
- 动态图更新和大规模部署复杂。

---

### 5.3 PinSage 类工业 GNN

PinSage 是 Pinterest 提出的工业级图神经网络推荐方法，适合超大规模图。

它的重点不是发明全新理论结构，而是解决工业落地问题：

- 大规模邻居采样；
- 小批量训练；
- 分布式图计算；
- 线上向量服务；
- 图嵌入增量更新。

### 长视频适用性

图召回特别适合长视频，因为影视内容之间有天然关系网络：

- 同系列电影；
- 同宇宙；
- 同导演；
- 同演员；
- 同 IP；
- 同题材；
- 同受众群。

例如：

- 看过漫威电影的用户，可能对漫威剧集感兴趣；
- 喜欢某导演电影的用户，可能对该导演其他作品感兴趣；
- 喜欢犯罪剧的用户，可能通过高阶图关系发现更多同类剧集。

---

## 6. 知识图谱召回：KGAT、KGCN、TransE + GNN

知识图谱召回和普通图召回的区别在于：它显式利用**结构化知识关系**，而不只是用户-物品交互。

长视频知识图谱中可以有：

```text
电影 ——属于—— 类型
电影 ——导演是—— 人物
电影 ——主演是—— 演员
电影 ——属于—— IP
电影 ——续集是—— 电影
电影 ——改编自—— 小说
剧集 ——包含—— 季
季 ——包含—— 集
角色 ——出现在—— 剧集
```

---

### 6.1 TransE

**核心思想**：把实体和关系都映射到向量空间。

例如：

```text
《盗梦空间》 —— 导演是 —— 诺兰
```

希望满足：

\[
embedding(盗梦空间) + embedding(导演是) \approx embedding(诺兰)
\]

也就是说，头实体向量加上关系向量，应该接近尾实体向量。

### 优点

- 能把知识图谱转化为向量；
- 便于与推荐模型结合；
- 能学习实体之间的语义关系。

### 缺点

- 对复杂关系建模能力有限；
- 单独使用效果不一定强；
- 需要高质量知识图谱。

---

### 6.2 KGCN：Knowledge Graph Convolutional Networks

**核心思想**：在物品的知识图谱邻域上做卷积，聚合相关实体信息，得到更丰富的电影表示。

例如电影《奥本海默》的邻域可能包括：

- 导演：克里斯托弗·诺兰；
- 类型：传记片；
- 主题：历史；
- 演员；
- 获奖；
- 相关历史事件。

KGCN 会把这些信息聚合到电影 embedding 中。

### 优点

- 新电影即使用户交互少，也可以通过元数据获得向量；
- 适合冷启动；
- 可解释性强；
- 能把内容关系引入推荐。

### 缺点：

- 依赖知识图谱质量；
- 图构建成本高；
- 实体消歧困难；
- 大规模训练和更新复杂。

---

### 6.3 KGAT：Knowledge Graph Attention Network

**核心思想**：在知识图谱传播过程中加入 attention，让模型判断哪些关系更重要。

例如对某个用户：

- “导演”关系可能权重高；
- “演员”关系可能权重低；
- “类型”关系可能最重要；
- “IP 关联”可能很有价值。

### 优点

- 能区分不同知识关系的重要性；
- 对偏好解释更细致；
- 有助于长尾推荐。

### 缺点

- 计算更复杂；
- 需要较高质量路径和关系；
- 容易受知识图谱噪声影响。

### 长视频适用性

知识图谱召回对长视频非常适用，因为电影和剧集天然拥有丰富元数据：

- 演员；
- 导演；
- 编剧；
- 类型；
- IP；
- 世界观；
- 续集；
- 前传；
- 改编来源；
- 获奖；
- 制作地区。

例如：

- 用户喜欢诺兰电影，系统推荐《奥本海默》《信条》《敦刻尔克》；
- 用户喜欢漫威电影，系统推荐漫威剧集；
- 用户喜欢《绝命毒师》，系统推荐《风骚律师》。

---

## 7. 多模态召回：图像、文本、音频 embedding + ANN

多模态召回的核心是：**不只把电影看成一个 ID，而是把它看成一个内容对象**。

长视频内容包含：

- 海报；
- 封面图；
- 预告片；
- 剧照；
- 字幕；
- 剧情简介；
- 用户评论；
- 豆瓣/影评；
- 音频；
- 视觉风格；
- 剪辑节奏；
- 色调；
- 配乐。

---

### 7.1 文本模态

文本信号包括：

- 电影简介；
- 类型标签；
- 用户评论；
- 影评；
- 剧情描述；
- 字幕；
- 标题；
- 推荐文案。

可以用模型提取文本 embedding，例如：

- BERT 类模型；
- Sentence Transformer；
- LLM embedding。

适合捕捉：

- 题材；
- 情绪；
- 叙事风格；
- 主题；
- 受众评价。

例如用户喜欢“节奏慢、偏文学性、孤独感强的电影”，文本 embedding 更容易捕捉这种偏好。

---

### 7.2 图像模态

图像信号包括：

- 海报；
- 封面图；
- 剧照；
- 预告片关键帧。

可以用视觉模型提取特征，例如：

- ResNet；
- ViT；
- CLIP；
- 视觉 Foundation Model。

适合捕捉：

- 视觉风格；
- 色调；
- 美术风格；
- 类型氛围；
- 封面吸引力。

例如：

- 黑暗、冷色调、城市夜景可能对应犯罪片或悬疑片；
- 明亮、高饱和、卡通风格可能对应家庭动画；
- 复古胶片质感可能对应文艺片或年代片。

---

### 7.3 音频模态

音频信号包括：

- 配乐；
- 对白；
- 音效；
- 节奏；
- 情绪；
- 语言。

适合捕捉：

- 情绪张力；
- 音乐风格；
- 语言；
- 剧集节奏；
- 惊悚感、轻松感、史诗感。

例如：

- 恐怖片音频特征与喜剧片显著不同；
- 音乐剧可以通过音频结构识别；
- 动作片的节奏和音效密度较高。

---

### 7.4 多模态融合

多模态召回通常分为两类。

#### 早融合

先把图像、文本、音频特征拼接或加权融合成一个电影向量，再进入推荐模型。

优点：

- 表示统一；
- 线上服务简单。

缺点：

- 模态之间可能互相干扰；
- 融合方式较粗糙。

#### 晚融合

每种模态单独召回，然后再融合结果。

例如：

- 文本相似召回 100 部；
- 视觉相似召回 100 部；
- 音频相似召回 50 部；
- 行为相似召回 500 部；
- 最后统一去重、加权、截断。

优点：

- 灵活；
- 各模态不会互相干扰；
- 便于线上调试。

缺点：

- 多路召回成本高；
- 权重调优复杂。

### 优点

- 冷启动能力强；
- 能理解“氛围”和“风格”；
- 对小众电影更友好；
- 推荐解释更自然。

### 缺点

- 多模态数据获取和清洗成本高；
- 特征质量不稳定；
- 线上存储和推理成本高；
- 与真实观看偏好之间可能存在偏差。

---

## 8. 语义 / LLM 召回：Semantic ID、生成式检索、TIGER、GPTRec

这一类方法试图解决传统 ID embedding 的核心问题：**模型只知道“用户看过哪些 ID”，但不知道这个电影在语义上是什么**。

---

### 8.1 Semantic ID：语义 ID

传统推荐中，电影 ID 通常是一个随机 embedding。新电影没有足够交互时，embedding 学不好。

Semantic ID 的思路是：

> 先给每部电影分配一个带有语义结构的编码，而不是随机 ID。

例如可以根据：

- 类型；
- 题材；
- 导演风格；
- 剧情内容；
- 视觉风格；
- 受众偏好；

把电影编码成层级 token：

```text
电影 A = [r1, r2, r3]
电影 B = [r1, r2, r4]
```

如果两个电影共享前缀，说明它们语义相近。

### 优点

- 新电影可以通过内容特征获得语义编码；
- 语义相近的电影 embedding 也相近；
- 便于跨语言和跨域推荐；
- 支持生成式模型输出。

### 缺点

- 语义编码设计复杂；
- 生成结果可能重复；
- 需要保证生成 item 存在于真实片库；
- 线上成本较高。

---

### 8.2 TIGER：生成式检索推荐

TIGER 是 Recommender Systems with Generative Retrieval 中的重要方法。

**核心思想**：推荐不再是从候选库里打分挑选，而是让模型直接生成用户可能喜欢的 item 的 Semantic ID。

流程大致是：

1. 输入用户历史观看序列；
2. Transformer 学习用户偏好；
3. 自回归生成下一部电影的语义 ID；
4. 根据语义 ID 找到真实电影；
5. 输出候选。

### 优点

- 从判别式检索变为生成式检索；
- 对冷启动内容更友好；
- 能学习语义结构；
- 可能统一多个推荐任务。

### 缺点

- 生成结果可能不存在；
- 需要去重和约束解码；
- 线上推理成本高；
- 与传统 ANN 召回相比，工程复杂度更高。

---

### 8.3 GPTRec：生成式序列推荐

GPTRec 使用类似 GPT 的自回归结构做序列推荐。

输入用户历史：

```text
电影 A → 电影 B → 电影 C
```

模型生成：

```text
电影 D
```

它可以基于传统 item ID，也可以结合语义 ID 或其他表示。

### 优点

- 序列建模能力强；
- 与 LLM 架构接近；
- 可借鉴大规模预训练技术。

### 缺点

- 推理成本高；
- 输出需要合法性和去重约束；
- 在超大规模片库上直接生成 item 比较困难。

---

### 8.4 LLM 召回

LLM 可以用于以下方式。

#### 语义理解

把电影简介、评论、海报描述、剧情、风格输入 LLM，生成结构化标签或 embedding。

例如：

```text
电影：A
简介：一部关于家庭、记忆与时间旅行的慢节奏剧情片
LLM 输出：
题材：家庭 / 时间旅行
情绪：伤感 / 温柔
节奏：慢
风格：文艺 / 剧情
适合人群：喜欢情感叙事的用户
```

#### 用户偏好理解

根据用户历史，让 LLM 总结偏好：

```text
用户最近观看：
《迷失》
《黑镜》
《西部世界》
《爱，死亡和机器人》

LLM 总结：
用户偏好：
- 科幻设定
- 强概念剧
- 哲学性主题
- 悬疑和反转
- 不偏好纯爱情剧
```

#### 自然语言查询召回

用户可以直接说：

> 我想看一部类似《盗梦空间》但更轻松、时长短一点的电影。

LLM 可以理解“类似”的含义，并结合内容库检索候选。

### LLM 召回优点

- 语义理解强；
- 支持自然语言表达；
- 冷启动友好；
- 可解释性好；
- 能处理跨语言和跨文化偏好。

### LLM 召回缺点

- 成本高；
- 延迟高；
- 可能幻觉出不存在的电影；
- 对实时用户行为建模不如传统模型高效；
- 隐私风险更高。

---

## 9. 热门 / 运营召回

热门召回和运营召回虽然看起来“不够智能”，但在工业系统中非常重要。

### 9.1 热门榜召回

例如：

- 本周观看人数最多；
- 当前讨论度最高；
- 平台热播剧；
- 新片榜；
- 豆瓣高分榜；
- 地区热门榜。

### 优点

- 简单；
- 稳定；
- 新用户冷启动友好；
- 覆盖面广；
- 对所有用户都有基础效果。

### 缺点

- 缺乏个性化；
- 强化流行度偏差；
- 小众内容曝光不足；
- 可能损害长期多样性。

### 9.2 新片召回

长视频平台经常需要推广新电影、新剧集、新综艺。

新片召回的规则包括：

- 新片上线初期强制曝光；
- 根据用户兴趣选择性推送；
- 按地区、语言、会员资格过滤；
- 结合宣发节奏调整权重。

### 9.3 编辑精选召回

运营人员可以人工构建专题，例如：

- “本周最佳悬疑剧”；
- “导演专题：诺兰”；
- “适合周末观看的家庭片”；
- “高口碑冷门电影”；
- “颁奖季精选”。

### 优点

- 内容质量可控；
- 能引入人工编辑判断；
- 支持品牌策略和文化目标。

### 缺点

- 规模有限；
- 无法完全个性化；
- 可能受商业目标影响。

### 9.4 地区 / 语言 / 本地化召回

不同地区用户偏好差异很大。例如：

- 韩剧在东亚市场可能表现突出；
- 欧洲艺术电影在不同国家偏好不同；
- 语言、字幕、配音会影响观看决策；
- 本地节假日和文化事件会影响推荐。

因此运营召回需要考虑：

- 国家；
- 语言；
- 版权范围；
- 文化偏好；
- 节假日；
- 本地热点。

## 10. 多路召回融合

现代推荐系统通常不会依赖单一算法，而是同时使用几十路召回。

### 10.1 为什么要多路召回

因为每一路召回都有偏置：

- ItemCF 偏向经典热门；
- 双塔偏向历史兴趣；
- 序列召回偏向短期兴趣；
- 图召回偏向结构相似；
- 多模态召回偏向内容相似；
- 热门召回偏向大众口味；
- 运营召回偏向平台目标。

多路召回的目的是互相补足，避免单一通道遗漏重要内容。

### 10.2 常见召回通道

一个长视频推荐系统可能同时包含：

1. ItemCF 召回；
2. UserCF 召回；
3. ALS / MF 召回；
4. BPR 召回；
5. 双塔召回；
6. 序列召回；
7. 图召回；
8. 知识图谱召回；
9. 多模态召回；
10. LLM / Semantic ID 召回；
11. 热门召回；
12. 新片召回；
13. 编辑精选召回；
14. 搜索历史召回；
15. 收藏 / 片单召回；
16. 续看召回；
17. 相似导演召回；
18. 相似演员召回；
19. 同 IP 召回；
20. 地区热门召回。

### 10.3 多路融合方式

#### 简单分数融合

每一路召回给出候选和分数，然后加权：

\[
score(i)=\sum_k w_k score_k(i)
\]

其中 \(k\) 表示第 \(k\) 路召回。

优点是简单可控。缺点是不同通道分数尺度可能不一致。

#### 规则融合

例如：

- 每路最多保留 N 个候选；
- 总候选不超过 M；
- 同一 IP 最多保留 2 部；
- 同类型最多保留 5 部；
- 新片至少保留一定比例。

#### 模型融合

把每一路召回的分数、来源、特征输入一个小模型，学习各路权重。

例如：

```text
特征：
- 来自 ItemCF 分数
- 来自双塔相似度
- 来自序列模型分数
- 来自图召回分数
- 来自多模态相似度
- 是否新片
- 是否热门
- 用户是否常看该类型

输出：
候选进入粗排的概率
```

#### 分层截断

例如：

```text
召回总数：5000
双塔保留：2000
序列召回保留：1000
图召回保留：800
多模态保留：600
运营召回保留：300
热门召回保留：300
```

### 10.4 多路召回的关键问题

- 各路召回分数量纲不一致；
- 候选重复；
- 多样性不足；
- 热门内容垄断；
- 冷启动内容被过滤；
- 召回目标与精排目标不一致；
- 线上延迟和存储成本增加。

---

## 11. 总结：这些算法各自解决什么问题

| 算法类型 | 主要信号 | 核心优势 | 核心短板 |
|---|---|---|---|
| ItemCF | 物品共现 | 简单稳定，可解释 | 冷启动弱，偏热门 |
| UserCF | 用户相似 | 捕捉同类人群偏好 | 规模大，隐私敏感 |
| MF / ALS | 潜在偏好 | 稳定，适合长期偏好 | 表达能力有限 |
| BPR | 隐式反馈排序 | 更适合 Top-N 推荐 | 负采样敏感 |
| FM | 特征交叉 | 适合稀疏特征融合 | 高阶交互有限 |
| Neural CF | 非线性交互 | 表达能力强 | 成本高，收益不稳定 |
| 双塔召回 | 用户向量 + 物品向量 | 工业主流，低延迟 | 缺少细粒度交叉 |
| GRU4Rec | 短期序列 | 适合连续观看 | 长序列能力有限 |
| SASRec | 注意力序列 | 捕捉长期兴趣 | 计算成本较高 |
| BERT4Rec | 双向序列表示 | 表示学习强 | 训练与推理目标可能不一致 |
| NGCF / LightGCN | 交互图 | 高阶协同信号 | 部署复杂 |
| PinSage 类 GNN | 大规模图 | 工业可扩展 | 图构建和更新成本高 |
| KGCN / KGAT | 知识图谱 | 语义强，冷启动好 | 依赖图谱质量 |
| 多模态召回 | 图像 / 文本 / 音频 | 理解风格和氛围 | 数据和推理成本高 |
| Semantic ID / TIGER / GPTRec | 语义空间 + 生成式检索 | 冷启动和跨语言好 | 成本高，需约束生成 |
| LLM 召回 | 自然语言和内容语义 | 交互自然，解释强 | 延迟高，可能幻觉 |
| 热门 / 运营召回 | 平台和运营信号 | 稳定，支持冷启动 | 个性化弱，流行度偏差 |
| 多路召回融合 | 多种信号 | 覆盖广，互补强 | 调度和调参复杂 |
