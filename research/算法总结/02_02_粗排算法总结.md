下面逐一介绍粗排阶段常用的几类算法。这里的“粗排”目标是：在召回结果可能仍有几千到几万条候选时，用比精排更轻量的模型快速打分，筛选出几百或几千条进入精排。

---

## 1. 轻量线性模型：LR

### 1.1 全称

LR = Logistic Regression，逻辑回归。

它是最经典、最简单、部署成本最低的排序模型之一，早期搜索、广告、推荐系统中广泛使用。

### 1.2 基本形式

对于候选影片，模型先计算一个线性分数：

\[
z = w_0 + w_1x_1 + w_2x_2 + \cdots + w_nx_n
\]

然后通过 Sigmoid 函数转成点击概率：

\[
p = \sigma(z) = \frac{1}{1+e^{-z}}
\]

其中：

- \(x_i\) 是特征，例如用户年龄段、影片类型、设备类型、历史播放次数；
- \(w_i\) 是特征权重；
- \(w_0\) 是偏置项。

### 1.3 特征通常是离散化后的 One-hot 编码

例如：

- 用户设备：TV / Mobile / Tablet；
- 内容类型：电影 / 剧集 / 综艺 / 纪录片；
- 时间段：早晨 / 午间 / 深夜；
- 用户历史偏好：悬疑、爱情、动作、喜剧；
- 影片热度等级：高 / 中 / 低。

LR 本身不能自动学习特征交叉，所以通常依赖人工特征工程。

### 1.4 优点

1. **速度快**  
   计算量极小，适合粗排大规模打分。

2. **可解释性强**  
   权重正负可以直接解释某个特征是正向还是负向影响。

3. **稳定、易部署**  
   对线上系统非常友好，故障排查简单。

4. **适合作为 baseline**  
   如果一个复杂模型不能稳定超过 LR，说明模型或特征设计可能有问题。

### 1.5 缺点

1. **无法自动学习特征交叉**  
   例如“深夜 + 惊悚片”可能是一个强信号，但 LR 需要人工构造“深夜_惊悚片”组合特征。

2. **表达能力有限**  
   对复杂非线性偏好建模能力弱。

3. **依赖特征工程**  
   效果高度取决于工程师构造特征的功力。

### 1.6 长视频粗排应用

LR 可以快速判断候选影片的基础相关性，例如：

- 用户喜欢悬疑片；
- 候选影片是悬疑片；
- 用户经常在电视端观看；
- 该影片电视端完播率高；
- 当前是周末晚间。

这种模型适合承担早期粗排，或作为多路粗排中的一路。

## 2. 因子分解机：FM

### 2.1 全称

FM = Factorization Machines，因子分解机。

FM 的核心目标是解决 LR 无法自动学习特征交叉的问题。

### 2.2 基本形式

FM 的预测分数可以写成：

\[
y(x) = w_0 + \sum_{i=1}^{n}w_ix_i + \sum_{i=1}^{n}\sum_{j=i+1}^{n}
\langle v_i, v_j \rangle x_ix_j
\]

其中：

- 第一部分和 LR 一样，是线性项；
- 第二部分是二阶特征交叉项；
- \(v_i\) 是第 \(i\) 个特征的隐向量；
- \(\langle v_i, v_j \rangle\) 表示两个特征隐向量的内积。

### 2.3 关键思想：用隐向量表示特征

如果直接构造所有特征交叉，组合数量会爆炸。

例如：

- 100 个用户特征；
- 100 个影片特征；
- 100 个上下文特征；

两两交叉可能有上万甚至更多组合，而且很多组合在数据中极少出现，难以训练。

FM 的做法是：

> 每个特征都学习一个低维向量，两个特征的交叉强度用两个向量的内积表示。

这样即使两个特征很少共同出现，只要它们分别和其他特征共现过，也能学到有意义的隐向量。

### 2.4 例子

假设有特征：

- 用户年龄段 = 青年；
- 内容类型 = 悬疑；
- 设备 = TV；
- 时间段 = 深夜。

FM 可以自动学习：

- 青年 × 悬疑；
- 深夜 × 悬疑；
- TV × 电影；
- 青年 × TV；
- 深夜 × TV。

这些组合不需要全部人工构造。

### 2.5 优点

1. **自动学习二阶特征交叉**；
2. **适合稀疏数据**；
3. **参数规模可控**；
4. **比 LR 表达能力强，同时仍然比较轻量**；
5. **在推荐、广告、CTR 预估中长期被广泛使用**。

### 2.6 缺点

1. **主要建模二阶交叉**  
   高阶交叉能力有限。

2. **仍然是浅层模型**  
   对复杂非线性关系表达能力不如深度模型。

3. **特征工程仍然重要**  
   虽然减少了很多交叉特征构造工作，但原始特征设计仍影响很大。

### 2.7 长视频粗排应用

FM 适合捕捉类似下面的信号：

- 用户喜欢悬疑剧 × 候选是悬疑电影；
- 用户在深夜观看 × 候选是惊悚片；
- 家庭账户在周末白天打开电视 × 候选是动画片；
- 用户偏好美剧 × 候选是高分美剧。

FM 常用于中等规模粗排，或者作为深度模型的线性/交叉组件。

## 3. Field-aware Factorization Machine：FFM

### 3.1 全称

FFM = Field-aware Factorization Machine，域感知因子分解机。

FFM 是 FM 的改进版本，核心区别是：**同一个特征在不同 field 中使用不同的隐向量**。

### 3.2 Field 是什么？

在推荐系统中，特征通常被分成多个 field，例如：

| Field | 特征 |
|---|---|
| 用户 field | 年龄、性别、会员等级 |
| 内容 field | 类型、导演、演员、片长 |
| 上下文 field | 时间、设备、页面 |
| 统计 field | CTR、播放率、完播率 |

在 FM 中，一个特征只有一个隐向量。

例如“悬疑片”无论和“深夜”交叉，还是和“青年用户”交叉，都使用同一个向量。

而在 FFM 中：

> “悬疑片”在与“用户年龄”交叉时用一个向量；  
> 在与“设备”交叉时用另一个向量；  
> 在与“时间段”交叉时再用另一个向量。

### 3.3 直观理解

FM 认为：

> 一个特征对所有交叉对象都使用同一种潜在语义。

FFM 认为：

> 一个特征在不同关系场景下应该有不同的表达。

例如“悬疑片”：

- 与“深夜”交叉时，可能代表氛围匹配；
- 与“青年用户”交叉时，可能代表人群偏好；
- 与“电视端”交叉时，可能代表沉浸式观看场景。

FFM 允许这些关系使用不同向量表达。

### 3.4 优点

1. **比 FM 更精细地建模特征关系**；
2. **适合 field 结构清晰的特征系统**；
3. **在 CTR 预估比赛中曾表现优异**；
4. **对稀疏特征交叉更敏感**。

### 3.5 缺点

1. **参数量更大**  
   每个特征在每个 field 下都要有独立向量。

2. **训练和推理成本高于 FM**；
3. **容易过拟合**；
4. **对特征 field 划分要求较高**。

### 3.6 长视频粗排应用

FFM 适合长视频场景中多 field 特征较明确的情况，例如：

- 用户 field；
- 内容 field；
- 演员导演 field；
- 类型题材 field；
- 设备 field；
- 时间上下文 field；
- 页面 field。

如果平台已经有完善的特征体系，FFM 可以比 FM 更细致地捕捉交叉信号。

## 4. 轻量深度模型：小型 DNN

### 4.1 基本思想

DNN = Deep Neural Network，深度神经网络。

小型 DNN 是指为了粗排效率，刻意压缩规模的神经网络。它通常包括：

1. 输入层；
2. Embedding 层；
3. 若干全连接层；
4. 输出层。

结构大致如下：

```text
稀疏特征
   ↓
Embedding 层
   ↓
拼接 / Pooling
   ↓
全连接层 1
   ↓
ReLU / Dropout
   ↓
全连接层 2
   ↓
输出分数
```

### 4.2 主要组件

#### Embedding 层

将离散 ID 特征映射为稠密向量。

例如：

- 用户 ID → 64 维向量；
- 影片 ID → 64 维向量；
- 类型 ID → 16 维向量；
- 演员 ID → 16 维向量。

#### 拼接层

把用户、影片、上下文、统计特征的 embedding 拼接在一起。

#### 多层感知机 MLP

通过非线性变换学习复杂特征关系。

#### 输出层

输出点击概率、播放概率或播放时长预测。

### 4.3 小型 DNN 的“小型”体现在哪里？

为了满足粗排延迟要求，通常会做以下压缩：

- 更少的隐藏层；
- 更小的 embedding 维度；
- 更少的专家网络或分支；
- 更少的交叉特征；
- 更小的 batch 内计算图；
- 参数量化；
- 简化的激活函数；
- 部分特征离线预计算。

### 4.4 优点

1. **能学习非线性关系**；
2. **比 LR / FM 表达能力更强**；
3. **可以融合数值特征、离散特征、序列特征和多模态特征**；
4. **结构灵活，容易扩展成多任务模型**。

### 4.5 缺点

1. **比 LR / FM 慢**；
2. **可解释性弱**；
3. **容易过拟合**；
4. **线上服务复杂度更高**。

### 4.6 长视频粗排应用

小型 DNN 可以用于预测：

- 点击概率；
- 播放概率；
- 预计观看时长；
- 完播概率；
- 续看概率。

例如输入包括：

- 用户 embedding；
- 用户历史类型偏好；
- 影片 embedding；
- 海报/预告片 embedding 的压缩版本；
- 时间、设备、页面上下文；
- 影片历史播放统计。

输出一个综合分数。

## 5. 简化版 Wide & Deep

### 5.1 原始 Wide & Deep 思想

Wide & Deep 由 Google 提出，用于推荐系统，包含两部分：

```text
Wide 部分：记忆历史共现规律
Deep 部分：泛化到没见过的组合
        ↓
联合输出
```

#### Wide 部分

Wide 部分通常是线性模型，擅长记住显式共现规则。

例如：

> 在电视端、周末晚间、家庭账户、儿童内容栏目中，动画片的点击率更高。

这种强共现关系适合 wide 部分记忆。

#### Deep 部分

Deep 部分是 embedding + DNN，擅长泛化。

例如：

> 用户喜欢科幻美剧，虽然没有直接看过某部新科幻剧，但通过题材、演员、导演、风格 embedding，模型可以推断可能喜欢。

### 5.2 原始结构

```text
Wide 特征 ─────────────┐
                       │
                      拼接 / 相加
                       │
Deep 特征 → Embedding → DNN ┘
                       ↓
                    输出层
```

### 5.3 粗排中的简化版

粗排版 Wide & Deep 通常会简化：

1. **减少 deep 层数**；
2. **降低 embedding 维度**；
3. **wide 部分只保留少量强特征**；
4. **减少交叉特征**；
5. **只预测一两个核心目标**，如点击概率和播放概率；
6. **离线预计算部分 embedding**。

### 5.4 优点

1. **兼顾记忆和泛化**；
2. **比纯 DNN 更稳定**；
3. **wide 部分可以吸收强业务规则**；
4. **deep 部分可以处理稀疏 ID 和长尾内容**。

### 5.5 缺点

1. **wide 特征仍需人工设计**；
2. **deep 部分增加计算成本**；
3. **系统复杂度高于单模型**。

### 5.6 长视频粗排应用

Wide 部分可以记住：

- 用户类型偏好；
- 热门影片共现；
- 设备与内容形态关系；
- 时间段与题材关系；
- 已追剧集的下一集强相关规则。

Deep 部分可以泛化：

- 新片冷启动；
- 相似题材推荐；
- 演员导演关联；
- 海报、简介、预告片等语义相似性。

## 6. 双塔粗排模型

### 6.1 基本结构

双塔模型是大规模粗排和召回的主流结构。

它有两个塔：

```text
User Tower                Item Tower
用户特征                   影片特征
   ↓                         ↓
用户 embedding             影片 embedding
        \                 /
         \               /
          内积 / 余弦相似度
                  ↓
               相关性分数
```

### 6.2 User Tower 输入

常见用户侧特征包括：

- 用户 ID；
- 年龄、性别、会员等级；
- 历史观看类型；
- 最近观看影片；
- 收藏、评分、搜索行为；
- 设备偏好；
- 活跃时间；
- 长期偏好 embedding；
- 短期兴趣 embedding。

### 6.3 Item Tower 输入

常见影片侧特征包括：

- 影片 ID；
- 标题、简介、类型；
- 演员、导演、IP；
- 海报视觉特征；
- 预告片特征；
- 音频/字幕特征；
- 历史点击率、播放率、完播率；
- 内容热度；
- 上线时间。

### 6.4 打分方式

常见方式包括：

#### 内积

\[
score(u, i) = p_u^\top q_i
\]

#### 余弦相似度

\[
score(u, i) = \frac{p_u^\top q_i}{\|p_u\|\|q_i\|}
\]

#### 轻量 MLP

把两个 embedding 拼接后接一个小 MLP，但这会削弱“离线预计算 item embedding”的优势。

### 6.5 为什么适合粗排？

因为影片塔可以离线计算。

工业流程通常是：

1. 离线为所有影片计算 item embedding；
2. 把所有 item embedding 建成 ANN 索引；
3. 线上实时计算 user embedding；
4. 在 ANN 中查找最近邻影片；
5. 返回候选集；
6. 进入后续粗排或精排。

这样避免了每来一个请求就对全库影片做复杂打分。

### 6.6 优点

1. **非常适合大规模打分**；
2. **item embedding 可离线预计算**；
3. **延迟低**；
4. **容易结合 ANN 检索**；
5. **可以融合多模态语义向量**。

### 6.7 缺点

1. **用户塔和物品塔之间缺少精细交叉**  
   因为两个塔分别独立编码，最后只做内积或简单融合，很多精细特征交叉会丢失。

2. **表达能力弱于精排模型**  
   精排可以使用更复杂的用户-物品交叉结构。

3. **线上和离线一致性问题**  
   如果离线训练和线上服务不一致，效果会下降。

4. **负样本设计非常关键**  
   双塔模型对负采样策略很敏感。

### 6.8 长视频粗排应用

双塔粗排可以快速回答：

> 这个用户此刻可能对哪几千部影片感兴趣？

例如：

- 用户长期喜欢科幻；
- 最近在看悬疑美剧；
- 当前设备是电视；
- 时间是周末晚上；
- item 侧有题材、演员、IP、海报、预告片语义向量。

双塔模型可以快速找到语义和兴趣上都相关的候选影片。

## 7. 知识蒸馏：精排模型蒸馏到粗排模型

### 7.1 基本思想

知识蒸馏的核心是：

> 用一个强大的精排模型作为 teacher，训练一个更小的粗排模型作为 student，让 student 学习 teacher 的行为或输出分布。

精排模型效果好，但太慢，不能对几万候选全量打分；粗排模型快，但效果弱。知识蒸馏就是让粗排模型尽量接近精排模型。

### 7.2 Teacher 与 Student

```text
候选影片 + 用户上下文
        ↓
   Teacher 精排模型
        ↓
Teacher 分数 / 排序 / soft label
        ↓
   Student 粗排模型
        ↓
Student 分数
```

### 7.3 常见蒸馏目标

#### 1. 蒸馏预测分数

让 student 拟合 teacher 的输出概率：

\[
L = (p_{teacher} - p_{student})^2
\]

或使用 KL 散度：

\[
L = KL(p_{teacher} \| p_{student})
\]

#### 2. 蒸馏排序关系

不要求 student 分数和 teacher 完全一致，只要求相对排序相似。

例如 teacher 认为影片 A 应排在 B 前面，student 也要学到：

\[
score(A) > score(B)
\]

这对推荐系统尤其重要，因为推荐关心排序，而不是绝对分数。

#### 3. 蒸馏 embedding

让 student 的中间表示接近 teacher 的中间表示。

例如 teacher 的影片 embedding 或用户兴趣 embedding 被压缩传递给 student。

#### 4. 蒸馏多目标输出

如果 teacher 输出多个目标：

- 点击概率；
- 播放概率；
- 完播概率；
- 预计时长；
- 续看概率。

student 可以同时学习这些目标的近似结果。

### 7.4 优点

1. **让粗排目标更接近精排目标**；
2. **减少召回、粗排、精排之间的目标不一致**；
3. **提升粗排效果，同时保持低延迟**；
4. **可用于压缩大模型、多任务模型或 LLM 相关模块**。

### 7.5 缺点

1. **teacher 本身可能有偏差**  
   如果精排模型有系统性偏差，student 会继承。

2. **训练链路复杂**  
   需要先训练 teacher，再训练 student。

3. **线上效果不一定单调提升**  
   蒸馏分数与最终业务指标之间仍可能有 gap。

4. **更新维护成本高**  
   teacher 更新后，student 也可能需要重新训练。

### 7.6 长视频粗排应用

精排模型可能非常复杂，能同时预测：

- 点击；
- 播放；
- 完播；
- 观看时长；
- 续看；
- 弃剧概率。

但粗排模型无法承受同样复杂度。于是可以用蒸馏让粗排模型学会：

> 在几万候选中，尽量保留精排真正会打高分的影片。

这样可以减少“好影片在粗排被提前过滤掉”的问题。

## 8. 多目标粗排：轻量 MMoE / PLE / Shared-Bottom

长视频推荐不只关心点击，还关心播放、完播、续看、时长和留存。因此粗排也常常是多目标模型。

下面介绍三种常见多任务结构。

---

### 8.1 Shared-Bottom 多任务模型

#### 基本结构

```text
输入特征
   ↓
共享底层网络 Shared Bottom
   ↓
任务 A Tower：点击预测
   ↓
任务 B Tower：播放预测
   ↓
任务 C Tower：完播预测
```

Shared-Bottom 表示所有任务共享同一组底层参数，再分别接各自的任务塔。

#### 优点

1. 参数少；
2. 结构简单；
3. 训练稳定；
4. 适合任务相关性高的情况。

#### 缺点

1. **任务容易互相干扰**  
   如果“点击”和“完播”目标存在冲突，共享底层可能学不到双方都最优的表示。

2. **负迁移风险较高**  
   例如某些标题诱人的内容点击率高但完播率低，如果强行共享底层，模型可能产生冲突。

#### 长视频例子

- 任务 A：用户会点击；
- 任务 B：用户会开始播放；
- 任务 C：用户会看完大部分；
- 任务 D：用户会继续追下一集。

如果这些目标高度相关，Shared-Bottom 可能有效；如果目标冲突，效果会下降。

---

### 8.2 MMoE：Multi-gate Mixture-of-Experts

#### 基本思想

MMoE 引入多个专家网络和多个任务 gate。

结构如下：

```text
输入特征
   ↓
Expert 1
Expert 2
Expert 3
Expert 4
   ↓
任务 A Gate：选择专家组合 → 任务 A Tower
任务 B Gate：选择专家组合 → 任务 B Tower
任务 C Gate：选择专家组合 → 任务 C Tower
```

每个任务有自己的 gate，决定它如何组合多个专家的输出。

#### Gate 的作用

Gate 可以理解为加权器。

例如：

- 点击任务可能更依赖“标题吸引力”专家；
- 完播任务可能更依赖“内容质量”专家；
- 续看任务可能更依赖“剧情连续性”专家；
- 时长任务可能更依赖“影片长度和用户耐心”专家。

不同任务通过 gate 选择不同专家组合。

#### 优点

1. **比 Shared-Bottom 更灵活**；
2. **能缓解任务冲突**；
3. **不同任务可以共享部分知识，同时保留任务差异**；
4. **在工业推荐系统中应用广泛**。

#### 缺点

1. 参数比 Shared-Bottom 多；
2. 训练不如 Shared-Bottom 稳定；
3. 专家数量和 gate 设计需要调参；
4. 如果任务本身高度相关，MMoE 的收益可能有限。

#### 长视频例子

一个轻量 MMoE 粗排模型可以同时预测：

- 点击概率；
- 播放概率；
- 完播概率；
- 下一集续看概率；
- 负反馈概率。

不同任务使用不同专家组合，例如：

- 点击任务关注封面、标题、热度；
- 完播任务关注题材匹配、口碑、影片质量；
- 续看任务关注剧集状态、剧情连续性、上一集完播情况。

---

### 8.3 PLE：Progressive Layered Extraction

PLE 是对 MMoE 的进一步改进，目标是更好地解决多任务之间的冲突和知识共享问题。

#### 核心思想

PLE 把专家分成：

1. **任务专属专家**：只服务某一个任务；
2. **共享专家**：服务多个任务。

并通过多层结构逐步提取任务知识和共享知识。

结构大致如下：

```text
输入特征
   ↓
任务 A 专属专家 ─┐
任务 B 专属专家 ─┤
共享专家 ────────┤
                ↓
        第一层 Gate / Extraction
                ↓
任务 A Tower
任务 B Tower
```

PLE 的关键词是：

> **渐进式分层提取。**

它在多个层次上反复进行：

- 任务私有信息提取；
- 共享信息提取；
- 任务间信息融合。

### PLE 与 MMoE 的区别

| 维度 | MMoE | PLE |
|---|---|---|
| 专家划分 | 专家通常是共享的 | 分为任务专属专家和共享专家 |
| Gate 设计 | 每个任务一个 gate | 每个任务有更细化的 gate |
| 结构 | 通常单层专家 | 可多层级、渐进提取 |
| 目标 | 让不同任务选择不同专家 | 进一步减少任务冲突和负迁移 |
| 参数量 | 中等 | 更大 |
| 适合场景 | 多任务相关性中等 | 多任务存在明显冲突或异质性 |

#### 优点

1. **更好地处理任务冲突**；
2. **共享知识和任务私有知识分离更清晰**；
3. **在多目标推荐中效果通常强于 MMoE**；
4. **适合复杂视频推荐目标**。

#### 缺点

1. 结构复杂；
2. 参数量大；
3. 训练和调参难度更高；
4. 粗排中使用时必须做轻量化，否则延迟和成本过高。

#### 长视频粗排应用

PLE 特别适合长视频推荐，因为长视频的目标天然存在冲突：

- 点击高的内容不一定完播高；
- 完播高的内容不一定带来长期留存；
- 短期时长高的内容不一定让用户满意；
- 强推热门内容可能损害多样性。

轻量 PLE 粗排可以同时预测：

- 点击；
- 播放；
- 完播；
- 观看时长；
- 续看；
- 收藏；
- 负反馈。

然后通过融合公式生成最终粗排分数。

## 9. 级联模型

### 9.1 基本思想

级联模型不是某一个具体算法，而是一种系统设计策略。

核心思想是：

> 用多个复杂度递增的模型依次过滤候选，避免一开始就用最重模型处理所有候选。

典型流程如下：

```text
召回：100 万候选
   ↓
轻量规则/简单模型：10 万候选
   ↓
轻量模型粗排：1 万候选
   ↓
中等复杂模型：1 千候选
   ↓
精排模型：几百候选
   ↓
重排：最终展示列表
```

### 9.2 常见级联设计

#### 第一级：规则过滤

用于快速排除明显不合适的候选：

- 已看过；
- 用户明确不喜欢；
- 地区不可播放；
- 年龄不合适；
- 版权状态异常；
- 内容下线；
- 重复推荐；
- 明显不符合当前页面。

#### 第二级：简单模型

例如 LR 或轻量 FM，快速打分。

#### 第三级：轻量深度模型

例如小型 DNN 或双塔模型。

#### 第四级：精排模型

复杂多任务深度模型，预测多个行为目标。

#### 第五级：重排

考虑多样性、页面布局、业务约束、封面选择。

### 9.3 为什么级联模型适合超大规模系统？

因为不同模型的计算成本差异巨大。

如果对 100 万候选都使用精排模型，计算成本会爆炸。级联模型可以让：

- 大部分候选被极轻量的模型快速过滤；
- 少量高质量候选进入重模型；
- 最终精排只处理最有希望的候选。

### 9.4 优点

1. **显著降低计算成本**；
2. **降低平均延迟**；
3. **允许后级使用更复杂模型**；
4. **灵活适配不同规模系统**；
5. **易于逐步迭代和上线**。

### 9.5 缺点

1. **前置阶段可能误杀好候选**  
   如果粗排模型与精排目标不一致，可能在早期过滤掉后来会被用户喜欢的内容。

2. **各级目标一致性要求高**  
   召回、粗排、精排之间的优化目标必须尽量一致。

3. **系统复杂度高**  
   需要维护多个模型、多个日志和多套评估流程。

4. **误差会逐级传递**  
   前一级的错误会影响后一级效果。

### 9.6 长视频粗排应用

典型级联流程可以是：

1. 从全库中召回 5 万候选；
2. 用规则过滤掉不可播放、已观看、重复内容；
3. 用双塔模型筛到 1 万；
4. 用轻量多目标模型筛到 2 千；
5. 用精排模型排序到几百；
6. 用重排生成最终首页列表。

## 10. 总结对比

| 算法 | 主要能力 | 优点 | 缺点 | 适合场景 |
|---|---|---|---|---|
| LR | 线性打分 | 快、稳定、可解释 | 无法自动交叉特征 | 早期粗排、baseline |
| FM | 自动二阶特征交叉 | 适合稀疏数据，比 LR 强 | 高阶能力有限 | 中等规模稀疏特征粗排 |
| FFM | Field-aware 特征交叉 | 比 FM 更精细 | 参数多，成本高 | 特征 field 清晰的平台 |
| 小型 DNN | 非线性表达 | 能融合多种特征 | 可解释性弱，成本更高 | 中大型粗排 |
| 简化 Wide & Deep | 记忆 + 泛化 | 兼顾强规则和泛化 | 结构较复杂 | 需要业务规则与深度模型结合 |
| 双塔模型 | 用户-影片向量匹配 | 大规模打分，支持 ANN | 缺少精细交叉 | 超大规模召回和粗排 |
| 知识蒸馏 | 精排知识迁移到粗排 | 目标一致性好 | 继承 teacher 偏差 | 工业粗排优化 |
| Shared-Bottom | 多任务共享底层 | 简单稳定 | 任务易冲突 | 任务高度相关 |
| MMoE | 多任务多专家 | 缓解任务冲突 | 参数多，训练复杂 | 多目标视频推荐 |
| PLE | 任务专属 + 共享专家 | 更适合任务冲突明显场景 | 结构更复杂 | 点击、完播、续看等多目标 |
| 级联模型 | 多级过滤 | 控制成本和延迟 | 可能前置误杀 | 超大规模工业系统 |

## 11. 粗排算法选择的实践建议

### 11.1 如果系统刚起步

推荐使用：

- LR 或 FM；
- 简单规则过滤；
- 少量人工交叉特征；
- 一个核心目标，如播放概率。

### 11.2 如果候选规模较大

推荐使用：

- 双塔模型；
- ANN 检索；
- 简化 DNN 粗排；
- 规则级联过滤。

### 11.3 如果目标复杂

推荐使用：

- 轻量 MMoE；
- 轻量 PLE；
- 多目标输出：点击、播放、完播、续看；
- 根据业务目标调整融合分数。

### 11.4 如果粗排和精排不一致

推荐使用：

- 知识蒸馏；
- 排序关系蒸馏；
- 多目标蒸馏；
- 校准粗排分数；
- 用精排反馈优化粗排样本。

### 11.5 如果延迟和算力紧张

推荐使用：

- 级联模型；
- 双塔 + ANN；
- 精排蒸馏到粗排；
- embedding 离线预计算；
- 参数量化和小模型压缩。

---

## 12. 一句话总结

> **LR 和 FM 是轻量可靠的起步方案；双塔模型解决大规模打分；小型 DNN 提升表达能力；MMoE / PLE 处理多目标冲突；知识蒸馏让粗排更接近精排；级联模型用系统设计控制成本。**
